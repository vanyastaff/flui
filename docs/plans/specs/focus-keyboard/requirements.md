# Фокус и клавиатура в Notes — требования (уровень 1)

- **Статус:** черновик
- **Дата:** 2026-10-05
- **База:** `main` @ `4915054c8`
- **Уровень 0:** [../release/requirements.md](../release/requirements.md) R8 (и R16: #1040, #1092)
- **ADR:** [ADR-0026](../../../adr/ADR-0026-focus-traversal-seam.md),
  [ADR-0023](../../../adr/ADR-0023-actions-shortcuts-seam.md),
  [ADR-0079](../../../adr/ADR-0079-keyboard-activation-and-focus-for-assistive-technology.md)

## Пользовательский сценарий

Пользователь без мыши запускает Notes (`examples/two_screens/tree.rs`) и:

1. Tab ведёт в заголовок Home, затем в список. Стрелки, PageDown и End доходят до любой из
   10 000 строк; Narrator читает «Note 5, 6 из 10000».
2. Enter открывает заметку, и фокус сразу в `Title`. Tab и Enter на `Save note` сохраняют.
   Alt+Left возвращает на Home, к строке той же заметки.
3. Так же проходятся `Settings`, `Toggle compact rows` и `Retry`, а после Alt+Tab работа
   продолжается с того же элемента.

Элементы: заголовок — `Settings` (кроме Settings), `Back` (кроме Home), `Reload notes`; Home —
список, `Retry`; редактор — `Title`, `Save note`; Settings — `Toggle compact rows`.

## Решения

- **D1.** Список — одна остановка Tab, внутри roving focus на стрелках (ARIA listbox, ListView).
- **D2.** Индикатор фокуса: контраст ≥ 3:1 к соседним цветам (WCAG 2.2 SC 2.4.7 + 1.4.11), не
  перекрыт (SC 2.4.11), отличается от overlay нажатия. High contrast Windows — вне релиза.
- **D3.** Назад — Alt+Left, `BrowserBack`, XButton1. Escape закрывает только модальные маршруты
  и не действует, пока фокус в текстовом поле.
- **D4.** Запрос на уничтоженный или устаревший узел получает новый отдельный результат (не
  `Rejected`, не `Queued`); это записывает ADR, заменяющий раздел ADR-0026. Поведение — R14.
- **D5.** Остаток #1040 чинится до релиза (R13c). #1092 исправлен полностью, закрываем.

## Текущее состояние

- Корневые привязки: Tab/Shift+Tab, Enter/Space/Select → `ActivateIntent`
  (`crates/flui-widgets/src/interaction/shortcuts.rs:539-546`). Escape, стрелки и клавиши Back
  не привязаны (`shortcuts.rs:405-406`, ADR-0079 «Not implemented»). Первый Tab без фокуса
  доходит до привязок через `claim_unfocused_keys` (ADR-0079 §3).
- Activator по умолчанию срабатывает и на автоповтор (`shortcuts.rs:54`, `:77`, `:139`):
  удержание Enter на кнопке повторяет активацию. Space срабатывает на key-down.
- Активация с клавиатуры исправлена для `InkWell` (`CHANGELOG.md:306`), на нём построен
  `TextButton` из Notes. `RawButton` — только `GestureDetector` + `Semantics`, без `Focus` и
  `ButtonActivateIntent` (`crates/flui-widgets/src/interaction/raw_button.rs:40`, `:81-96`);
  `crates/flui-widgets/ARCHITECTURE.md:1906-1908` верен.
- Порядок обхода — `ReadingOrderPolicy`: сверху вниз, затем слева направо, без RTL
  (`crates/flui-interaction/src/routing/focus_scope.rs:1961-1985`); на краю scope по умолчанию
  `ClosedLoop` (`focus_scope.rs:1911-1922`). Кандидаты — только присоединённые узлы.
- У каждого маршрута свой `FocusScope` (`crates/flui-widgets/src/navigator/modal_route.rs:288-300`).
  При `TopChanged` новый верхний маршрут забирает фокус и восстанавливает запомненный
  (`crates/flui-widgets/src/navigator/navigator.rs:466-485`). Документация
  `crates/flui-widgets/src/navigator/page_route.rs:32` («no `FocusScope`») устарела.
- `crates/flui-widgets/src/scroll/` не знает о фокусе: нет прокрутки к фокусу, клавиш и
  закрепления строки. Tab после последней построенной строки уходит по кругу в заголовок.
- Индикатор фокуса у `TextButton`: overlay `primary` с альфой 0.1, тот же, что у нажатия
  (`packages/flui-material/src/elevated_button.rs:174-186`, `text_button.rs:131`); в
  `ThemeData` нет `focusColor` (`packages/flui-material/src/ink_well.rs:28-30`). Строки списка
  в Notes без отступов (`tree.rs:302-311`). Видимость индикатора не проверяет ни один тест.
- Запрос фокуса на отсоединённый узел возвращает `Queued` («исполнится при присоединении»,
  `focus_scope.rs:155-156`), в том числе для узла уничтоженного элемента.
- #1040 исправлен в #1152: запрос из слушателя ставится в очередь, FIFO, с ограничением
  (`crates/flui-interaction/src/routing/focus.rs:39-60`). Остаток: публичный
  `FocusAttachment::replace_node` (`focus_scope.rs:241`) ведёт в `finish_node_replacement`, а тот
  защищён только `debug_assert` (`focus.rs:385-404`; в doc сказано «no reachable caller»).
  Слушатель может вызвать `replace_node` во время уведомления, и release-сборка опубликует
  устаревший переход.
- #1092 исправлен в #1153: winit-backend отдаёт событие через `ui-events-winit`
  (`crates/flui-platform/src/platforms/winit/events.rs:378-382`); issue можно закрыть.
- Тесты: `tests/fixtures/notes_flow.rs:357-385` и нативно
  `tools/xtask/src/device/windows_notes.rs:548-555` проверяют только путь «поле → Tab,
  Shift+Tab, Tab → Enter на `Save note`», а поле фокусируется указателем. Остальное не
  проверено.

## Требования

Уровни (`docs/testing.md`): **виджетный** — строка `notes_public_input_flow_matrix` в
`tests/fixtures/notes_flow.rs` (через facade), **a11y**, **GPU readback**, **нативный**
(`cargo xtask device windows-notes`).

### Обход и активация

- **R1.** КОГДА окно Notes открывается, СИСТЕМА ДОЛЖНА оставлять primary focus пустым (ADR-0079
  §3): Narrator объявляет окно («FLUI Notes»). Первый Tab (Shift+Tab) фокусирует первый
  (последний) по порядку элемент текущего маршрута, и Narrator объявляет его («Settings,
  кнопка»). Элемент перекрытого маршрута не фокусируется. Тест: виджетный + a11y,
  `first_tab_enters_the_current_route`.
- **R2.** КОГДА пользователь нажимает Tab на любом экране (Home загружен, Home с ошибкой,
  редактор, Settings), СИСТЕМА ДОЛЖНА проходить каждый интерактивный элемент ровно один раз в
  порядке чтения (заголовок слева направо, затем содержимое; список — одна остановка, D1).
  Shift+Tab идёт в точно обратном порядке, за последним элементом — первый того же маршрута.
  Тест: виджетный, таблица по экранам; последовательность читается по узлу `focused` в
  `A11yTree`: `tab_order_covers_every_screen`.
- **R3.** КОГДА элемент в фокусе, СИСТЕМА ДОЛЖНА выполнять на Enter (key-down) и на Space
  (key-up, с состоянием «нажато», пока Space удерживается, как в WinUI) то же действие, что и
  клик. Отключённый элемент ничего не делает, клавиша всплывает дальше. Так же ДОЛЖЕН работать
  `RawButton`: он фокусируем при наличии `on_press` и отвечает на
  `ActivateIntent`/`ButtonActivateIntent`. Тесты: виджетный, таблица «элемент × клавиша»
  `keyboard_activation_matches_click`; `crates/flui-widgets/tests/raw_button.rs`
  `raw_button_activates_from_the_keyboard` (падает на текущем коде).
- **R4.** КОГДА элемент в фокусе, СИСТЕМА ДОЛЖНА рисовать индикатор фокуса по D2: контраст
  индикатора с соседними цветами не ниже 3:1, индикатор отличается от overlay нажатия, виден у
  строк без отступов и не перекрыт. Тест: GPU readback (вместе со спекой `render-proof`); точки
  выборки на индикаторе строки и кнопки заголовка различают «в фокусе», «без фокуса» и «нажато»,
  контраст считается по WCAG: `focus_indicator_is_painted`.

### Ленивый список (10 000 строк, D1)

- **R5.** КОГДА фокус в списке Home, СИСТЕМА ДОЛЖНА вести себя по таблице. После каждого шага
  целевая строка построена, в фокусе и целиком видна; строка, которой не было среди построенных,
  строится не позже следующего кадра. Тест: виджетный, одна таблица
  `list_keyboard_navigation`, строка на каждую строку ниже.

  | Ввод | Результат |
  |------|-----------|
  | Вход Tab / Shift+Tab | запомненная строка, иначе первая видимая |
  | ArrowDown / ArrowUp | соседняя строка; на краю ничего, фокус остаётся |
  | PageDown / PageUp | первое нажатие — последняя (первая) полностью видимая строка; следующие — на страницу дальше |
  | Home / End | строка 0 / строка 9999 |
  | Tab из списка | следующий элемент после списка (на Home — по кругу в заголовок) |
  | Предел построения | построенных строк ≤ видимая полоса + cache extent + 1 (закреплённая, R6) |
  | a11y | у строки роль элемента списка с позицией и размером набора: Narrator читает «Note 5, 6 из 10000» |

- **R6.** КОГДА сфокусированная строка уходит из viewport при прокрутке указателем, СИСТЕМА
  ДОЛЖНА держать её закреплённой: строка остаётся построенной, в фокусе и в `A11yTree`. Следующая
  стрелка или Enter действуют от неё и прокручивают её в видимую область. Тест: виджетный,
  `focused_row_is_pinned_while_scrolled_away`.

### Маршруты и окно

- **R7.** КОГДА маршрут открывается (push), СИСТЕМА ДОЛЖНА переносить фокус в новый маршрут:
  в редакторе — на поле `Title` (autofocus в showcase), в Settings — на первый элемент по
  порядку. Перекрытый маршрут не держит primary focus и не получает ни Tab, ни клавишных
  событий. Тест: виджетный, `push_moves_focus_into_the_new_route`.
- **R8.** КОГДА верхний маршрут закрывается, СИСТЕМА ДОЛЖНА возвращать фокус на элемент,
  который его открыл. Для `Settings` это кнопка `Settings`. Для заметки — строка той же заметки
  по ключу, даже если её элемент пересобран или уничтожен (например, смена плотности в Settings
  меняет геометрию строк). Если заметки больше нет, фокус получает тот же индекс, приведённый к
  границам списка; если список пуст — первый элемент маршрута. Тест: виджетный, таблица
  `pop_restores_the_opening_element`.
- **R9.** КОГДА пользователь нажимает Alt+Left или `BrowserBack` или кнопку мыши XButton1 на
  странице, ниже которой есть другая, СИСТЕМА ДОЛЖНА закрывать только текущую страницу, как
  `Back`, сохраняя черновик; на Home — ничего. Escape закрывает только модальный маршрут и
  ничего не делает, пока фокус в текстовом поле; страницы Notes модальными не являются. Клавиша,
  чей key-down поглотил IME, вместе с её key-up и повторами до навигации не доходит. Тест:
  виджетный, таблица `back_keys_pop_only_the_current_page` (модальный маршрут — строка в
  `flui-widgets`).
- **R10.** КОГДА окно деактивируется и снова активируется (Alt+Tab), СИСТЕМА ДОЛЖНА возвращать
  фокус на последний сфокусированный элемент, а индикатор — в прежнее состояние. Тест:
  виджетный, `window_reactivation_restores_focus`; шаг нативного тура R18.

### Сценарии отказа

- **R11. Клавиша во время перехода.** КОГДА клавишное событие приходит, пока маршрут анимирует
  вход или выход, СИСТЕМА ДОЛЖНА доставлять его только в текущий верхний маршрут; уходящая
  страница с клавиатуры не активируется. Если push отменён клавишей Back посреди перехода, фокус
  возвращается по R8. Тест: виджетный, кадр в середине перехода,
  `keys_during_transition_reach_only_the_top_route`.
- **R12. Автоповтор и чужой key-down.** КОГДА пользователь удерживает Enter или Space, СИСТЕМА
  ДОЛЖНА выполнять одну активацию на одно физическое нажатие. Повтор или key-up, чей key-down
  достался другому получателю фокуса (Enter открыл заметку, повторы пришли в редактор), ничего
  не делают. Tab, стрелки и символы повторяются. Удержание Enter на `Settings` даёт ровно одну
  страницу Settings. Тест: виджетный, down + 5 repeat + up, `held_enter_activates_once`;
  нативный тур R18 удерживает Enter.
- **R13a. Порядок уведомлений (#1040).** КОГДА слушатель смены фокуса сам меняет фокус,
  СИСТЕМА ДОЛЖНА публиковать переходы в хронологическом порядке, и последний опубликованный
  получатель равен `primary_focus()`. Тест: публичный API `flui-interaction` (упорядоченный тест
  из #1152).
- **R13b. a11y следует за фокусом.** КОГДА шаг клавиатурного тура закончен, СИСТЕМА ДОЛЖНА
  публиковать `focused` в `A11yTree` ровно на primary focus. Тест: инвариант после каждого шага
  R2 и R5.
- **R13c. Вложенная замена узла (D5).** КОГДА `FocusAttachment::replace_node` вызван из
  слушателя во время уведомления, СИСТЕМА ДОЛЖНА либо поставить замену в очередь за текущим
  уведомлением, либо отказать с ошибкой, и в release-сборке тоже; устаревший переход не
  публикуется. Тест: публичный API `flui-interaction`, `nested_replacement_publishes_no_stale_edge`.
- **R14. Запрос на устаревший узел (D4).** КОГДА код вызывает `request_focus` на узле, чей
  элемент уже уничтожен (захваченный callback редактора после pop), СИСТЕМА ДОЛЖНА возвращать
  отдельный результат «устаревший», оставлять фокус прежним, не паниковать и не исполнять запрос
  позже. Тест: виджетный в `flui-widgets`, `stale_focus_request_is_inert`.
- **R15. Уничтожение сфокусированного элемента.** КОГДА сфокусированный элемент пересобирается
  с тем же ключом, СИСТЕМА ДОЛЖНА сохранять на нём фокус. Только если элемент действительно
  исчез (`Retry` после успешной загрузки), фокус переходит на следующий по порядку элемент того
  же маршрута, а если его нет — на первый, и не становится `None`, пока фокусируемые элементы
  есть. Тест: виджетный, таблица `focus_survives_rebuild_and_moves_on_removal`.
- **R16. Паника в callback.** КОГДА `on_press` паникует при активации с клавиатуры или паникует
  слушатель фокуса, СИСТЕМА ДОЛЖНА действовать по PANIC-POLICY: менеджер фокуса остаётся рабочим,
  и следующий Tab переводит фокус. Тест: виджетный, таблица
  `keyboard_continues_after_callback_panic`.
- **R17. Индикатор по модальности ввода.** КОГДА фокус выставлен только pointer-вводом (тап,
  клик), СИСТЕМА НЕ ДОЛЖНА показывать индикатор на кнопках. Клавиша или перенос фокуса
  assistive technology (Narrator через UIA `SetFocus`) считаются клавиатурным фокусом и
  индикатор показывают. На платформе без аппаратной клавиатуры Notes проходится указателем и
  действиями a11y без ошибок. Тест: виджетный, таблица `focus_indicator_follows_input_modality`.

### Нативно

- **R18.** КОГДА Notes запущен на сертифицируемой desktop-платформе (D1 уровня 0), СИСТЕМА ДОЛЖНА
  проходить тур: первый Tab, обход каждого экрана (UIA `HasKeyboardFocus`), End и PageDown,
  удержание Enter на строке, правка `Title`, Enter на `Save note`, Alt+Left с проверкой фокуса,
  Alt+Tab туда и обратно, Retry. Тест: нативный, `cargo xtask device windows-notes`, датированный.

Карта отказов: unmount — R6, R15; stale callback — R14; повтор — R12; реентерабельность —
R13a–c; переход и отмена push — R11; паника — R16; платформа — R17. Исчерпание ID не применимо:
`FocusNodeId` 64-битный и отказывает навсегда (`focus_scope.rs:26-37`), недостижимо за срок жизни.

## Вне scope

- Ctrl+S и другие сочетания приложения; стрелочный обход вне списка, `FocusTraversalGroup`.
- RTL-порядок обхода (Notes LTR) и high contrast Windows (D2): известные ограничения.
- Действие a11y `onFocus` и скринридер — спека `a11y-native`; композиция IME — `text-ime`.
- Восстановление фокуса после перезапуска (`persistence` его не хранит).
- Android, iOS, Web — `experimental`; для них только R17 на виджетном уровне.

## Открытые вопросы

1. Back на Apple: Option+Left там переходит по словам. Привязать Cmd+[ вместо Alt+Left?
2. Пустой список (все заметки удалены): остаётся ли он остановкой Tab с сообщением «нет
   заметок» или пропускается?
