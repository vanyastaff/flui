# Design: shared capability execution and conformance

The existing `flui_platform::executor::Executor` is the only execution contract added to `ProviderContext`; `HostIoPool` and concrete runtime pools stay above the platform boundary. `ProviderContext` gains optional executor access without changing its constructor's existing callers. `RuntimeHostServices` carries an optional `Arc<dyn Executor>` through initial and secondary presentations to the single production `ProviderContext`. `flui-app` supplies its loop-scoped `ExecutionServices`, and `HeadlessHost` supplies its deterministic background services. No hidden fallback pool is created; a provider without an executor reports unavailable.

On Linux, portal registration creates one `PortalShared` per capability registry and clones it into launcher and dialog providers. It owns the existing lazy `Bus` and a checked token mint. Runtime-local `Portal` owns only the shared handle, executor and a ticketed task book. Requests run as abortable IO futures. Handles are removed by exact ticket, all user-owned drops and abort calls happen outside locks, spawn refusal resolves through a shared resolver slot, and retirement aborts only that runtime's tasks. A narrow poll boundary contains request panics where the executor does not already do so, using the repository's annotated ADR-0287 exception rather than adding another public panic framework.

Tests define launcher and dialog scenarios once and drive them through public acquisition and `HeadlessHost`. Scripted and private-bus portal suites invoke the same tables; D-Bus mappings, reconnect, forged responses and absence tests stay portal-specific. The multi-runtime row shares one registry between two headless hosts and checks one caller unique name, distinct request tokens and independent cancellation.

The normal Linux `zruntime` dependency disappears; its dev-dependency remains for the stand-in bus service. ADR-0154, execution architecture and gaps are rewritten to the as-built rule. Platform parity remains marked as stand-in coverage until a real desktop portal run exists.
