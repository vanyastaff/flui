# flui-interaction — Rust-паттерны по темам

База: `main` @ `9a4daa3ed` (worktree оркестратора). Пути — от `crates/flui-interaction/src/`.
Версии std — по `rust-lang/rust/RELEASES.md`; probe-компиляция не выполнена (остановлена в очереди).

Это исходная сверка 2026-10-06. Предложения `Cell<GestureSettings>`, `set_settings`
и `GestureSettingsScope` ниже заменены [ADR-0172](../../../adr/ADR-0172-host-owned-system-preferences.md):
существующий `GestureArenaScope` доставляет read-only provider; последовательность
сохраняет snapshot при admission до terminal. Текущая приёмка — [tasks.md](tasks.md), I11.

## 1. Выбранный паттерн по теме

| Тема | Паттерн | Почему (и чем не является) |
|---|---|---|
| **Арена** (`arena/mod.rs`) | Слот + **поколение** (`ArenaGeneration`, `:243`), выдача по `checked_add` с отказом при исчерпании (`:863`); входной handle `GestureArenaEntry` (`:266`) несёт поколение; решения копятся в `DeferredResolution` и исполняются после снятия guard (`:584-586`). | Identity ≠ label: повторно использованный `PointerId` не попадает в старую арену. **Сменить хранилище:** `GestureArena` закреплён `!Send + !Sync` (`:1777`), а внутри `DashMap` + `parking_lot::Mutex` (`:62-63`, `:248`, `:824-830`) — блокировки без потоков. Целевая форма — `Rc<RefCell<ArenaState>>` с `Slab`/`Vec<Option<Slot>>` + generational key; reentrancy решается уже существующей deferred-очередью, а не мьютексом. |
| **Распознаватели** (`recognizers/*`) | **Закрытый набор + sealed trait** (`GestureArenaMember: sealed::arena_member::Sealed`, `arena/mod.rs:134`); один `GestureRecognizer` (`recognizer.rs:33`); фаза — **enum-машина состояний** (`Possible/Claiming/Started/…`), переход вычисляется под borrow в `Outcome`/`Notice`, колбэки — после (ветка I2 `scale.rs:786-792`). Сдерживание паник — общие `invoke_callback`/`retire_callback` (вынести из `scale.rs` в `recognizers/callback_containment.rs`). | Вместо Flutter-иерархии `OneSequence → PrimaryPointer → Tap` — композиция: общий `ContactTracker`/`PrimaryContact` как **поле**, а не supertrait. Настройки — `Cell<GestureSettings>` (тип `Copy`), не `Arc<Mutex<_>>` (10 мест, см. §2). |
| **Колбэки распознавателей** | **Builder до `Arc`/`Rc`**: `TapRecognizer::builder(arena).on_tap(..).settings(s).build() -> Rc<Self>`; после build — неизменяемы. | Сейчас `with_on_*(self: Arc<Self>, ..) -> Arc<Self>` (`tap.rs:313,334`, 45 методов) + `set_settings` (10 шт.) — пара setter/fluent поверх уже разделённого `Arc`, требует interior mutability на каждое поле. |
| **Routing / hit-test** (`routing/hit_test.rs`, `interaction_lane.rs`) | Слои ID — **newtype над `NonZeroU64`** (`LaneId/TargetId/RouteId`, `interaction_lane.rs:31-37`); результат resolve — **токен** `ResolvedRouteToken` (`:223`); трансформ, не принимающий non-finite, возвращает `Option` (`hit_test.rs:450`). Регистрация целей — **RAII**: `register_*` возвращает guard, `Drop` снимает (сейчас пары `register_*/unregister_*`, `:1415-1807`). | Пара add/remove делает ответственность за снятие вызывающего; guard делает утечку невозможной и даёт одну точку для «снять во время dispatch». |
| **Mouse tracker** (`routing/mouse_tracker.rs`) | Состояние **на устройство** (`DeviceState`, `:139`) в упорядоченной коллекции (`BTreeMap<DeviceId, _>` или `Vec`); работа на устройство собирается в `DeviceWork` (`:788`) под borrow, колбэки — после, с изоляцией паники по устройству и сохранением первой. Курсор — `enum CursorRequest { Defer, Icon(CursorIcon) }` вместо сентинела `CursorIcon::Default` (`hit_test.rs:739-748`). | Порядок enter/exit — контракт (W3C), он не может зависеть от `HashMap`. `clippy::iter_over_hash_type` ловит только `for`-циклы, не `.values().map()` — поэтому тип, а не lint. |
| **Фокус** (`routing/focus.rs`, `focus_scope.rs`) | `Rc<FocusNode>` + owner-local `FocusManager`; ID — `FocusNodeId(NonZeroU64)` (`ids.rs:90`), счётчик `try_update(checked_add)` с постоянным отказом (`focus_scope.rs:33`). Подписки — **RAII `Subscription`** вместо `add_listener -> ListenerId` + `remove_listener` (`focus.rs:452/471`, `focus_scope.rs:748/767`). Результат обработки клавиши — `KeyEventResult` (уже есть, `focus_scope.rs:60`), а не `bool` (`KeyEventCallback = Rc<dyn Fn(&KeyEvent) -> bool>`, `focus.rs:24`). | Узел — модель с наблюдателями, но наблюдение — guard, не пара методов. Конфигурация узла (`can_request_focus`, `skip_traversal`, `autofocus`, `traps_focus`) — одна `FocusNodeConfig` (Copy) + `set_config`, а не 6 `set_*(bool)` (`focus_scope.rs:526-1643`). |
| **Velocity / processing** (`processing/*`, `velocity.rs`) | **Чистые значения + стратегия**: трекер принимает `(EventTime, Point<f64>)`, окно/стоп — в `Duration` (`HORIZON`, `ASSUME_POINTER_STOPPED`), сравнение `Duration`↔`Duration`, а не `as_secs_f64()*1000.0` (`processing/velocity.rs:341-342,510-511`). Стоп-гейт берёт «сейчас» из того же источника, что и отсчёты (`estimate_at(now)`), не `Instant::now()` (`:208-229`). Выбор оценщика — `enum VelocityEstimator { Lsq{..}, Impulse }` в настройках, не 4 параллельных типа с одинаковыми `get_*`. Выход — `Velocity` только конечный (тип/конструктор `try_new`). | `get_velocity*`/`get_fling_velocity(allow_slow: bool)` (`processing/velocity.rs:271-930`, 12 мест) — Dart-форма: `velocity()`, `fling_velocity(FlingGate::{AllowSlow, RequireMin})`. |
| **Настройки** (`settings.rs`) | **Валидирующий конструктор**: `GestureSettings::try_new(..) -> Result<_, GestureSettingsError>` (thiserror, `#[non_exhaustive]`), поля приватные, `Copy`; профили — `const`-конструкторы (`android_defaults()`…). Доставка в распознаватели — inherited `GestureSettingsScope` (widgets) → builder распознавателя. | Сейчас невалидное значение молча клампится/заменяется (ветка I3 `settings.rs:190-226`, `prediction.rs:84-92`). |
| **События / словарь** (`events.rs`, `flui-platform-api::pointer` — ветка P1) | **Валидированные newtype-величины** (`PointerPosition`, `Pressure`, `PenOrientation`, `PanZoomTransform` с `try_new -> Result<_, InputValueError>`), `Option` = «нет датчика», `#[non_exhaustive]` на событиях/деталях, `EventTime(u64)` наносекунды + `saturating_duration_since`, `PointerId/DeviceId(NonZeroU64)` с `From`/`TryFrom<u64>`. | Образцовая форма (P1, `pointer/value.rs`, `pointer/mod.rs`). Остаток в текущем крейте: `pub type DeviceId = i32` (`ids.rs:223`) — alias, не newtype; два ext-трейта на одно (`PointerEventExt` `events.rs:458` и `PointerEventExtTrait` `traits.rs:84`). |
| **Text input** (`text_input.rs`) | **Токен владения** `ClientToken(NonZeroU64)` (`:64`), счётчик `checked_add` (`:366`), ошибки — `TextInputError` (`:124`), исходы — `DetachOutcome` (`:114`). | Файл занят веткой text-ime; только сверка. `set_transaction_open(bool)` (`:561`) — кандидат на RAII `TransactionGuard` (открыть = получить guard, закрыть = drop). |
| **ID** (`ids.rs`, арена, lane) | `NonZeroU64` newtype, приватный конструктор (`pub(crate) fn new`), выдача `checked_add` + постоянный отказ; для слотов — generational key. `AtomicU64::try_update` (1.95) там, где счётчик глобальный (ADR-0097), `Cell<u64>` + `checked_add` — где owner-local. | Нарушения: `HandlerId::new(inner.next_handler_id); next_handler_id += 1` без проверки (`arena/signal_resolver.rs:151-152`); `checked_add(1).unwrap_or(0)` как «исчерпан» (`interaction_lane.rs:290,298`, `focus_scope.rs:33`) — сентинел 0 вместо `Option`/ошибки (терпимо, т.к. 0 непредставим в `NonZero`, но читать как тип лучше: `checked_add(1).and_then(NonZero::new)`). |
