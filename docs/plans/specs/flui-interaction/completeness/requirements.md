# Полнота ввода: ядро без пакетов-заплаток — требования

- **Статус:** scope утверждён владельцем 2026-10-12; design и задачи — [design.md](design.md), [tasks.md](tasks.md)
- **Дата:** 2026-10-12
- **Охват крейтов:** `flui-platform-api` (словарь и capability-трейты), `flui-platform` (бэкенды),
  `flui-interaction` (маршрутизация, жесты, фокус, IME-хост), `flui-widgets` (поведенческие виджеты),
  существующие `packages/flui-material`, `packages/flui-cupertino`, `packages/flui-devtools`.
  **Новых крейтов нет.**
- **Исследования:** [../../../../research/2026-10-12-interaction-input-best-practices.md](../../../../research/2026-10-12-interaction-input-best-practices.md),
  [../../../../research/2026-10-12-interaction-input-followups.md](../../../../research/2026-10-12-interaction-input-followups.md)
- **Предыдущая волна:** [../matrix.md](../matrix.md), [../scope-closure.md](../scope-closure.md), [../tasks.md](../tasks.md);
  спеки [../recognizer-api/](../recognizer-api/requirements.md), [../pointer-vocabulary/](../pointer-vocabulary/requirements.md)

## Зачем

У Flutter сообщество держит десятки пакетов, которые закрывают дыры ядра
([fluttergems: Touch & Gesture](https://fluttergems.dev/touch-gesture/) и соседние категории):
детекторы свайпа, трансформ-жесты с поворотом, нативный drag-and-drop, slidable/swipe-actions,
reorderable-списки, hit-test по фигурам, haptic-паттерны, оверлей касаний, обходы арены для вложенных
скроллов. Причины повторяются: арена не выражает «родитель уступает прокручиваемому ребёнку»
(flutter/flutter#50946, #81648), нет отдельного жеста поворота (#57698), DnD только внутри приложения
(#30719), haptics — пять фиксированных пресетов без проверки поддержки.

Цель: ядро FLUI закрывает эти потребности само, на всех платформах, с поведением, закреплённым тестами.
Пакет сообщества должен появляться ради нового, а не ради недостающего в ядре.

Состояние на 2026-10-12 (инвентаризация кода): арена, 10 распознавателей, скорость, ресэмплинг,
захват указателя и фокус — сильные; пробелы на краях. ОС-DnD нулевой на всех нативных бэкендах,
haptics нет ни в одном реальном бэкенде, нет pinch тачпада на Windows, пера на macOS/Linux, IME на
Web/Android/iOS; `ForcePress`, `MultiTap`, `TapAndDrag`, `Eager`, `OneEuro` без продакшн-вызова;
`GestureDetector` отдаёт около половины возможностей распознавателей; reorderable, swipe-actions,
контекстные меню, `SelectionArea` отсутствуют.

## Решения владельца (scope)

Приняты в обсуждении 2026-10-12; каждая строка — требование этой спеки.

| # | Решение |
|---|---|
| S1 | Распознаватели и маршрутизация — `flui-interaction`; готовые жестовые виджеты — `flui-widgets` (поведение без стиля); стиль — тонкие обёртки в `flui-material`/`flui-cupertino`. Сенсорные жесты (shake, tilt по гироскопу) — вне охвата, позже как отдельная платформенная возможность. |
| S2 | API и архитектура готовы для Win32, macOS, iOS, Android, Linux (Wayland/X11), Web с первого дня. Разработка synthetic-first; затем нативная доводка каждой платформы, Windows первой. Срок не ограничивает дизайн; ломающие изменения допустимы. |
| S3 | Итог фиксируется в этой подспеке рядом с существующей; `matrix.md` перепроверяется, строки M2-R3 (1€) и M3-M3 (DnD) выводятся из OUT. |
| S4 | Координация жестов в два канала: арена решает владение контактом; отдельный синхронный канал делит дельты scroll/zoom/fling между прокручиваемыми предками и ребёнком. Отношение `Simultaneous` и вложенная композиция; ADR, заменяющий ADR-0167. |
| S5 | Блокировка оси — конфигурация распознавателя: `AxisLock::{Free, Horizontal, Vertical, DominantAfterSlop, Rails { breakout_angle }}`. |
| S6 | Windows: pan/zoom тачпада и touch через DirectManipulation в существующий `PointerEvent::PanZoom`; колбэки считаются реентерабельными. |
| S7 | Linux остаётся на winit, переход на 0.31 после stable; свой словарь (ADR-0143) сохраняется; отсутствующие возможности — типизированно в `capabilities()`. |
| S8 | Haptics в два уровня: семантический `HapticIntent` и паттерны с проверкой поддержки; ADR, заменяющий ADR-0031. Виджеты сами вызывают отклик по пресету платформы; приложение выключает на поддереве. |
| S9 | Один DnD API для внутреннего и межприложенческого перетаскивания: ленивые представления, внутри процесса — Rust-значение напрямую; ADR, дополняющий ADR-0038. |
| S10 | Сериализуемая запись ввода `InputRecording` (поток `PlatformInput`) — фича `recording` в `flui-platform-api`; имя `trace` не используется, чтобы не путать с `tracing`. Headless-бэкенд — единственный синтетический драйвер: проигрывает скрипты и записи и показывает каждый вызов возможностей (haptics, DnD, IME) как наблюдаемое событие. Нативная запись — тап в каждом бэкенде в тот же формат. |
| S11 | Проверка соответствия бэкендов — модуль `backend_conformance` в `flui-platform-api`, вход `assert_backend_conforms` (образец — `text_store_kit::assert_conforms`, который сам переименовывается по спеке [../../naming/](../../naming/renames.md)); бэкенд, не прошедший проверку, не готов. |
| S12 | Нативная инъекция для сертификации — Rust-команды в `xtask`; Windows первой, остальные — скелет и пометка «не запускалось на этом хосте». |
| S13 | Пресеты «поведения» платформ (slop, таймауты, оценщик скорости, fling) по умолчанию нативные, значения со ссылкой на первоисточник ОС; переопределение на поддереве. |
| S14 | `flui-interaction` — модули верхнего уровня `pointer`, `gesture`, `focus`, `text_input` с односторонними зависимостями под `cargo xtask module-dag` (слои — в S-1). |
| S15 | `GestureBinding` — тонкий корень композиции над узкими сервисами. |
| S16 | Встроенные распознаватели используют только публичный API; доказательство — распознаватель в `crates/flui-sdk/tests/`, собранный только против `flui-sdk`. |
| S17 | Неподключённый `pub` подключается, а не удаляется: `ForcePress`, `MultiTap` → `GestureDetector`; `TapAndDrag` → выделение текста; `OneEuro` → опциональное сглаживание в `GestureSettings`; `Eager` — внутренний, если виджету не нужен. |
| S18 | Каждый жестовый виджет публикует semantics-действие, эквивалентное жесту. |
| S19 | Отладочный оверлей касаний, скоростей и решений арены — в `flui-devtools`, поверх `observability`. |
| S20 | Порядок работы: спека и ADR (docs-only PR) → задачи → реализация по одной задаче на PR → code-review → ретро. |

## Требования

ID действуют только внутри этой подспеки.

### G. Координация жестов

- **G1.** Вертикальный список внутри горизонтального pager: вертикальное движение прокручивает список,
  горизонтальное листает pager, решение принимается не позже выхода за slop; у края списка
  остаток дельты переходит к ближайшему прокручиваемому предку по той же оси.
- **G2.** Pinch на фото внутри pager: два контакта масштабируют фото; один контакт при масштабе 1
  листает pager; при увеличенном фото pan двигает фото до края, остаток — pager.
- **G3.** Pull-to-refresh над списком: перетягивание вниз в верхней точке списка расходуется индикатором
  до порога, без второй арены и без флага «disallow intercept».
- **G4.** Pan, scale и rotate на одном view распознаются одновременно (`Simultaneous`); отношения
  `Exclusive`, `RequireFirstFailure`, `Simultaneous` вкладываются; вложение больше не ошибка.
- **G5.** Отдельные распознаватели поворота и свайпа (дискретное направление + скорость; edge-swipe
  с заданного края) — каждый как обычный `GestureRecognizer`.
- **G6.** `AxisLock` у drag/pan/scale: `DominantAfterSlop` фиксирует ось, преобладавшую при выходе за
  slop; `Rails` прилипает к оси и срывается, когда угол движения превышает `breakout_angle`.
- **G7.** Арена сохраняет текущие гарантии: однократное урегулирование, поколения ID контактов,
  сдерживание паник (ADR-0127), отсутствие потоков-таймеров.

### P. Платформенные бэкенды

- **P1.** Каждый бэкенд объявляет поддержку через типизированный `capabilities()`; TODO и молчаливые
  пробелы запрещены.
- **P2.** Общая логика трансляции (ID и поколения контактов, счёт кликов, накопление pan/zoom,
  coalesced/predicted батчи, смена устройств) — в одном модуле `flui-platform`; бэкенд только отображает
  нативные показания в сырые сэмплы.
- **P2a.** Счёт кликов: где ОС не даёт число кликов, оно считается по системным таймауту и slop
  (сейчас Win32 всегда отдаёт 1, хотя читает `GetDoubleClickTime`).
- **P3.** Windows: DirectManipulation (pinch/pan/инерция тачпада и touch), OLE DnD, haptics пера,
  `capabilities()` без TODO.
- **P4.** macOS: tablet/proximity (перо), smart magnify и swipe, `NSDragging*` DnD,
  `NSHapticFeedbackManager`.
- **P5.** iOS: pinch/rotate, прокрутка трекпада и мыши, coalesced/predicted touches, `UITextInput`,
  `UIDragInteraction`/`UIDropInteraction`, haptics, Pencil (squeeze, double-tap, hover).
- **P6.** Android: IME через `InputConnection`, DnD, haptics (`VibrationEffect`), pinch тачпада,
  рукописный ввод стилусом — по решению design.
- **P7.** Linux: winit 0.31 (перо, двусторонний DnD); честный `composing` у клавиш.
- **P8.** Web: IME (решение design: EditContext и/или скрытый элемент), ctrl+wheel и Safari `gesture*`
  → `PanZoom`, HTML DnD, Vibration API где есть.

### H. Haptics

- **H1.** Семантический `HapticIntent` — данные, которые объявляют распознаватели и виджеты.
- **H2.** Паттерны (последовательность примитивов, интенсивность) с проверкой поддержки до вызова и
  определённой деградацией.
- **H3.** Виджетный путь через lifecycle-возможность (ADR-0078); выключение на поддереве.
- **H4.** Headless записывает каждый вызов; тест виджета проверяет, что порог dismiss/swipe-action и
  long-press дают отклик.

### D. Drag-and-drop

- **D1.** Один источник/цель для внутреннего и ОС-перетаскивания; `Draggable`/`DragTarget` поверх него.
- **D2.** Ленивые представления (Rust-значение, текст, URI, файлы, promised files); внутри процесса drop
  отдаёт значение без сериализации.
- **D3.** Операции copy/move/link, изображение перетаскивания, позиционирование по глобальным
  координатам, стратегия якоря, long-press-вариант.
- **D4.** Ограничения платформ выражены типами (Web: данные к `dragstart`; X11: действие только на drop).
- **D5.** Runtime доставляет `DragDrop`-ввод (сейчас отбрасывается с debug-трассой).

### T. Тестирование

- **T1.** Три уровня: скрипты на виртуальных часах (расширенный `PointerScript`), записанные нативные
  трассы, ОС-инъекция только для сертификации.
- **T2.** Формат трассы версионирован, хранит время источника и время прихода, описание устройств;
  проигрывается headless без тест-only типов событий.
- **T3.** Golden-трассы с реальных устройств (как минимум Windows touch/pen/тачпад) лежат в репозитории
  и проходят в CI.
- **T4.** `backend_conformance`: переиспользование ID, cancel при потере захвата, coalesced раньше predicted,
  поток `PanZoom` всегда завершается, DnD leave после enter, haptics принят или объявлен
  неподдерживаемым.
- **T5.** Пресеты платформ — тестируемые константы со ссылкой на источник.

### W. Виджеты

- **W1.** `GestureDetector`: tap down/up/cancel, vertical drag, long-press start/move/end, tertiary tap,
  force press, multi-tap, rotate, swipe.
- **W2.** Поведенческие виджеты в `flui-widgets`: swipe-actions строки, reorderable list/grid,
  photo-zoom с drag-to-dismiss и snap-back, контекстное и long-press меню (якорное popup),
  `SelectionArea` для неизменяемого текста, ручки и тулбар выделения, `LongPressDraggable`,
  расширение области попадания без изменения layout, hit-test по фигуре для custom paint.
- **W3.** Стиль Material/Cupertino — тонкие обёртки в существующих пакетах.

### A. Доступность

- **A1.** Swipe-actions → custom actions; reorder → «переместить выше/ниже»; dismiss → dismiss;
  zoom → increase/decrease; long-press меню → «показать меню».
- **A2.** Для каждого виджета тест падает, если действие недоступно без жеста.

### F. Фокус и клавиатура

- **F1.** Задачи T3–T16 спеки [../../focus-keyboard/](../../focus-keyboard/tasks.md) входят в охват:
  modality и focus-visible, трекинг нажатых клавиш с ресинхронизацией, восстановление фокуса,
  рабочий `traps_focus`, Esc/Back/PageUp/PageDown/Home/End, навигация в списках, X1/X2 → Back.

### M. Модули

- **M1.** Слои снизу вверх: базовый (словарь событий, ID, закрытие владельца `close`, сдерживание
  паник) → `pointer` (hit-test, маршрутизация, захват, hover, ресэмплинг) → `gesture` (арена,
  распознаватели, скорость, настройки); `focus` и `text_input` — над базовым слоем, независимо от
  `pointer`/`gesture`; `binding` — корень композиции наверху. `gesture` импортирует `pointer`, не наоборот;
  `gesture` и `focus` друг друга не импортируют. Порядок задаётся `[package.metadata.flui.modules]` и
  проверяется `module-dag`; исключения запрещены.
- **M2.** `GestureBinding` — корень композиции; сервисы с узким API и своими тестами.
- **M3.** Внешний распознаватель в `crates/flui-sdk/tests/` собирается только против `flui-sdk`.
- **M4.** Каждый `pub`-элемент достижим из продакшн-пути.

### N. Имена и конвенции Rust

- **N1.** Публичный API следует [Rust API Guidelines](https://rust-lang.github.io/api-guidelines/):
  `UpperCamelCase` для типов и вариантов, `snake_case` для функций и модулей; конверсии
  `as_`/`to_`/`into_`; геттеры без `get_`; `From`/`TryFrom`/`Display`/`Default`, где применимо;
  `#[must_use]` на значениях, которые нельзя молча выбросить; `#[non_exhaustive]` на растущих
  публичных перечислениях; ошибки — перечисления `thiserror`, которые вызывающий может сопоставить.
- **N2.** Имя говорит, что это или что оно делает. Запрещены `kit`, `util(s)`, `helper(s)`, `common`,
  `support`, `misc`, `manager` без предмета и пустые `Data`/`Info`/`Impl`/`Base`/`Wrapper`.
  Без заикания пути: `gesture::Arena`, не `gesture::GestureArena`, если модуль уже называет предмет;
  публичный реэкспорт верхнего уровня сохраняет полное имя только там, где без модуля оно двусмысленно.
- **N3.** Имена Flutter не переносятся сами по себе; узнаваемое имя Flutter — `#[doc(alias)]`
  ([../../naming/renames.md](../../naming/renames.md)).
- **N4.** Состояние, которое нельзя смешать, — разные типы, а не флаги: состояния сессии DnD,
  фазы `PanZoom`, поддержанная/неподдержанная возможность.
- **N5.** Предлагаемые в design имена проходят ревью таблицей «имя → что это → почему не короче/длиннее»
  до реализации; переименование после слияния — отдельная задача.

### O. Наблюдаемость

- **O1.** Оверлей в `flui-devtools`: контакты, траектории, вектор скорости, победитель арены и причина.

## Вне охвата

- Сенсорные жесты (shake, наклон устройства) — отдельная платформенная возможность.
- Собственный Wayland/X11 бэкенд — пересмотр по результатам `backend_conformance`.
- Встраивание платформенных view (`cancelsTouchesInView`, M2-A11).

## Приёмка

Требование закрыто, когда его поведение закреплено тестом через публичный API, который падает с
откатом изменения; нативный путь, не исполненный на этом хосте, помечен так в PR и в `tasks.md`.
