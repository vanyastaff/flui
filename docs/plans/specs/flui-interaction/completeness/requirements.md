## Зачем

У Flutter сообщество держит десятки пакетов, которые закрывают дыры ядра
([fluttergems: Touch & Gesture](https://fluttergems.dev/touch-gesture/) и соседние категории):
детекторы свайпа, трансформ-жесты с поворотом, нативный drag-and-drop, slidable/swipe-actions,
reorderable-списки, hit-test по фигурам, haptic-паттерны, оверлей касаний, обходы арены для вложенных
скроллов, сворачивающиеся заголовки. Причины повторяются: арена не выражает «родитель уступает
прокручиваемому ребёнку» (flutter/flutter#50946, #81648), `NestedScrollView` — признанная ошибка
(#102003), DnD только внутри приложения (#30719), `Dismissible` конфликтует со скроллами годами (#32954,
#24233), у поведенческих виджетов нет semantics, haptics — пять пресетов без проверки поддержки. Те же
провалы гости из Rust-фреймворков показали у себя: захват как совет (Iced #2004), touch как эмуляция мыши
(Iced, Slint #834, egui), прокрутка «всё или ничего» (Masonry), DnD только файлами (Iced, egui, Bevy),
жесты, выданные за события мыши (GPUI), задержка нажатия у родителя (Slint #13120, #6781).

Цель: ядро FLUI закрывает эти потребности само, на всех платформах, с поведением, закреплённым тестами,
и с поверхностью расширения, на которой сторонний автор пишет жест не хуже встроенного.

## Решения владельца

Приняты 2026-10-12/13 в обсуждении и трёх раундах атаки дизайна (Flutter, Compose, Apple, Rust UI, ввод
ОС/браузеров, доступность, сопровождающий; гости GPUI, Xilem/Masonry, Slint, Iced, egui, Dioxus/Blitz и
Bevy).

| S2 | API и архитектура готовы для Win32, macOS, iOS, Android, Linux (Wayland/X11), Web. Разработка synthetic-first, затем нативная доводка каждой ОС, Windows первой. Срок не ограничивает дизайн; ломающие изменения допустимы. |
| S3 | Всё определённое здесь строится в этой спеке, независимо от наличия потребителя сегодня. Нет релизного среза и выноса в подспеки; есть порядок задач. Неподключённого `pub` нет, потому что потребителя строим в том же плане. |

## Требования

ID действуют только внутри этой подспеки. Каждое требование закрывается тестом через публичный API,
который падает с откатом изменения.

### B. Граница ввода и время (позвоночник)

- **B1.** `HostInput::{Platform(PlatformInput), Window(WindowEvent), Frame { vsync }, Accessibility(ActionRequest)}`
  — единственный вход рантайма; запись, проигрывание и наблюдатель видят именно его.
- **B2.** Одна шкала времени: дедлайны арены, долгое нажатие, таймауты latch, spring-loading, синтез End
  pinch в вебе — на шкале `EventTime`. В headless один виртуальный источник ведёт часы взаимодействия (по
  времени прихода) и `FrameClock` (по vsync). Двойное проигрывание одной записи даёт одинаковые решения
  арены.
- **B3.** `InputSequenceId` выдаёт `GestureBinding` (`NonZeroU64`, без переиспользования, исчерпание —
  постоянный отказ) на контакт, на последовательность колеса, клавиатуры, AT и автопрокрутки; несут его
  событие, детали жестов, канал, DnD-сессия, запрос haptics, запись и наблюдатель.
- **B4.** Реентерабельное нативное событие никогда не теряется: при занятом колбэке ставится в очередь.
- **B5.** `InputSurface` (окно или встроенная поверхность) — корень маршрутизации и записи; указатель вида
  `Virtual` с собственным id устройства (геймпадный курсор, автоматизация, будущий XR) входит до заморозки
  формата.

### G. Арена

- **G1.** Нормативная таблица владения (строки — виды членов: осевой, свободный, scale, `AnchoredDrag`
  лист/предок, `Sequenced`; столбцы — топологии); каждая клетка — строка проверки соответствия.
- **G2.** Ось решается по накопленному смещению от Down; осевой член без ортогонального конкурента держит
  контакт до slop по своей оси или отпускания; строки 44°/45°/46° с шумом первого сэмпла.
- **G3.** `PanClaim::{Auto, PanX, PanY, None}` поддерева при Down (как CSS `touch-action`) и
  `allowed_devices` распознавателя (перо рисует, палец прокручивает). Свободный член уступает осевому, если
  на ось того приходится не меньше cos 45° движения, если `PanClaim` поддерева не говорит иного.
- **G4.** Одна ось у двух вложенных: предок — участник канала не соревнуется в арене с потомком-листом по
  этой оси; самый внутренний претендент владеет, предок получает дельты. Лист канала, предки которого берут
  остаток (`InteractiveViewer`), не уступает.
- **G5.** Композиция `Exclusive`, `RequireFailure`, `Sequenced` (удержание → преемник, один член арены,
  явная передача) вкладывается; `AlreadyComposed` удаляется; потолок задержки разрешения
  `max_resolution_delay` из пресета, превышение — диагностика при сборке. Пользователи `Sequenced`: меню →
  перетаскивание, DnD по долгому нажатию, reorder, ручки выделения.
- **G6.** Когда арена отдаёт контакт, проигравшие и `Listener` на пути получают `Cancel { reason }`.
- **G7.** Касание движущегося прокручиваемого: член hold побеждает tap и long-press на этом контакте, но не
  drag и scroll; hit-test детей не выключается; строка «вертикальный drag по оседающему pager».
- **G8.** `AxisLock` у pan/scale, проекция скорости, рельсы только для touch и тачпада, `TransformLock`.
- **G9.** `SwipeGestureRecognizer`; поворот — конфигурация Scale.
- **G10.** Hover замирает (курсор загорожен), пока последовательность прокрутки закреплена.

### C. Канал вложенной прокрутки

- **C1.** Список в pager; C2 — фото в pager (в т.ч. 30° и 50°, второй палец, край в начале, отмена);
  C3 — pull-to-refresh (колесо и инерция не вытягивают, отмена и проигрыш сбрасывают); C4 —
  сворачивающийся заголовок (float/pin/snap, Tab и AT выводят строку из-под заголовка — WCAG 2.4.11).
- **C5.** Fling — одна модель с наследованием id последовательности; `Momentum` не вызывает `post_fling`;
  новый ввод отменяет переданную инерцию; `nested_fling_*` ADR-0169 — строки.
- **C6.** Лист последовательности без контакта (колесо, клавиатура, AT, автопрокрутка) — самый глубокий
  участник под точкой или фокусом, способный поглотить первую дельту; закреплён на последовательность; та же
  реализация, что `AxisLock`. Latch по `(окно, устройство)` с первого PR сервиса.
- **C7.** Таймаут простоя latch у всех источников; у фазовых — длиннее (Wayland шлёт Start без End).
- **C8.** Любое изменение смещения идёт через один примитив: `ScrollCause::{UserInput, Momentum, SideEffect,
  Programmatic}`; `reveal(rect)` проходит всех предков через `pre_scroll`/`post_scroll`; пользовательский
  ввод прерывает программную и плавную прокрутку.
- **C9.** Контракт участника: снимок цепочки на последовательность, реентрантность отклоняется, паника =
  поглощено всё, результат конечен и в пределах; `ScrollEndReason::{Released, Cancelled, Preempted,
  ArenaLost}`; без аллокаций.
- **C10.** `SnapPolicy` — одна для страниц и якорей.

### P. Платформы

- **P1.** Доступность возможностей — из handle; `InputCapabilities` (`#[non_exhaustive]`, методы) только для
  безhandle-возможностей; `Availability::{Native, Emulated, Unavailable}`; «реализовано» отдельно от
  «присутствует»; изменение — событием; `PlatformCapabilities` удаляется.
- **P2.** Сборка указателя один раз в `flui-platform/src/shared/`; чистые функции разбора на всех целях;
  бэкенд хранит исходное нативное событие на контакт (старт нативного DnD).
- **P3.** Счёт кликов по настройкам ОС. P4 — часы: точнейшие часы ОС, выбор на устройство и
  последовательность, частота и якорь в заголовке нативной записи, монотонность, переполнение.
- **P5.** Прокрутка двумя пальцами — `Scroll` с фазами на всех ОС; `PanZoom` — масштаб/поворот с
  определённым фокусом.
- **P6.** Перо: поправки свойств (`Revise` — только в `Listener` и запись), hover, высота, roll, squeeze.
- **P7.** `InputRegions` — сбор областей ввода с layout на окно; первый вид — исключение системных жестов;
  далее области указателя и заголовка окна.
- **P8.** Windows: DirectManipulation (перевод в `Scroll` с фазами и `PanZoom`, прокачка, свой запрос кадра,
  модальный цикл размера); OLE DnD (отложенный старт в самой внешней точке покоя, кадры всем рантаймам
  потока, перерисовка второго окна); haptics; QPC.
- **P9–P13.** macOS, iOS, Android, Linux, Web — как design §7; каждая ОС разделена на задачи ввода, DnD,
  haptics, IME, инъекции и записей.
- **P14.** IME: `TextStore` (ADR-0090) и его проверка; Esc при композиции — сначала IME; таблица порядка
  событий IME на ОС — строки проверки.
- **P15.** Web: события, допускающие `preventDefault`, решаются синхронно в колбэке.

### H. Haptics

- **H1.** Уровни 1–2, `HapticRequest { source, timing }` у обоих; `HapticOutcome::Queued` для отложенных,
  итог — через наблюдатель.
- **H2.** Очередь кадра: запрашивает кадр, дедлайн → `Suppressed`, слив при скрытии и перекрытии окна.
- **H3.** Устаревший или неизвестный источник — устройство окна по умолчанию.
- **H4.** Настройка haptics пользователя — `SystemPreferences`; порог всегда с видимым изменением.
- **H5.** Lifecycle-возможность, выключение на поддереве, headless на границе кадра.

### D. Drag-and-drop

- **D1.** Типы ADR-0038; `Draggable`/`DragTarget` поверх; внутри окна — захват указателя; эскалация в ОС —
  выход за окно и непустые операции «снаружи».
- **D2.** Идентичность: (nonce процесса, `UiRuntimeId`, `DragSessionId`) в приватном формате; Rust-значение
  внутри одного `UiRuntime` (любые его презентации); между рантаймами — по Q35.
- **D3.** `AllowedActions { within_app, outside_app }`; несколько сессий; drop только цели, принявшей
  последнее движение.
- **D4.** Изображение, глобальная позиция, якорь, старт по `Sequenced`, Esc и курсор, spring-loading,
  автопрокрутка (`ScrollCause::SideEffect`), keep-alive перетаскиваемого.
- **D5.** Модальный цикл ОС: отложенный старт, тест реентрантности, перерисовка второго окна.
- **D6.** Ограничения платформ типами; runtime доставляет DnD в hit-test цели.

### R. Запись и проверки

- **R1.** Три уровня: скрипты на виртуальных часах (читаемые, с builder'ами мыши, touch, пера, тачпада,
  виртуального указателя наравне), записи, ОС-инъекция для сертификации.
- **R2.** Поток `HostInput` с `InputSurface`/`WindowId`, `t` и временем прихода, результатом
  диспетчеризации каждого события; заголовок — устройства, масштабы, значения поведения, часы.
- **R3.** Два уровня записей: `PlatformInput` проверяет `flui-interaction`; нативный кодек в тестах
  `flui-platform` проигрывает разобранные структуры в Linux CI.
- **R4.** Приватность: текст, заголовки, имена устройств скрыты.
- **R5.** `InputTap` в `flui-app`; сериализатор только в dev/tool сборке; обычный граф фасада без тестовой
  поддержки.
- **R6.** Проверки соответствия бэкенда; каждая функция (DnD, haptics) добавляет свои строки.
- **R7.** Генерированный круговой прогон каждого варианта словаря через DTO — gate против дрейфа.
- **R8.** Golden-записи и инъекция для каждой ОС; пути без инъекции сертифицируются записями с железа.
- **R9.** Строки «двойной клик внутри одного кадра», «N событий за кадр», «событие между vsync».
- **R10.** Тестовые поиски по дереву semantics (роль, метка); запуск «до успокоения» с пределом шагов.

### W. Виджеты и детектор

- **W1.** `GestureDetector` на типизированных слотах; конфликт невыразим.
- **W2.** `RawGestureDetector` принимает фабрику и `update(&config)`; экземпляр живёт в состоянии элемента;
  пересборка посреди жеста не рвёт его.
- **W3.** `AnchoredDrag` (одномерный, `SnapPolicy`) — основа `SwipeActions`, `Dismissible`, шторок.
- **W4.** `SwipeActions`: leading/trailing, полный свайп на отпускании, отмена возвратом.
- **W5.** `ReorderableList`/`Grid` — DnD-сессия с быстрым путём; keep-alive; автопрокрутка по времени.
- **W6.** `InteractiveViewer` — лист канала, поворот, snap-back, double-tap zoom.
- **W7.** `ContextMenuArea` на `Sequenced`.
- **W8.** `SelectionArea`: указатель, клавиатура, AT вместе; требует поправки ADR-0204 (текстовые прогоны
  для текста под `SelectionArea`, строка стоимости).
- **W9.** `HitSlop`: `min_target`; приоритет — визуальное попадание, расстояние до края, z-порядок; зона не
  пересекает слой, барьер, оверлей. W10 — hit-test по фигуре (render-объект с harness).
- **W11.** `PageView` — `Scrollable` с `SnapPolicy`; осевой drag.
- **W12.** Material/Cupertino — обёртки стиля.

### A. Доступность

- **A1.** `GestureAlternatives`: `Intent` → semantics-действие, клавиша, одноуказательная альтернатива (Q36).
- **A2.** Клавиши — значения по умолчанию `Shortcuts` на платформу во `flui-widgets` рядом с `Intent`; Esc не
  деструктивен; без пересечений с Back, закрытием, редактированием; проверка пересечений — там же.
- **A3.** Диагностика для путевого колбэка без `Intent`.
- **A4.** `MotionPreference::Reduce`, включая масштаб длительности 0 на Android.
- **A5.** Локализация с параметрами; объявление позиции; RTL.
- **A6.** Матрица виджет × путь ввода; строки — в PR каждого виджета; T-сборка матрицы и проверка версии
  адаптеров — в конце.
- **A7.** Вклад в AccessKit upstream.
- **A8.** Действия ключуются ключом модели, не элементом; «переместить в конец» ленивого списка сохраняет
  фокус и объявляет; бюджет стоимости semantics на строку.
- **A9.** Вид указателя для dwell/вспомогательных устройств.

### E. Поверхность расширения

- **E1.** Через `flui-sdk` — трейт распознавателя, dispatch, композиция, сдерживание, `RawGestureDetector`,
  `NestedScrollConnection`, `AnchoredDrag`, `SnapPolicy`, паттерны haptics, DnD; каждая задача добавляет
  свои строки `surface.rs`.
- **E2.** Доказательство — нестандартный распознаватель в `flui-sdk/tests`, смонтированный
  `RawGestureDetector`, с пересборкой посреди жеста.
- **E3.** Таблица размещения публичных имён.
- **E4.** Внешние релизы — типизированный `Unavailable` + строка проверки; подъём — «blocked-external».
- **E5.** Шаблон-чеклист нового поведенческого виджета (альтернативы, слот, локализация, строка канала,
  строки матрицы, обёртки стиля).

### Q. Качество

- **Q1.** High-DPI: slop в логических пикселях; дробный масштаб в записях и инъекции.
- **Q2.** Несколько окон и рантаймов: latch и захват по окну с первого PR сервисов; захват при drag из окна A
  над окном B остаётся у A.
- **Q3.** Бюджеты: без аллокаций у канала, сборки указателя и наблюдателя без подписчиков.
- **Q4.** wasm: нет файловой системы у записи; вибрация с активацией.

### M. Модули — M1 слои; M2 сервисы без обратных ссылок, `drain(&self)`; M3 достижимость `pub`.

### N. Имена — N1 API Guidelines; N2 устоявшийся термин, без `kit`/`util`/`helpers`/`common`/`support`;
N3 Flutter-имена — `#[doc(alias)]`; N4 несмешиваемое — разные типы; N5 таблица §0. Проверка — пункт
чеклиста каждого PR и задача аудита.

## Вне охвата

- Сенсорные жесты (shake, наклон устройства) — отдельная платформенная возможность.
- Собственный Wayland/X11 бэкенд — пересмотр по результатам проверок соответствия.
- Встраивание платформенных view (`cancelsTouchesInView`, M2-A11).

## Приёмка

Требование закрыто, когда его поведение закреплено тестом через публичный API, который падает с откатом
изменения; нативный путь, не исполненный на этом хосте, помечен так в PR и в `tasks.md`.
