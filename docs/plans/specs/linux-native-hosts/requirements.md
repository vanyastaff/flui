# linux-native-hosts — требования

- **Статус:** черновик, ждёт утверждения владельцем
- **Дата:** 2026-11-03
- **База:** `main` @ `57495bdf1`
- **ADR:** [ADR-0151](../../../adr/ADR-0151-platform-layer-boundary-and-names.md) §11 («Native
  Linux, then winit goes») и §15 (AT-SPI приходит с хостом Linux),
  [ADR-0082](../../../adr/ADR-0082-flui-app-sole-core-host-dependent.md) §5 (строка Linux),
  [ADR-0286](../../../adr/ADR-0286-window-chrome-regions-answer-the-system-hit-test.md) §9–§11
  (рамка окна приложения)
- **Дизайн:** [design.md](design.md); задачи — [tasks.md](tasks.md)

## Зачем

Решение уже принято: ADR-0151 §11 требует, чтобы приложения Linux шли через нативные хосты
Wayland и X11, а winit был удалён, как только нативный хост работает. Сегодня `flui-app` на Linux
включает `flui-native/winit-backend`, и `choose_linux_host` выбирает winit всегда, когда он
собран. Поэтому вся нативная работа (ввод, IME, буфер обмена, drag and drop, AT-SPI, рамка окна)
до пользователя не доходит, а каждая возможность Linux делается дважды: для winit и для
нативного хоста.

Нового ADR нет и флага отката на winit нет: FLUI до первого выпуска, совместимость сохранять
не для кого (решение владельца 2026-10-20), а флаг противоречит ADR-0151 §11.

## Требования

- **R1. Выбор хоста по сеансу.** Приложение `flui-app` на Linux открывает окна через нативный
  хост: в сеансе Wayland через Wayland, в сеансе X11 через X11, в сеансе Wayland с Xwayland и
  собранным одним X11 через X11. Пользователь, которому нужен X11 в сеансе Wayland, снимает
  `WAYLAND_DISPLAY`, как для любого клиента; нового переключателя нет.
- **R2. Отказ запуска типизирован.** Нет дисплея, нужный хост не собран, задан только
  `WAYLAND_SOCKET`: запуск возвращает ошибку с причиной, как `choose_linux_host` делает сейчас.
  Тихого перехода на другой хост нет.
- **R3. Ничего не теряется относительно winit.** Каждая строка `docs/platform-parity.md`, которую
  на Linux сейчас даёт winit, на нативном хосте есть не хуже, или её потеря названа в
  `docs/gaps.md` и согласована с владельцем до переключения. Список строк и состояние нативных
  хостов — в [design.md](design.md), раздел «Сверка с winit».
- **R4. Переключение проверено запуском.** До переключения `flui-app` проходит на CI
  сквозной запуск на нативном Wayland (Weston) и на нативном X11 (Xvfb): окно открывается,
  первый кадр показан, окно закрывается, процесс выходит с кодом 0. Отсутствие композитора или
  X-сервера при `FLUI_REQUIRE_WAYLAND` — провал, не пропуск.
- **R5. Тесты Linux идут через нативные хосты.** Наборы, которые сейчас поднимают winit на
  Linux (`linux_preferences`, профиль X11 в `backend_conformance`), переходят на нативные
  хосты и проверяют то же.
- **R6. winit удалён целиком.** После переключения в рабочем пространстве нет зависимостей
  `winit`, `ui-events-winit` и `arboard`, нет функции `winit-backend`, условия `winit_host`,
  модулей `*/winit.rs`, записей winit в списках `xtask` (`globals`, `reach`, `send-impls`,
  `panic-boundary`, `module_dag`) и записанных трасс `winit_*`. Списки разрешений только
  сокращаются.
- **R7. Документы описывают нативные хосты.** Столбцы Wayland и X11 в
  `docs/platform-parity.md` описывают нативные хосты; отметка ✅ ставится только после запуска
  на этой платформе. `docs/gaps.md` (записи 5, 8, 9, 10), `crates/flui-native/ARCHITECTURE.md`,
  `docs/crates.md` и записи ADR (ADR-0151 §11 и §15, ADR-0082 §5, ADR-0286 §9) приведены к
  коду.

## Вне объёма

- Новые возможности, которых не было и в winit: жест удержания тачпада, `xdg_popup` и окна-
  владельцы, передача буфера обмена менеджеру при выходе на X11, запуск под GNOME, KDE и
  Hyprland. Они остаются в `docs/gaps.md`.
- Windows и macOS: winit там не используется приложениями, его удаление их не меняет.
