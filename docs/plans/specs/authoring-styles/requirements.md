# Стили описания виджетов — требования (уровень 1)

- **Статус:** черновик; решения владельца 2026-10-05 внесены
- **Дата:** 2026-10-05
- **База:** `main` @ `4915054c8`
- **Уровень 0:** [../release/requirements.md](../release/requirements.md) R18, D3, D5
- **Связанные:** [../send-flip/requirements.md](../send-flip/requirements.md) (event-callback
  `Fn(&mut EventCx<'_>) -> R`, `!Send`-захваты); [../dx/research.md](../dx/research.md) P1–P4,
  P8, P14, P17; `docs/FOUNDATIONS.md` C2, C3; ADR-0086, ADR-0088; RFC 3681.

## Зачем

Описание дерева — самая частая поверхность (FOUNDATIONS C3: метрика принятия). Сегодня есть
только `new()` с setter'ами, а `column!` собирает лишь кортеж, отсюда `Column::new(column![…])`
(два имени на узел, DX P1). Форма фиксируется до 0.2.0: потом каждое изменение её ломает.

## Решения спеки

- **Р1 (владелец, 2026-10-05).** В 0.2.0 два стиля. **Builder:** `Column::new(…)` и setter'ы
  `fn x(mut self, …) -> Self`, без `.build()`; обязательные параметры позиционные в `new`.
  **Макрос-выражение:** `column![a, b]` возвращает сам виджет, свойства задаются вызовами
  setter'ов после него (`column![…].spacing(8.0)`); внутри только выражения через запятую, без
  `;` и без DSL `поле: значение`.
- **Р2 (владелец).** Struct-литерал (`Text { data: "x".into(), .. }`) добавляется позже, без
  ломки, когда стабилизируют `default_field_values` (rust-lang/rust#132162; трекер открыт на
  2026-10-04; на rustc 1.99.0 — E0658, проверено координатором). Поэтому уже сейчас поля
  приватны, а умолчания объявлены в одном месте, откуда генератор потом выпустит `поле: T = …`.
  **Ограничение (RFC 3681, «Privacy interactions»):** литерал с приватными полями запрещён даже
  при умолчаниях, так что включение литерала сделает поля `pub`, а их имена и типы — контрактом.
  Поэтому параметры виджета плоские и названы как setter'ы (R21); см. вопрос 1.
- **Р3.** Предел в 16 детей в макросе снимается механически: макрос вкладывает кортежи.
- **Р4.** Генератор — свой derive в `flui-macros`, реэкспорт через `flui-sdk`; без typestate (`bon`).
- **Р5.** Макрос есть только у контейнеров с несколькими детьми (`Column`, `Row`, `Flex`,
  `Stack`, `ListBody` и подобные); у листьев и виджетов с одним ребёнком — только `new`.
  R18 уровня 0 («три стиля у каждого виджета») надо переформулировать под Р1, Р2 и Р5.

## Пользовательский сценарий

Экран «счётчик заметок»; `count: Signal<u32>` (`!Send`) захвачен без обёрток.
```rust
// Builder — компилируется сегодня
Column::new((
    Text::new(format!("Заметок: {}", count.get(ctx))),
    Padding::new(EdgeInsets::all(8.0)).child(
        RawButton::new(Text::new("Добавить")).on_press(move |cx| count.update(cx, |n| *n += 1)),
    ),
))
.main_axis_alignment(MainAxisAlignment::Center)
// Макрос — цель 0.2.0 (column! возвращает Column)
column![
    Text::new(format!("Заметок: {}", count.get(ctx))),
    Padding::new(EdgeInsets::all(8.0)).child(
        RawButton::new(Text::new("Добавить")).on_press(move |cx| count.update(cx, |n| *n += 1)),
    ),
]
.main_axis_alignment(MainAxisAlignment::Center)
// После стабилизации default_field_values — не в 0.2.0, форма полей иллюстративна
Column {
    main_axis_alignment: MainAxisAlignment::Center,
    children: (
        Text { data: "Заметки".into(), .. },
        RawButton { child: Text::new("Добавить").into(), on_press: callback(move |cx| count.update(cx, |n| *n += 1)).into(), .. },
    ),
    ..
}
```

## Текущее состояние

**Каталог** (`rg` по `impl … View for`, `impl_*_view!`, derive `StatelessView`/`StatefulView`,
затем `pub struct`): **179** публичных виджетов — `flui-widgets` 130 (+24 непубличных),
`flui-material` 42 (+2), `flui-cupertino` 7; у facade своих нет. **Ни у одного нет `pub` полей.**
У каждого есть `new`: без аргументов (`Center::new()`, `crates/flui-widgets/src/layout/center.rs:20`)
или с обязательными позиционными (`Text::new(data)`, `text/text.rs:35`; `Padding::new(padding)`,
`layout/padding.rs:28`; `SizedBox::new(w, h)`, `layout/sized_box.rs:23`). Setter'ы
`mut self -> Self` (410 в `flui-widgets`), без `.build()`. Один ребёнок: `Child`
(61; `crates/flui-view/src/child/child.rs:33`) или `BoxedView` (37), через `.child(impl IntoView)`.
Много детей: `C: ViewSeq` у `Column`, `Row`, `Flex`, `ListBody`, `Stack` (`flex/flex.rs:246`:
приватные `style: FlexStyle, children: C` — параметры не плоские; `stack/stack.rs:23`).
Generic-виджетов 11. Callback-поля у 23 виджетов `flui-widgets` и 21 material; setter
`F: Fn(&mut EventCx<'_>) -> R + 'static, R: EventOutcome` (`gesture_detector.rs:238`,
`packages/flui-material/src/elevated_button.rs:67`). Ключ: только метод `View::key`
(`crates/flui-view/src/view/view.rs:188`), обёртки «ключ для любого ребёнка» нет.

**Дети и макросы.** `ViewSeq` реализован для `()`, кортежей `0..=16` (`crates/flui-view/src/seq/tuple_impls.rs:23`,
`:63`) и `Vec<V>` (`seq/vec_impls.rs:20`); `View for Option<V>` нет, ветки `if` требуют
`.boxed()` (`examples/two_screens/tree.rs:204`; DX P4). `column!`/`row!`
(`crates/flui-view/src/macros/mod.rs:42`, `:159`) строят кортеж; на 17+ — `compile_error!`
(`:138-149`), фикстура `crates/flui-view/tests/ui/column_17_compile_error.rs`. Документация
модуля показывает некомпилируемый `Column { children: column![…] }` (`:10-12`) в блоке `text`;
метка `FR-034` вынесена в карточки `release/tasks.md`. `flui-macros` даёт derive
`StatelessView`, `StatefulView`, `InheritedData`, `Diagnosticable`, `Animatable`, `Routable`
(`crates/flui-macros/src/lib.rs:110-324`) — генератора стилей нет. Closure через `let` не
получает сигнатуру `cx` (E0631, `crates/flui-view/tests/ui/let_bound_event_closure_without_helper.rs`;
DX P8), нужен `callback(…)`.

**Места вызова.** `Column::new(column![…])` в Notes (`examples/two_screens/tree.rs:191`, `:249`,
`:269`, `:353`), `examples/counter.rs:53`, book (`book/src/widgets/catalog.md:43`); `column![`/`row![`
— 49 вхождений в `.rs`. `docs/FOUNDATIONS.md:103` и `crates/flui-widgets/src/lib.rs:32` описывают
`bon`-builder'ы, которых нет ни в одном манифесте.

### Предыдущая реализация (до переписывания)

Старый `crates/flui_widgets` (удалён в `16ca09544`, 2026-02-08), файл
`git show 4a204b489:crates/flui_widgets/src/layout/column.rs`: три стиля в документации
(`:8-32`: литерал с `..Default::default()`, `Column::builder()….build()`, `column! { поле: значение }`);
`#[derive(bon::Builder)]`, все поля `pub`, умолчания в `#[builder(default = …)]` (`:66-104`); setter
детей скрыт ради ручного `where S::Children: IsUnset` (`:78-79`, `:118-129`); `build()` ради
`validate()` с `tracing::warn!` (`:131-145`); макрос раскрывается в builder, дети — `Vec` (`:262-290`).

`570ca7606` («Resolve bon builder conflicts for Child/Children API», 2025-11-20): typestate
конфликтовал с ручными `child()`/`children()`; в `Row`, `Stack`, `IndexedStack` добавлен
мутирующий `child(&mut self, …)` рядом с устаревшим `set_children`.

**Работало:** одно место для полей и умолчаний; читаемый литерал. **Мешало:** `.build()`;
typestate против своих setter'ов; `Default` делал всё необязательным; только `Vec`-дети с
боксингом; проверки в рантайме; ошибки внутри раскрытия; DSL `поле: значение` вне rustfmt.
**Почему удалено:** не задокументировано (тело `16ca09544` пустое, соседние коммиты причин не
называют). **Цель сохраняет:** от старой — одно место определения и путь к литералу; от
сегодняшней — обязательные позиционные параметры, типизированные дети без боксинга, setter'ы
без `.build()`, вывод `cx` в inline-closure.

## Требования

Один тест на требование (вид в скобках); таблица — строка на виджет, форму или стиль; стили по Р5.

- **R1a.** КОГДА виджет facade или официального пакета публичен, СИСТЕМА ДОЛЖНА иметь строку
  реестра с его доступными стилями; таблица сверяет реестр с публичными типами (consumer-тест).
- **R1b.** КОГДА у виджета есть стиль, СИСТЕМА ДОЛЖНА получать его код от генератора. Проверка:
  проверка падает на виджете с рукописным `new`/setter'ом/макросом вне генератора (тест-проверка).
- **R2.** КОГДА содержимое записано builder'ом и макросом, СИСТЕМА ДОЛЖНА строить одинаковые
  деревья элементов, render-объектов и semantics. Проверка: таблица по контейнерам, сравнение
  дампов после кадра в `flui-testing` (consumer-тест).
- **R3.** КОГДА обязательный параметр не передан в `new`, СИСТЕМА ДОЛЖНА отказывать при
  компиляции, указывая на вызов пользователя и называя функцию и недостающий аргумент.
  Проверка: фикстура `Text::new()` с `.stderr` (trybuild).
- **R4.** КОГДА необязательный параметр не задан, СИСТЕМА ДОЛЖНА подставлять умолчание,
  объявленное в одном месте и указанное в rustdoc параметра. Проверка: одна таблица на крейт
  (умолчание виджета равно документированному) + rustdoc-JSON проверка, что у каждого
  необязательного параметра описано умолчание (consumer-тест + rustdoc-JSON).
- **R5.** КОГДА макросу контейнера передано любое число детей, СИСТЕМА ДОЛЖНА компилировать
  вызов; builder принимает кортеж до 16 и сверх того отсылает к макросу в диагностике.
  Проверка: `column_17_compile_error` становится pass-фикстурой с 17 и 64 разнотипными детьми;
  фикстура кортежа из 17 в `Column::new` с `.stderr` (trybuild).
- **R6.** КОГДА число разнотипных детей известно статически, СИСТЕМА ДОЛЖНА сохранять их
  конкретные типы без боксинга в обоих стилях и принимать `Vec<BoxedView>`/итератор. Проверка:
  утверждение типа результата `Column<(Text, Padding)>` и вызов с `Vec` (consumer-тест).
- **R7.** КОГДА ребёнок условный — `Option<V>`, ветки `if/else`/`match` разных типов,
  итератор, — СИСТЕМА ДОЛЖНА принимать его в каждом стиле без `.boxed()` и без боксинга
  статически известных соседей (DX P4). Проверка: одна таблица, строка на форму × стиль,
  дамп дерева при обеих ветках (consumer-тест).
- **R8.** КОГДА у виджета один ребёнок, СИСТЕМА ДОЛЖНА сохранять сегодняшнюю обязательность:
  необязательный опускается, обязательный — позиционный в `new`. Проверка: таблица по реестру
  сверяет обязательность с сигнатурой `new` (rustdoc-JSON).
- **R9.** КОГДА ребёнок не `IntoView` или значение свойства не того типа, СИСТЕМА ДОЛЖНА
  указывать span на выражение пользователя и называть требуемый трейт/тип, без
  сгенерированных типов в первой строке. Проверка: фикстуры «ребёнок-не-View» в builder и
  макросе, «`spacing("8")`» в обоих стилях (trybuild).
- **R10.** КОГДА callback задан в любом стиле, СИСТЕМА ДОЛЖНА принимать
  `Fn(&mut EventCx<'_>) -> R, R: EventOutcome` с захватом `!Send` (`Signal`, `Rc`). Проверка:
  таблица стиль × захват (consumer-тест).
- **R11.** КОГДА closure записано как `|cx| …`, `|| …` или связано через `let`, СИСТЕМА ДОЛЖНА
  принимать или отвергать каждую форму по документированному правилу; отвергнутая форма даёт
  ошибку, называющую `callback(…)` (DX P8). Проверка: фикстура на форму (trybuild).
- **R12.** КОГДА виджет хранит callback, СИСТЕМА ДОЛЖНА держать тип хранения приватным во всех
  стилях (будущий литерал — через непрозрачный публичный тип), сохраняя свободу send-flip и D5.
  Проверка: в публичных сигнатурах и полях нет `Box<dyn Fn…>`/`Arc<dyn Fn…>` (rustdoc-JSON).
- **R13.** КОГДА генерируется код стиля, СИСТЕМА НЕ ДОЛЖНА добавлять `Send`/`Sync` к полям, детям
  и callback'ам; виджет с `!Send` полем на `flui-sdk` в доступных стилях (consumer-тест).
- **R14.** КОГДА пишется generic-виджет (`Column<C>`, `Stack<C>`), СИСТЕМА ДОЛЖНА выводить его
  параметры без аннотаций, как сегодня; generic-строки реестра без turbofish (consumer-тест).
- **R15.** КОГДА setter вызван повторно, СИСТЕМА ДОЛЖНА применять последний вызов; одному
  параметру соответствует один setter, а у макроса нет setter'а детей, так что конфликт
  `child`/`children` непредставим. Проверка: consumer-тест «последний побеждает» + фикстура
  `column![a].child(b)` и неизвестного setter'а с E0599 на имени метода (consumer + trybuild).
- **R16.** КОГДА в макрос передан не список выражений (`;`, `поле: значение`, пусто после
  запятой дважды), СИСТЕМА ДОЛЖНА указывать на ошибочный токен и показывать ожидаемую форму.
  Проверка: фикстура на случай (trybuild).
- **R17.** КОГДА код использует любую форму макроса, СИСТЕМА ДОЛЖНА форматироваться
  стабильным rustfmt. Проверка: фикстура форм прогоняется rustfmt дважды, второй прогон ничего
  не меняет, первый не оставляет вызов нетронутым из-за несовместимого синтаксиса (тест-проверка).
- **R18.** КОГДА дерево вложено на 4 уровня, СИСТЕМА ДОЛЖНА давать читаемую запись в каждом
  стиле: эталон после rustfmt компилируется и строит одно дерево (consumer-тест).
- **R19.** КОГДА к любому ребёнку прикреплён ключ в любом стиле, СИСТЕМА ДОЛЖНА сохранять
  состояние ребёнка при перестановке. Проверка: перестановка двух `StatefulView` с ключами,
  счётчик сохраняется, по строке на стиль (consumer-тест).
- **R20.** КОГДА в виджет добавлено необязательное поле в 0.x, СИСТЕМА ДОЛЖНА компилировать
  существующие вызовы builder'а и макроса без изменений. Проверка: fixture-крейт собирается
  против версии с добавленным параметром (consumer-тест).
- **R21.** КОГДА определяется виджет, СИСТЕМА ДОЛЖНА описывать его параметры плоско (один
  setter — один параметр с тем же именем, типом и умолчанием), чтобы генератор мог выпустить
  литерал (Р2). Проверка: rustdoc-JSON сверяет setter'ы с перечнем параметров генератора;
  nightly-фикстура с `#![feature(default_field_values)]` собирает литерал для строк реестра
  (rustdoc-JSON + пункт release-чеклиста).
- **R22.** КОГДА собирается каталог и Notes, СИСТЕМА ДОЛЖНА укладываться относительно базы:
  `cargo build --timings -j1` для `flui-widgets` и `flui-material` — не более +15 %;
  пересборка после правки одной строки в `examples/two_screens/tree.rs` — не более +10 %;
  release-бинарь Notes — не более +3 %. Медиана 5 прогонов на тихой машине (замер).
- **R23.** КОГДА открыт rustdoc виджета, СИСТЕМА ДОЛЖНА показывать на одной странице параметры
  с умолчаниями и обязательностью и пример каждого доступного стиля; сгенерированные служебные
  типы не видны в списке крейта. Проверка: rustdoc-JSON + doctest примеров (rustdoc-JSON + doc test).
- **R24.** КОГДА свойство задаётся у макроса, СИСТЕМА ДОЛЖНА раскрывать его в вызов метода на
  возвращённом виджете, чтобы rust-analyzer дополнял его как метод; проверка раскрытия
  (consumer-тест), LSP-скрипт — ручной пункт release-чеклиста.
- **R25.** КОГДА автор пакета на `flui-sdk` объявляет виджет, СИСТЕМА ДОЛЖНА давать ему те же
  стили тем же derive. Проверка: fixture-пакет только на `flui-sdk` + строка в
  `crates/flui-sdk/tests/surface.rs` (consumer-тест).
- **R26.** КОГДА пользователь обновляется, СИСТЕМА ДОЛЖНА описывать механическую замену
  `Column::new(column![…])` → `column![…]` во фрагменте `changelog.d/` (`cargo xtask changelog --check`).
- **R27.** КОГДА смержен переход, СИСТЕМА ДОЛЖНА иметь все места вызова в репозитории на новой
  форме: собираются examples, проходит `mdbook test` (consumer-тест).
- **R28.** КОГДА пользователь читает tutorial, СИСТЕМА ДОЛЖНА показывать в одной главе один
  экран в каждом доступном стиле; Notes пишется в одном домашнем стиле (builder + `column!`).
  Проверка: `mdbook test` главы (doc test).

## Вне scope

- Литерал в 0.2.0 (Р2); DSL вне Rust (`rsx!`, `.slint`); новые виджеты и их поведение,
  render-объекты, `CustomPainter`; параллельный кадр (D5; сохраняют его R12, R13).

## Открытые вопросы

1. **Литерал и semver (ADR к моменту стабилизации).** По RFC 3681 литерал требует `pub` полей;
   их имена и типы станут контрактом, а `Column` сегодня хранит `FlexStyle` не плоско. Плюс
   литерал без `..` ломается при добавлении поля — обещаем ли совместимость только для формы
   с `..`? `#[non_exhaustive]` с умолчаниями RFC не сочетает.
2. **Обязательность умолчаний для литерала.** Обязательный позиционный параметр `new` станет
   полем без умолчания; совпадёт ли порядок и имя с `new` (R21) для всех 179 виджетов?
3. **Граница «контейнер» (Р5) и ключ (R19).** Входят ли `Wrap`, `Table`, `Scaffold` со слотами;
   ключ — обёртка у любого `View` или параметр генератора (решает design.md)?
