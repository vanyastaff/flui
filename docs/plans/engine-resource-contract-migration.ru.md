# Контракт GPU-ресурсов engine: производственная миграция

Первое изменение ограничено flui-engine. Единственный rasterizer и allocator API — wgpu. Работающий `embedded_gpu_scene` является consumer публичного painter lifecycle; это не доказательство существования managed GpuView. Документ описывает целевой контракт и последовательность доставки. Admission/retirement и ordered IR уже реализованы; Engine-local descriptors, sampling/alpha и захваченные allocation leases реализованы; [проверки и границы](../research/engine-resource-contract-validation.ru.md) отделяют их от managed producer и остальных требований ниже.

## Предусловие первого immutable IR delivery

Минимальный admission и submission-retirement owner вводятся **до** отдельного immutable STORAGE buffer на segment, а не после IR PR. Иначе множество маленьких stop tables проходит per-binding limit, но исчерпывает CPU/GPU память. `GpuResources` резервирует checked GPU payload, staging и CPU peak recorder+sealed+conversion copies до роста Vec/Box и create_buffer_init; отдельные work/count caps ограничивают runs, stops, bindgroups и passes. Где возможно, fallible reserve; Rust allocator abort и driver process failure не объявляются восстановимыми.

Instance-owned `DeviceDomain` объединяет submit, diagnostics и retirement для managed painters на одном GPU. Это не process static: realm quotas и wake ownership раздельны, device-wide serial ordering и fault generation общие. Recorded→Submitted(serial)→Retired(completion) — один protocol. Opaque consuming `PreparedSubmission` включает command buffers, charges, domain owner, device epoch и target context; нельзя передать произвольный buffer и отдельно обещать reservation. Domain потребляет bundle, сам submit и регистрирует completion. Discard возвращает только unsubmitted reservations; `finish_frame`, drop CPU handle и wgpu safety retention **не** означают GPU completion.

Production clear/dispatcher/blur/mask/blit submissions тоже проходят Domain, не только final encoder. FrameState удерживает набор submitted serials: late failure retires уже отправленное и discards только неподанное. Whole known requirements preflight до первого submit; candidate/staging target с reserved double-buffer/copy bytes сохраняет committed image до успешного commit. «Не present» не восстанавливает retained target, если его уже изменил ранний pass. Target atomicity требует этих механизмов и tests late failure после intermediate submit.

Host pump доставляет completion и generation teardown; pending bytes/frames bounded. Admission отвечает typed Wait/Reject с durable wake obligation. Closing/Draining/Lost/Retired service принадлежит DeviceDomain и переживает последнее окно. Callback только отправляет generation/serial через weak/mailbox handle, не удерживает сильный Domain/Device цикл и не вызывает user Drop. Native progress использует bounded nonblocking poll; browser backend использует browser progress (Device::poll там no-op). PollError/loss переводят lifecycle явно. Closing deadline прекращает ожидание UI, **не** означает completion или освобождение VRAM; late callbacks старого epoch idempotent. Device loss освобождает ledger поколения после доказанной teardown, а не после одного timeout/destroy вызова.

Первый `PreparedIrBudget` — ограниченная quota новых IR allocations и CPU temporaries, **не whole-engine cap**. До общего ledger legacy exclusions перечисляются явно: image/cache uploads, texture pool/offscreen targets, glyph/image atlases, existing buffer/uniform pools и external allocations вне managed factory. Для них сохраняются имеющиеся quotas/telemetry, отсутствие общего transient cap признаётся. Полный cache/atlas/pool ledger расширяется отдельным delivery; только после inventory всех allocation sites можно объявить общий managed payload cap. Перенос categories не снимает и не дублирует allocation charge.

Baseline перед миграцией: alternating gradients, nested effects, cache churn и atlas pressure; CPU record/prepare/encode p50/p99, allocations/uploads, peak live+submitted payload и pass/bindgroup counts. Regression bounds выбираются по измерению, не выдумываются; per-segment allocation correctness не является performance proof.

Candidate/staging target и его copy work относятся к новым charged frame resources,
даже если используют существующий texture pool. Legacy offscreen exclusion не
освобождает их от reservation; budget category определяется operation ownership,
а не тем, какой allocator helper её создал.

## Реальные дефекты и первая атомарная реализация

`external_texture_registry.rs::register` создаёт bind group с выбранным sampler, но `replay/flush.rs::flush_segment_external_images` берёт только view и вызывает flush с default linear sampler. `update` дополнительно безусловно выбирает linear. `batches/images.rs::draw_texture` игнорирует `_filter_quality`, хотя public painter обещает управление sampler. Все external samples идут через straight-alpha pipeline. Premultiplied кадр камеры/producer с alpha 0.5 получает повторное умножение RGB; неизвестная alpha policy не диагностируется.

Первый commit должен одновременно исправить эти пути, а не только добавить metadata:

- В registry ввести descriptor с sampling и `ExternalAlpha::{Opaque,Straight,Premultiplied}`; unknown не принимать. Первое color значение — явно encoded sRGB текущего pipeline; другие кодировки отвечают Unsupported до появления согласованного working color path.
- Registration/update возвращают Result и валидируют descriptor перед созданием view/bind group. Размер брать из texture, не из двух независимых доверенных чисел. Проверять D2, одну array layer, sample_count=1, поддерживаемый format/view, TEXTURE_BINDING, filterability и sampler compatibility. Для первого изменения ограничить format поддержанным colour subset; compressed/depth/integer/многоплоскостной texture не выдавать за RGBA.
- Устранить две конкурирующие sampling promises. Public per-draw FilterQuality остаётся authoritative; None → nearest, Low/Medium/High → linear с документированной текущей эквивалентностью (нет обещания mip/anisotropy). Registry descriptor задаёт default только для API draw, явно выбирающего resource sampling. Не делать молчаливый override descriptor. Если новый режим UseResource требует cross-crate изменения FilterQuality, сначала engine-local `ExternalSampling` draw entry point с реально подключённым consumer, затем ADR и единая vocabulary. Старый bool register удалить/мигрировать, не оставлять неиспользуемый selector.
- Command IR хранит effective sampling для draw; replay binding использует выбранный sampler, а не default. Update сохраняет descriptor. Нельзя использовать старый registry bind group напрямую: его bindings сейчас texture=0/sampler=1, replay layout sampler=0/texture=1. Создать bind group с правильным replay layout и кэшировать по allocation generation + sampling; удалить дублирующий неиспользуемый layout/bind group registry.
- Straight применяет обычный pipeline. Premultiplied использует существующий premul pipeline и tint `[opacity,opacity,opacity,opacity]`, иначе RGB не получает group opacity. Opaque обозначает гарантию producer alpha=1, проверка содержимого GPU не производится. Не объявлять raw imported handle pixel validation.
- Reject update полностью сохраняет старую texture/view/descriptor и способность следующего draw. Не оставлять debug_assert как единственную проверку. Реальная wgpu validation остаётся последним рубежом, а не заменой CPU admission.

Файлы первого commit: `external_texture_registry.rs`, `painter/{mod,draw}.rs`, `batches/images.rs`, `command_ir.rs`, `replay/flush.rs`, при необходимости `error.rs`, `lib.rs` export и `ARCHITECTURE.md`. Публичный registry сейчас доступен через painter несмотря на private module: descriptor/error types требуется нормально re-export, без hidden unnameable API. Внешний example в отдельном reviewable consumer commit использует новый descriptor. API breaking допустим до1.0; changelog фиксирует его.

## Следующее обязательное изменение: allocation identity и leases

Нынешний IR хранит bare TextureId и разрешает его в replay. Record A → unregister A → register B тем же id → flush показывает B. Record cropped A → update другой allocation → flush может сочетать старые UV с новой texture. Простое Arc<TextureView> в replay слишком поздно.

В engine-local lowered IR удерживать strong `ExternalAllocationLease`, захваченный во время recording/lowering. Это snapshot allocation **lowered frame**, не Scene construction: Scene A→rebind B→lowering намеренно разрешает B; после lowering rebind не подменяет captured allocation. Внутренний ключ включает registry owner, allocation generation и device generation. Register не заменяет живую identity молча; replacement создаёт новое generation. Unregister закрывает новые lookups, старые recorded leases переходят в discard либо submission ownership. Texture/view/sampler/descriptor immutable в allocation. Gpu-free Scene IR выше engine не получает wgpu handles. Runs принадлежат одному immutable target context (extent, origin, viewport epoch); merge key включает effective sampler/alpha, allocation generation и table identity, не приблизительное matrix equality.

Allocation freeze **не** замораживает texels. Policy `LatestAtOrderedSubmission` допускает изменение той же texture до draw и задаёт один owner ordering producer passes/queue writes; две CPU writes перед одним submit не создают два pixel snapshots. Snapshot pixels — отдельный explicit copied snapshot или новая allocation с dependency edges и reserved bytes. Ordered producer pass без сохранения результата сам по себе snapshot не гарантирует. Content revision отлична от allocation generation: producer commit сообщает revision и invalidates dependent output regions, будит соответствующий realm. Консервативный первый consumer может full-repaint volatile resource, но wake всё равно обязателен; unchanged Scene и retained NoDamage не должны скрывать video update. При смене device старый lease не допускается в новый encoder, возвращается DeviceGenerationMismatch; producer recreates/reimports ресурс.

Managed factory привязывает устройство и admission до create_texture, выдаёт constrained operation capability без raw Device/Queue, Deref к ним или destroy authority. `&Device`/`&Queue` тоже raw authority: их можно clone; Device::destroy имеет receiver &self. Scoped lifetime над reference этого не устраняет. Managed operations проверяют Domain/epoch и submit только через consuming PreparedSubmission. Trusted raw Device/Queue/import — отдельная честно названная граница: caller может сохранить clone, destroy или concurrent submit вне Domain; это не получает managed order/cap/isolation guarantee. Сырая wgpu Texture не даёт engine надёжного публичного способа проверить device identity; owner token — assertion caller, не доказательство. Raw caller гарантирует same device, supported usage и отсутствие destroy в admitted lifetime; wgpu validation остаётся последним рубежом. Imported allocation создана до admission: cap не распространяется на чужие allocations/clones, memory/content immutability и recovery raw misuse не обещаются как managed safety.

Изменение TextureId/DrawOp/Scene ownership и host-managed registration требует нового Proposed ADR с `Supersedes` точных accepted sections ADR-0006/других договоров и `Superseded-by` в старых ADR; accepted решение нельзя молча переписывать. Private engine clarification, сохраняющий accepted invariant, может быть Mapping decision. Proposed части ADR-0098 можно уточнять до acceptance. Engine-local lease допустим первым: он закрепляет именно GPU lowering frame. Scene replay с прежним logical id через несколько кадров требует отдельного cross-crate generation contract.

## Admission и учёт ресурсов

Целевой DeviceDomain ledger: live allocations + free pool inventory + caches + frame leases/submitted retirement; `GpuResources` одного painter не создаёт независимый общий cap на shared Device. Domain считает allocation один раз независимо от view/Arc clones и painter, realm quota относится к её admission/retention ownership по явной policy. Imported allocation учитывается отдельно как admitted external bytes с оговоркой внешнего ownership. Pool return — перенос категории, не уменьшение live reservation; только actual retirement освобождает capacity. Budget consumption зарезервирован до GPU allocation, queue upload, CPU decode/raster/tessellation; rollback возвращает reservation после каждого отказа. Пока действует только PreparedIrBudget, перечисленные legacy exclusions не скрываются под формулировкой «единый cap».

Не заменять byte budget количеством textures: `texture_pool` сейчас ограничивает available count, `texture_cache` и `buffer_pool` имеют собственные end-frame eviction policies, которые не ограничивают transient пик. Общий ledger начинается с immutable IR allocations и submission retirement, включает external/pool allocations, затем cache/atlas/buffers. Estimate считает mip levels, layers, samples и block-rounded dimensions checked arithmetic; неизвестную bytes-per-format нельзя считать четырьмя байтами. Это conservative payload budget, не обещание точного driver VRAM.

Managed create/upload validates dimensions, device limits, format usage, row stride и checked input bounds до wgpu вызова. Import уже созданной texture может лишь отказать **после чужой allocation**; не называть это pre-allocation admission. Decode limits принадлежат IO/assets ingress; engine проверяет decoded dimensions/bytes до upload и сообщает бюджет host. CPU работы получают отдельные лимиты (glyphs, path complexity, effect depth, passes), потому что небольшой pixel buffer не ограничивает shader compilation или recursive work. Mature crates выполняют механизмы decode/packing; FLUI задаёт owner policy.

Frame failure сообщает typed ResourceError с operation/required/available, не presents частично подготовленный кадр. Не прятать missing lease warning+skip как успешную presentation. Сохранённый last completed target может быть показан согласно existing PresentDisposition; next valid frame должен реально продвигаться. Выбирать fallback/mapping явно на host boundary. Полная frame atomicity требует проверки FrameProtocol и discard obligations, а не одного return Result в registry.

DeviceDomain — единственный diagnostics owner устройства, с generation fault mailbox и bounded retention. Нынешний `renderer.rs::install_device_diagnostics` только логирует uncaptured error; это не подтверждение успешного кадра. Wgpu30 ErrorScopeGuard thread-local и !Send/!Sync при std: owned operation batch push нужные scopes на своём thread, явно pop в reverse order даже при early Err/unwind boundary, только затем передаёт popped futures в bounded edge resolver с generation/operation id. Drop guard без pop теряет captured errors, поэтому не является cleanup policy. Secondary captured diagnostic не заменяет известный first failure. Other-thread raw operations не приписываются scope render thread; delayed/unattributed errors маркируют generation/outcome uncertain. Accepted submit, completed GPU work и displayed scanout разные acknowledgments. Host polling/recovery живёт на edge; frame path остаётся синхронным.

Rollback ledger/lease Drops infallible и idempotent, не вызывают user callbacks. Первый failure authoritative; вторичные callback/Drop faults диагностируются в controlled boundary согласно panic policy. Prepared/Submitted/Discarded состояния исключают double release. Не обещать containment panic=abort, double unwind или allocator/driver abort. Cooperative task cancellation требует bounded steps/checkpoints, deadlines и concurrency caps; Stop не отменяет submitted GPU job и не освобождает его reservation. Stale generation results rejected при publication, completion всё равно доводит retirement.

Source color intent и linear working transition — разные reviewable deliveries: сначала typed metadata и explicit named legacy SDR conversion, затем единый source→linear premul→effects→encode без mixed pipeline внутри кадра. Descriptor conversion/caches должны учитывать metadata generation; effect matrix domain и advanced blend space фиксируются до working transition. Нельзя clipping/byte conversion выдавать за сохранение HDR intent.

## Приёмка: ошибки, конкуренция и следующий кадр

GPU tests входят в существующую engine readback family и single-threaded group; public consumer tests registry/painter API, private seam только для искусственного admission failure. Не создавать ещё один cargo test binary.

| Сценарий | Отличающее доказательство |
|---|---|
| 2×1 красный/синий, масштабирование nearest/linear | Несколько внутренних sample points дают чистые texels против смешанных; register, draw override и update проверяются независимо |
| Premul `[0.5,0,0,0.5]` на чёрном, opacity1/0.5 | RGB≈0.5/0.25; сломанный straight pipeline≈0.25/0.125; не oracle из того же helper |
| Unsupported alpha/color/format/usage/размер | Typed отказ до engine view/bindgroup/managed allocation; прежняя запись остаётся drawable |
| Record A, unregister/rebind id B, flush | Первый frame показывает leased A, следующий явный B; missing future lookup сообщает ошибку |
| Record cropped A, incompatible replacement | Update rejected; crop и sampling A сохранены в release profile тоже |
| Content writes в ту же allocation | Тест отдельно подтверждает documented latest texels; snapshot не заявлен |
| Device-generation mismatch | Старый lease rejected до encode, recreation новым owner рисуется следующим кадром |
| Budget fail, validation fail, затем valid frame | Счётчики/reservation не утекают, первый error authoritative; pair failures в обеих последовательностях |
| Drop/discard frame после записи | Leases retired без unregister side effects; следующий request помещается в budget |
| Pool return/cache eviction/submission overlap | Один allocation учтён один раз, free pool всё ещё consumes budget, active lease не evicted |
| Scene создан A→rebind B→lower; затем seal→rebind C | Lowered frame показывает B, последующий lowering C; Scene snapshot A не заявлен |
| Raw clone.destroy после record / foreign device import | Отдельная trusted misuse failure; managed API destroy authority не выдаёт; no false successful frame |
| Quiescent unchanged Scene, red→green content commit | Revision invalidates region и wake приводит к green present; независимые realms не затронуты |
| Latest two writes / explicit copied snapshot | Latest видит последнее содержимое; copied snapshot сохраняет прежнее и consumes отдельный budget |
| Delayed completion, два in-flight frame, close/loss | Cap не освобождён finish_frame; callback/pump либо teardown возвращает capacity без утечки |
| Uncaptured delayed error / producer error плюс UI failure | Generation fault не превращается в успешный displayed ack; первый error сохранён и recovered frame продвигается |
| Reservation fail плюс callback/Drop fault | Infallible internal cleanup, no double release; каждый fault отдельно, pair chronology и next valid operation |
| CPU peak table/count cap / cancel during bounded work | Refusal до allocation, no unbounded intermediate copies; UI cancellation отдельно от worker/GPU completion |
| Failure после intermediate blur/clear submit | Submitted charges остаются до retirement, остаток discard; committed image неизменна, следующий valid frame работает |
| Два managed painters одного DeviceDomain | Один ordering/diagnostics ledger, отдельные realm quotas/wakes; нет двух независимых device caps |
| Last window close, PollError/loss, late completion | Domain service завершает lifecycle без Arc cycle; timeout не снимает charge; old epoch callback idempotent |
| Early Err с thread-local captured GPU error | Scopes explicitly popped на owner thread; primary error сохранён, secondary diagnostic доставлен edge resolver |
| Raw Device/Queue clone против managed operation API | Managed API не раскрывает raw authority; trusted raw mode не объявляет managed cap/order guarantee |
| PreparedIrBudget + legacy blur/cache/atlas workload | Quota новых IR соблюдена; legacy bytes показаны отдельно и не названы whole-engine cap |

Нужные команды после снятия общего compiler gate: `cargo nextest run -p flui-engine --features testing` с соответствующим family filter; `cargo run --example embedded_gpu_scene -- --capture`; `cargo xtask check-changed`. Фактический live producer smoke должен показать API migration, captured sampling/alpha cases и recovery. Он не доказывает будущий managed widget, video decoder или platform view integration.
