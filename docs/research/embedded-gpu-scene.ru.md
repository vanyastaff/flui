# GPU-содержимое внутри FLUI engine

`cargo run --example embedded_gpu_scene` открывает окно с вращающимся кубом.
Его геометрия проходит отдельный перспективный GPU-проход с `Depth32Float`:
скрытые грани разрешает проверка глубины. Цветовой результат хранится в
`Rgba8Unorm` с `RENDER_ATTACHMENT | TEXTURE_BINDING`. На том же устройстве
`WgpuPainter` получает текстуру через существующий реестр и рисует её между
прямоугольниками UI. Золотая передняя плашка перекрывает область куба; нижняя
полоса изменяется во времени вместе с ним. Ни чтение пикселей CPU, ни повторная
загрузка текстуры между этими проходами не используются.

Пример использует собственный winit-host, а не `run_app` и не `UiRealm`.
Это исполняемый пример GPU-композиции движка, а не готовый 3D widget framework,
не загрузчик моделей и не интеграция игрового движка. `Renderer` и callback
`run_direct` сегодня не передают внешний texture registry/device вызывающему.
Для managed widget-интеграции нужен отдельный ADR, связывающий renderer-owned
регистрацию, texture identity/lifetime, realm damage/wake и device recovery.
Просто экспортировать mutable painter из `Renderer` недостаточно: такой доступ
обходит frame ownership и не уведомляет damage tracker об обновлении пикселей.

`begin_frame` сбрасывает состояние painter до записи. `render_to_view` кодирует
рисование, допускает несколько flush одного кадра. После отправки последнего
encoder вызывается `finish_frame`: до этого момента uniform allocations и
используемые текстуры кадра не переиспользуются. При ошибке кодирования encoder
отбрасывается, затем кадр также завершается. Это тот же ресурсный контракт,
который внутренний `Renderer` уже выполняет своими приватными вызовами.

На suspend пример освобождает GPU/window resources, на resume создаёт их заново.
Нулевой размер останавливает redraw loop до resize. Surface Lost/Outdated
переустанавливает конфигурацию; постоянная ошибка завершает пример с диагностикой.
Автоматическое восстановление device loss здесь не заявляется. SDR-цвета заданы
encoded RGBA8, alpha куба — 0 либо 1; пример требует non-sRGB surface format,
чтобы не выдавать неявное преобразование цвета за реализованный HDR pipeline.

## Приёмка

1. `cargo check --example embedded_gpu_scene` проверяет публичный путь embedder.
2. На реальном GPU запустить пример и записать adapter/backend из stderr.
   При вращении задние грани не должны проступать; золотая UI-плашка остаётся
   поверх результата GPU-прохода, нижняя полоса движется.
3. Изменить размер, минимизировать и восстановить окно. При восстановлении
   изображение обновляется, вывод wgpu validation не появляется.
4. Закрыть окно: процесс завершается. Не считать удачную компиляцию или один
   статический кадр доказательством анимации и lifecycle.

Headless capture выполнен основным агентом на NVIDIA GeForce RTX 3070 Ti
через DX12: проверки глубины, двух углов, UI overlay и progress прошли;
сохранённый PNG также просмотрен визуально. Ручной оконный путь — анимация,
resize, minimize/restore и suspend/resume — пока не проверен. Golden/readback-сравнение нескольких фиксированных углов
будет полезным следующим тестом: sample points должны различать depth-enabled
результат и намеренно отключённую проверку глубины, а также порядок UI-overlay.

## Headless capture и проверка пикселей

`cargo run --example embedded_gpu_scene -- --capture <absolute PNG path>`
работает без окна и использует тот же `encode_frame`, что экранный путь.
Углы 0 и π/2 проверяют соответственно красную и жёлтую ближние грани в центре.
Красная грань записана раньше дальней голубой: этот sample отличает depth test
от простого порядка треугольников. Дополнительные samples проверяют переднюю
золотую плашку, движущуюся полосу и фон. PNG сохраняется только после успешных
проверок и содержит второй угол; texture registry освобождается явно.
Readback используется только диагностикой, не экранной композицией.
Основной агент выполнил capture на NVIDIA GeForce RTX 3070 Ti / DX12; все
аналитические проверки прошли, изображение просмотрено визуально. Ручной
оконный lifecycle остаётся непроверенным.
