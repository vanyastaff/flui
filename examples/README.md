# FLUI Examples

This directory holds the minimal "hello world", the hot-reload examples and the WASM demos. The
plain `examples/*.rs` files run with `cargo run --example <name>`; the rest are separate crates
or WASM targets with their own build step.

## Start Here

| Example | Run |
|---|---|
| **counter** — the minimal FLUI app: one `Signal` and a `RawButton` whose press writes it (start here — this is the README's own "Hello World" code sample, and the exact shape `flui create`'s `counter` template generates) | `cargo run --example counter` |
| **native_window** — the escape hatch from a widget: the view acquires its window as `flui::native::NativeWindowCapability` in `create_state`, and its buttons set the title bar colour and the backdrop through `win32()` on Windows, the level and the alpha through `appkit()` on macOS | `cargo run --example native_window --features native` |
| **two_windows** — a second window beside the first, each with its own UI runtime, both drawn by the one raster executor (ADR-0305); on Wayland the raster thread draws every window | `cargo run --example two_windows --features unstable-windows` |
| **navigation** — one typed `Router` under `MaterialApp::router`: a push, a page popped with a result, and a confirmation dialog, each reached from `build` through `Router::of(ctx)` and `PageHandle::of(ctx)` | `cargo run --example navigation --features material` |
| **notes** — the book's tutorial (`book/src/tutorial/`) list, pages and theme in one window: a `TextField` that adds a note, a keyed `ListView` of notes, a page per note that deletes it after an `AlertDialog` confirms, and a Material theme that follows the platform's brightness | `cargo run --example notes --features material` |

## Hot reload

| Example | Run |
|---|---|
| **desktop_scene** — hot-reloadable scene plugin for desktop (Windows/macOS/Linux) | two terminals, see below |
| **hot_reload_counter** — the counter template through `flui run`, which hot-reloads by default (host/logic/types split) | `cd examples/hot_reload_counter && flui run` |
| **hot_reload_lifecycle_fixture** | Dev-only `app_plugin!` fixture for `flui-hot-reload`'s own integration test — not meant to be run directly. |

**desktop_scene** is a `cdylib` plugin, not a binary — there is no `cargo run -p flui-desktop-scene`. It's built in one terminal and loaded by a separate host process in another (full workflow: [`docs/hot-reload.md`](../docs/hot-reload.md#desktop-plugin-workflow)):

```bash
# Terminal 1 — rebuild the plugin on change (needs cargo-watch)
cargo watch -w examples/desktop_scene -x "build -p flui-desktop-scene"

# Terminal 2 — run the host with in-process reload; it loads
# target/debug/libflui_scene.so (.dylib, flui_scene.dll) unless FLUI_SCENE_PLUGIN names another path
cargo run -p flui-hot-reload --features host-hook --example scene_render
```

## Web / WASM

| Example | Run |
|---|---|
| **web_demo** — Web/WASM platform demo | `cd examples/web_demo && wasm-pack build --target web --out-dir pkg`; serve `examples/web_demo/` over HTTP |
| **painting_demo** — Web/WASM `Canvas` painting demo | `cd examples/painting_demo && wasm-pack build --target web --out-dir pkg`; serve `examples/painting_demo/` over HTTP |

The `painting_demo` crate contains browser code only and targets
`wasm32-unknown-unknown`. It is an ordinary FLUI application on the `flui` facade: `run_app`
starts the web runner, which takes the page's `<canvas id="flui-canvas">`. The root is a
scrolling column of sections, each a `Text` title above a `CustomPaint` whose `CustomPainter`
draws that section's geometry at the size it is given, with its captions as `Text` widgets under
or beside it. Native workspace checks compile an empty cdylib; they do not exercise the browser
demo.

## Android

An Android app is a project generated by `flui create`. From its directory, `flui build android`
builds the APK and `flui run --device <id>` (ids from `flui devices`) installs and starts it; see
`crates/flui-cli/README.md`.

## Building examples

```bash
cargo build --examples          # everything that doesn't need a feature
cargo run --example             # list every example target (the per-target crates are packages)
cargo run --example <name>      # run one by name
```
