# Spec: transactional, presentation-local frame failure containment (the remainder of #561)

- **Status:** Draft v3 (v3 folds in six corrections from the task decomposition — listed in `tasks.md` §Notes; approach A′ chosen at the gate on 2026-09-11 with three user answers — see `intent.md` §User amendments; v2 folds in three review findings on PR #1023: the geometry shadow cannot reproduce hit-test topology → held input; `Idle` never acknowledges the commit bit; seam (c) covers every removal-path hook)
- **Slug:** `561-transactional-frame-failure`   ·   **Date:** `2026-09-11`   ·   **Owner:** `chief-architect` (design), flui-view / flui-app / flui-rendering leads per PR
- **Governing ADR:** `docs/adr/ADR-0048-frame-transaction-boundary.md` — **amended**, not replaced (the intent says extend); ADR-0027 (presentation-local), ADR-0062 (the paint queue is the cross-pass record), ADR-0054 decision 2 (`GEOMETRY_DEGRADED` sticky stand-in flag)

## Problem

Carried over from `intent.md` ("What's wrong today", after its Corrections): a frame that fails part-way is contained to its presentation and reported, but what it leaves behind is not one version. Concretely, at main `3b8bb79c`:

1. **Build side (flui-view).** A user `build()` panic is already contained per element (`behavior_commons::build_or_recover` → `ErrorView`, Flutter's `performRebuild` first catch). Every other user hook is not: `init_state` / `did_change_dependencies` run in the *child's* phase-1 drain iteration, whose `Err` arm restores the slot, re-pushes the dirty entry and `resume_unwind`s (`build_owner.rs::drain_build_scope`; pinned as propagation by `tests/inherited_dependency.rs::init_state_panic_leaves_the_slot_intact_not_a_hole`) — a deterministic `init_state` panic is a permanent retry storm. A panic inside the reconcile (`create_render_object` / `update_render_object` / `did_update_view` of a child) unwinds after `dirty_reasons.remove(&id)` and `core.clear_dirty()` ran and before `child_ids` is rewritten (`id_reconcile.rs` step 3): the parent keeps its OLD `child_ids` with freed ids while the render tree already holds the NEW render objects of elements no parent references — stranded shells paint, and the next rebuild inserts again, so ghosts accumulate. A user `dispose()` panic — the case ADR-0048 headlines — runs inline in the reconcile for unkeyed removals (`remove_finalized_inner` → `unmount` → `dispose`), after `registered_global_key.take()` and before the slot is freed. Flutter's `ComponentElement.performRebuild` has a **second** `try/catch` around `updateChild` that catches all of these; FLUI is below that floor.
2. **Retry (flui-app).** `draw_frame_for_presentation` takes the layer tree, then runs a tail (`service_child_requests`, `attach_performance_overlay`, scene). A panic in the tail drops the taken tree; `render_frame_with_sink` arms only `wake_frame()` on `Errored` (`retry_needs_repaint` deliberately false: "nothing was produced to submit" — false for this case); `run_paint` early-returns on an empty queue → the retry parks `Idle` with the screen at N-1 and the tree at N, forever. This is the root cause behind "mixed version on screen" once build is contained.
3. **Hit test (flui-app / flui-rendering).** Only the pump's ambient re-probe is gated on `any_failed` — pump-wide, so a *secondary* presentation's failure freezes the primary's hover. Pointer events between a failed frame and its retry hit-test the live tree; bounded ≤ `MAX_CONSECUTIVE_LAYOUT_FAILURES` (3) frames for retriable layout failures (structural ones poison on first occurrence), unbounded for a deterministic paint panic (paint has no poison budget — retry policy, outside this intent).
4. **Criterion 6 (flui-rendering tests).** `poison.rs` stands a poisoned node in with its last committed geometry, or `Size::ZERO`/`SliverGeometry::ZERO` if it never succeeded; ADR-0054's `GEOMETRY_DEGRADED` marks the parent. No test distinguishes the two; PR #1005's fixture passed with the poisoning step deleted (a cycle fixture poisoning the root, tight constraints, unchanged-constraints cache short-circuit).
5. **Report privacy (flui-app).** `FrameFailureKind::SegmentPanic.message` carries the panic text verbatim to the embedder's handler in every profile; `RenderError` payloads are static names/ids/counts by inspection. The on-screen `ErrorView` already withholds the message in release (`RenderErrorBox::paint` under `cfg!(debug_assertions)`) — Flutter parity; the typed report is the one channel without a profile split.

Semantics (a11y trails the screen only after a scene-submit failure, one pump) is **filed out** to the threaded-lane issue by the user's decision — see `intent.md` Corrections.

## Goals / Non-goals

**Goals**
- Every element-level mutation a user hook can abort is bounded at the child that hook belongs to; the frame never unwinds out of `build_scope` or `finalize_tree` from user code; no stranded render child survives a contained panic.
- A retry after any `Errored` outcome re-presents: the tree and the screen converge on the next pump.
- Pointer input is hit-tested only against a committed (presented) tree: while a presentation is between a failed frame and its retry its pointer events are held and replayed on commit; hover-class derivations are gated per presentation.
- A test distinguishes last-good retention from the zero stand-in and goes red when the poisoning step is deleted.
- The typed report is profile-aware; contained recoveries are reported with ownership identity and causal detail, without bumping the failure streak.

**Non-goals (explicitly out of scope)**
- Semantics candidate/validate/publish (filed with the threaded raster lane; `SemanticsOwner::flush` untouched).
- A paint poison budget or any retry-policy change (`intent.md` "Not this"); the secondary-realm handler wiring (blocked).
- Routing on the `BUG:` prefix — it classifies (`internal_invariant`), it never decides containment (PANIC-POLICY owns the prefix by convention only; flui-view is `#![forbid(unsafe_code)]`, so containing cannot produce UB).
- Changing what a successful frame produces; the on-screen `ErrorView`'s release behaviour (already parity).

## Approach — A′: per-child boundaries at the three real seams, one report drain, one commit bit, held input

### G1 — build-segment atomicity (flui-view)

**Invariant:** *a rebuild either commits a child or commits an `ErrorView` in that child's slot; a removal always frees the slot; the drain always reaches the step that rewrites `child_ids`.* Encoded as three boundaries, not a session catch:

- **Seam (a) — the phase-1 `Err(payload)` arm of `drain_build_scope`.** After `put_element`, the failing element is replaced **at its parent's slot**: `remove_subtree(id, Finalize)` then insert `ErrorView` at `(parent, slot)` through a new tree primitive `ElementTree::replace_child_with(parent, slot, view, owner)`. No re-push, no `resume_unwind`. A root element with no parent propagates (Flutter: `runApp` fatal). `StatefulBehavior::on_unmount` gates `dispose()` on `initialized`, so a `ViewState` whose `init_state` never completed is never disposed (Flutter effective parity: a throwing `initState` never reaches `dispose`); the second consequence — a state mounted and removed before its first build is never disposed either — is recorded in the ADR, and `create_state` must not acquire lifecycle resources, as in Flutter. The pins this flips are the CHILD fixtures — `tests/inherited_dependency.rs::did_change_dependencies_panic_leaves_the_slot_intact_not_a_hole`, `build_owner.rs::tests::scoped_drain_unwind_restores_foreign_work_reasons_dependency_and_flags`, and two `#[should_panic]` tests in `flui-widgets` `localization/localizations.rs` driven by a child `init_state` probe; `init_state_panic_leaves_the_slot_intact_not_a_hole` mounts its panicking state as the ROOT and stays a propagation pin (renamed to say so).
- **Seam (b) — per-insert and per-update boundaries inside `reconcile_children_by_id`.** The shipped per-insert pair (`insert_reporting_child` + `InsertedChild::{Minted, Retaken}` + `discard_unannounced` | `remove_subtree(.., Finalize)`) and the per-update shape (`update_or_replace_resident`) that `sparse_children::mount_sparse_child` already uses are extracted into tree-level primitives `mount_or_substitute` / `update_or_substitute` (rule of three: sparse children, reconcile, seam (a)); `sparse_children.rs` calls them. `Minted` → `discard_unannounced` (unmount without the observation — the observer never saw a completed mount); `Retaken` (a GlobalKey retake carrying user state, announced as `Reparent`) → `remove_subtree(Finalize)`; an update panic → remove the resident + substitute. The reconcile therefore always reaches step 3, `child_ids` is always rewritten, and no stranded shell survives. Registrations a completed mount made (GlobalKey reserve, observer `element_mounted`, render adoption + parent data, interaction-lane registrations via `did_mount_render_object`) are undone by the ordinary unmount path, never by a raw slab remove. The catch REGION is the user-hook windows inside the insert (`create_render_object`/`did_mount_render_object` on a fresh mount; `update_render_object`/`did_update_view` on a retake) — framework-raised panics outside those windows, notably the debug-only eager duplicate-GlobalKey rejection (ADR-0050, two pins), keep propagating; the region decides, the `BUG:` prefix only labels. The sparse path today wraps the WHOLE insert and narrows to the same region when the primitives are extracted.
- **Seam (c) — every user-overridable hook on the removal path.** Each runs under its own `catch_unwind` and the framework cleanup after it is unconditional: `ViewState::deactivate` (keyed removal — `deactivate_subtree` releases inherited edges then calls it; the element is queued inactive regardless), `ViewState::dispose` (`remove_finalized_inner` frees the slot and bumps the generation regardless), `RenderView::did_unmount_render_object` (`RenderBehavior::on_unmount` calls it before `remove_render_object_from_tree` — the render node is removed regardless), `ListenableView::listenable()` on unmount (the listener is removed regardless). `ViewState::activate` on a GlobalKey retake needs no per-node catch: it unwinds into seam (b)'s `Retaken` disposal, the retake fails whole and the slot gets an `ErrorView`; `did_change_dependencies` on reactivation is scheduled as a build and lands in seam (a). Both the inline reconcile removals and the finalize sweep continue; the sweep reports and continues (Flutter's `finalizeTree` parity) — it never flips the frame to `Errored`.
- **One drain.** `BuildOwner::recovered_panics: Vec<RecoveredPanic { element: ElementId, parent: Option<ElementId>, view_type_id: TypeId, hook: LifecycleHook, error: FlutterError, internal_invariant: bool }>` (`internal_invariant` computed at push time from the raw payload — a consumer that redacts the message in release could not recompute it), threaded through `ElementOwner` exactly like `dirty_reasons`; pushed by all three seams *and* by `build_or_recover`. Drained by the realm after the build segment into `FrameFailureReport`s with `disposition: Contained` (no streak bump). `BUG:` payloads are contained and classified (`internal_invariant`), never routed.

Failure modes A′ keeps (recorded in ADR-0048's amendment): the `ErrorView` factory itself panicking on mount is unbounded by design (it names the broken factory — `mount_sparse_child`'s stance); a `BUG:` contained at seam (b) may leave render-side residue (that boundary does not claim recovery; the report says `internal_invariant`); a deterministic `did_update_view` panic under an animated parent yields one `Contained` report per frame (the embedder throttles — the same accepted steady state as a failing submit); a `LayoutBuilder` scope root failing in seam (a) needs its scope-registry entry pruned (builder verifies).

### G2 — the retry re-presents; hit test and hover read the committed version (flui-app)

- **Tail retry (replaces G2b).** `PresentationState` gains `segment_phase: Cell<SegmentPhase::{Build, Finalize, Pipeline, Tail, Scene}>`, written as `draw_frame_for_presentation` advances (unwind-correct: the last phase entered survives). On `Errored` with the phase past `Pipeline`, `render_frame_with_sink` arms `mark_needs_full_repaint_for(producer)` in addition to `wake_frame()`, so the retry paints and presents. The `retry_needs_repaint` comment is rewritten (its "nothing was produced to submit" justification is false for the tail case). `run_frame`'s doc is corrected: the layer tree on the semantics-`Err` arm stays in `last_layer_tree` and is submitted by the retry, not discarded.
- **The commit bit.** `PresentationState { tree_revision: Cell<TreeRevision>, presented_revision: Cell<TreeRevision> }` — a new newtype in flui-app (`epoch.rs`), distinct from the lane's per-submit `FrameEpoch` and from the failure streak (which `Idle` resets — the exact case the gate must hold). `tree_revision` bumps on `Painted` (before submit) and on `Errored` — not at segment entry, or a semantics-only `Idle` segment would strand the presentation `Uncommitted`. `presented_revision = tree_revision` ONLY on `Painted + {Presented, NoPresent}` (`NoPresent` is a commit: the backend accepted the scene as its latest — no damage means equal pixels, occluded means presented on uncover by the resume pump, and no input reaches an occluded window meanwhile); **`Idle` never transitions `Uncommitted → Committed`** (an `Errored` frame that consumed its dirty state and a retry that parks `Idle` submitted nothing); `Errored` / `SurfaceStale` / `DeviceLost` / `Failed` / the deferred first frame leave it `Uncommitted`. `frame_commit_state() -> FrameCommitState::{Committed, Uncommitted { since: TreeRevision }}` replaces the pump-wide `any_failed` at the ambient re-probe (fixing the secondary-freezes-primary precision bug); hover-class derivations hold their last targets while `Uncommitted`.
- **Held input while `Uncommitted` (closes the hit-test residual — the user's choice to close it in this spec; the geometry shadow first proposed cannot, see Alternatives).** Pointer events for an `Uncommitted` presentation are queued on `PresentationState`, consulted in `UiRealm::handle_input_addressed`'s `PlatformInput::Pointer` arm BEFORE `presentation.gestures().handle_pointer_event` — so the arena, the per-pointer route cache and `pending_moves` never see a held event — and dispatched in arrival order, through the same arm's dispatch closure, at the commit transition inside `render_frame_with_sink` (a replayed `Down` hit-tests the committed tree now; a replayed `Move` enters `pending_moves` and flushes next pump). Precedent: Flutter's `GestureBinding._pendingPointerEvents` flushed only when `!locked` (`gestures/binding.dart`), applied to the frame-commit state instead of reassembly. Rules that make order structural: once the queue is non-empty every pointer event for that presentation is appended and the queue drains only by replay; consecutive `Move`/`Hover` per pointer collapse in the queue (as `pending_moves` does), so it is O(active pointers + discrete events); a defensive cap drops the OLDEST complete sequences (down…up wholly inside the queue) with a latched warn, never splitting a sequence; never held: `Keyboard`, `Ime`, `DragDrop`, lifecycle/close, window hover; a window leave drops held `Hover`s and keeps contact sequences; presentation teardown drops the queue (no synthesized `Cancel`; traced count). No time bound: during an unbounded paint storm the screen is frozen and a live-tree hit was never a meaningful answer — the embedder's `consecutive_failures` escalation is the exit. The deferred first frame becomes correct for free (input held until the first submit). Deadlines start at delivery, one pump late — Flutter's `locked` semantics; velocity trackers must read event timestamps, not delivery time (builder verifies against `PointerInfo`'s time field).

### G3 — the criterion-6 fixture (flui-rendering tests, `tests/layout_poison.rs`)

Tree: root → parent (a box that lays its single child out under `BoxConstraints::loose(..)` and sizes to child + padding, whose `layout_child` error path continues on the substitute — the `DegradationProbe` route in `subtree_arena.rs`) → leaf `{ size_on_success: Cell<Size>, panic: Cell<bool>, layout_calls: Cell<u32> }` (non-root, loose constraints so S is not derivable from constraints). Pass 1: leaf returns S1 = 30×40 → assert leaf `geometry_box() == Some(S1)`, calls 1. Pass 2: `panic = true`, `size_on_success = S2 = 50×60`, `mark_needs_layout(leaf)`, run — the frame returns `Ok` (a DESCENDANT failure is swallowed by the parent's child-layout callback, which hands the parent `Size::ZERO` and records a `Poisoned` failure against the leaf; only a dirty-root failure surfaces); assert leaf still S1, `layout_poison.is_poisoned(leaf)` (same-crate test or a `testing`-feature accessor — no public poison accessor is added), calls 2, parent `geometry_degraded()`. Pass 3: `panic = false` (would yield S2), `mark_needs_layout(parent)` (not the root — `layout_dirty_root` serves cached geometry on unchanged constraints; `mark_needs_layout` walks up and un-poisons only visited ancestors, so the leaf keeps its poison and the parent passes its own short-circuit), run → assert calls **still 2**, leaf **S1 not S2**, parent degraded. **Discriminators:** (i) flip pass 2's `panic` off → pass 3 reads leaf `== S2` (calls stays 2: the leaf is served from the unchanged-constraints cache) → red on the geometry assertions; (ii) delete pass 2 entirely → calls 1 at pass 3 → red on the call count. **Control fixture:** the leaf panics from pass 1 → `geometry_box() == None` (the ZERO stand-in), parent degraded — the same oracle with the opposite answer is what "distinguishes" means. Oracles are the render object's own call counter and `RenderNode::geometry_degraded()` (public).

### G4 — what the report carries (flui-app)

`FrameFailureKind::SegmentPanic { message: PanicText, phase: SegmentPhase, internal_invariant: bool }` with `PanicText::{Verbatim(Box<str>), Redacted}` (`Display` for `Redacted` reuses `flui_log::REDACTED_VALUE` — flui-app is a composition root that already depends on flui-log; the variant is the contract, the literal is not duplicated). Default: `Verbatim` under `cfg(debug_assertions)`, `Redacted` in release; `AppConfig::with_frame_failure_detail(FrameFailureDetail::{Redacted, Verbatim})` is the explicit release opt-in — the same profile split `RenderErrorBox` already applies on screen, so the two surfaces state one policy. `FrameFailureReport` gains `disposition: FailureDisposition::{FrameDropped, Contained}` and `FrameFailureKind::RecoveredPanic { element: ElementId, view_type_id: TypeId, hook: LifecycleHook, message: PanicText }` fed from the flui-view drain — ownership identity + causal detail for contained recoveries. `RenderError`'s five `Box<str>` variants have one production constructor (`SemanticsError` from an id-only error) — stated "by inspection" in the ADR, and `Pipeline { error }`'s `Display` goes through the same `PanicText` gate so the claim does not depend on the grep staying true. `docs/runtime-contract.toml`'s root-export manifest is updated deliberately (`FrameFailureKind` is monitored).

### PR-0 — the panic-payload classifier has one home (flui-foundation)

`flui_foundation::panic::{payload_text(&dyn Any) -> Option<&str>, is_internal_invariant(&str) -> bool}` replacing the seven production copies of the `downcast_ref::<&'static str>() / String` dance (`flui-platform` `panic_boundary.rs`, `flui-app` `ui_realm.rs` + `close_request.rs`, `flui-rendering` `entry.rs` + `subtree_arena.rs` ×2, `flui-view` `error.rs`) and the test-only copies (`flui-rendering` `cell.rs`, two flui-view test helpers, `flui-widgets` `overlay/tests.rs`) so the census is an exact zero. Returns `Option` (non-string payload → `None`, per the `close_request.rs` pin); callers keep their own fallback rendering, so no asserted message changes. A fourth copy at the new seams would be rejected; this lands first.

### Alternatives considered

- **A (session-level reconcile catch + raw child removal + `[ErrorView]` child-list replacement + `BUG:` routing + semantics stage/commit).** Rejected after adversarial review: it covered the wrong phase (`init_state` runs in the child's phase-1 iteration, not the reconcile); "raw" removal leaks four registrations the shipped `InsertedChild`/`discard_unannounced` pair already handles and ignores the `Retaken` case; a `dispose` panic mid-reconcile left the slot unfreed and the recovery re-disposed it; `resume_unwind` after the finalize sweep dropped a frame for nothing and parked the retry `Idle`; `BUG:` routing turned a string convention into control flow at one seam only; every-profile redaction flipped a ticked criterion and broke its pin; the semantics split burned two consumed side effects (`take_removed_accessibility_ids`, `focus_claimants`) and its `Idle`-commit rule recreated a11y-leads-screen after a tail failure.
- **B / B′ (versioned or copy-on-write geometry read by the hit-test walk).** Rejected after review of the spec (PR #1023): `PipelineOwner::hit_test_subtree_impl` enumerates the LIVE `node.children()` and calls live render objects — a child removed by a successful build whose frame then failed in paint vanishes from hit test though still presented, an inserted never-presented one receives input, and clips, transforms, `placed_generation` gates and hit-test behaviour change with no geometry write. A geometry-only shadow closes one case and dresses the rest as fixed. A retained hit-test tree per presentation would close it but is a parallel structure for a one-pump window. Held input is the literal "one committed version" at no per-node cost.
- **C (element-slab snapshot/undo, Compose-style — `Snapshot.takeMutableSnapshot`/`apply`/`dispose` at the state layer, verified on developer.android.com; the "throwing composition is disposed" behaviour from memory).** Rejected: the element slab, `child_ids`, the GlobalKey registry and the render tree are not MVCC; a journal needs every mutation site across two crates to cooperate — the four-write-sites failure ADR-0062 recorded. A staging `ElementTree` swap is out for the same reason (`ViewState` is not `Clone`; render adoption at mount is a side effect on the other tree).
- **D (Flutter floor verbatim: `_tryRebuild` catch-and-continue, present the frame).** Presents the torn subtree with the parent un-dirty. Masonry offers no containment (docs.rs `masonry::core::Widget`: a panic is a logic error); GPUI `Window::draw` and SwiftUI `Transaction` (animation propagation, not failure rollback) from memory, unverified — neither is a floor above Flutter's.
- **ALT-2 (presentation-fatal + clean retry: undo via the sparse report, re-push the parent, propagate).** Meets "cannot partially commit" but leaves a deterministic hook panic as a frozen window at fallback pace; the undo is the same code as A′'s, so no simplicity gain.

## Acceptance criteria

Each traces to intent's "What 'fixed' looks like" (as corrected): **F1** everything that reads frame state sees one committed version; **F2** a failed subtree never leaves a half-applied mutation; **F3** a test tells last-good retention from the zero stand-in and goes red without the poisoning step; **F4** a production report carries nothing sensitive by default.

- **AC1 (F2, `init_state`):** a child whose `init_state` panics is replaced by an `ErrorView` at its parent's slot in the same frame; `dispose()` is never called on that state; the frame is `Painted`; the parent's render-child count is unchanged; red before PR-2b (the panic propagates — the flipped pin).
- **AC2 (F2, reconcile insert):** a `Row` of 10 children where child 7's `create_render_object` panics → one `ErrorElement` at slot 7, nine siblings intact and laid out, `child_ids` rewritten (no freed ids), the `TreeObserver`'s mount/unmount events pair, the parent's render-child count is 10; red before: the panic escapes.
- **AC3 (F2, ghost regression):** after AC2's frame, two further parent rebuilds leave the parent's render-child count at 10 and the slab count constant (no stranded shells); red before: the count grows per rebuild.
- **AC4 (F2, `Retaken`):** a GlobalKey-retaken child whose mount panics is removed with `Finalize` (key unregistered, observer balanced); red before.
- **AC5 (F2, `did_update_view` / `update_render_object`):** an update panic removes the resident and substitutes; siblings intact; red before.
- **AC6 (F2, removal-path hooks):** a panic in (a) `dispose()` inline during a reconcile removal, (b) `dispose()` in the finalize sweep, (c) `ViewState::deactivate` on a keyed child mid-`deactivate_subtree`, (d) `did_unmount_render_object`, (e) `listenable()` on unmount — in each the cleanup completes (slot freed + generation bumped for (a)(b); inherited edges released and the element queued inactive for (c); the render node removed from the render tree — render-tree length oracle — for (d); the listener removed for (e)), the walk/sweep continues, the frame is `Painted`, and one `Contained` report with the matching `hook` is delivered; plus (f) an `activate` panic during a GlobalKey retake → the retake fails whole, `ErrorView` at the slot, key unregistered, subtree freed. Red before each: (a) the slot survives and a second `dispose` fires; the others escape.
- **AC7 (F2, `BUG:` classified not routed):** a `BUG:`-prefixed panic in a lifecycle hook is contained exactly like any other and reported with `internal_invariant: true`.
- **AC8 (F1, tail retry):** a panic injected after `run_frame` returned `Ok` (tail probe) yields `Errored`; the very next pump paints and presents (`Painted { Presented }`), and the screen's scene equals a fresh owner's; red before: the retry parks `Idle`.
- **AC9 (F1, commit bit):** after `Errored → retry parks Idle` (no repaint armed by construction in the test) `frame_commit_state()` stays `Uncommitted` EVEN THOUGH the segment ran (`Idle` never acknowledges); after a `Painted { Presented }` it is `Committed`; a `Painted { NoPresent }` commits; the deferred first frame is `Uncommitted`; a semantics-only `Idle` segment on a `Committed` presentation stays `Committed` (no bump); a secondary presentation's failure leaves the primary `Committed` and its ambient re-probe runs; red before: the streak resets on `Idle` / `any_failed` is pump-wide.
- **AC10 (F1, held input):** with a presentation `Uncommitted` (a build removed child A and inserted B, then the frame failed in paint), pointer events arriving before the retry are NOT dispatched — hit-test-call oracle on the presentation's renderer == 0 and no new arena pointer; after the retry commits (`Painted { Presented }`) the held `down, N moves, up` are dispatched in arrival order (arena ORDER asserted) against the committed tree and the down's route targets B, not A; 1000 held Moves for one pointer collapse to one; a held Hover is dropped by a window leave while a held contact sequence survives it; presentation teardown drops the queue with no synthesized Cancel; the tests drive `handle_input_addressed` under the headless realm (not the `GestureBinding` harness — memory: the live wire and the harness have diverged before). Red before: the down is dispatched immediately against the live tree (hit-test count 1 while `Uncommitted`).

- **AC12 (F4):** in a release build (`cargo test --release` on the relevant test, or a `cfg`-toggled unit) `SegmentPanic.message` is `PanicText::Redacted` by default and `Verbatim` with `FrameFailureDetail::Verbatim`; in a debug build it is `Verbatim` by default (`frame_failure_containment` keeps asserting the message reaches the report); `RecoveredPanic` follows the same rule; `Pipeline { error }`'s `Display` never emits a `Box<str>` payload verbatim in release.
