## Decisions this decomposition fixes (read before dispatching any task)

**D1 — The per-child boundary is a code REGION, never a payload filter.** For a fresh element the region runs from `view.create_element()` through the end of `mount` inside `ElementTree::insert_with_provisional_order` (Flutter's second `performRebuild` catch wraps `inflateWidget`, so a throwing `createElement` is contained there too — nothing to undo before the mint, `Minted` after it); for a `GlobalKey` retake it runs from the `InsertedChild::Retaken` write — which MOVES to immediately after the relocation lands and BEFORE `activate_subtree` (D13) — through `activate_subtree` and the retake's `update`. Framework code outside those windows keeps propagating exactly as today: the debug-only eager duplicate-GlobalKey rejection in `retake_active_global_key`, `register_global_key_with_collision_check`, the retake preflight — the ADR-0050 model (`crates/flui-view/AGENTS.md` bullet 1; memory `global-key-duplicate-model-diverges`) and the pins `tests/global_key.rs::duplicate_global_key_panics_in_debug` / `tests/global_key_duplication.rs::one_key_twice_under_the_same_parent_is_rejected` stay untouched. A `BUG:` raised inside a window (the adoption `with_mut` inside `RenderBehavior::on_mount`) is contained and classified `internal_invariant: true` (AC7): the region decides, the prefix labels. Consequence for the sparse path: `sparse_children::mount_sparse_child` today catches the WHOLE insert; after 3.2 a framework panic between the windows propagates through a lazy list as it does through a dense parent. No sparse test pins the old shape (`rg -n "duplicate" crates/flui-view/src/element/sparse_children.rs` → prose only).
  **Ruled (chief-architect, 2026-09-11): REGION.** The two framework panics outside the windows are policy (ADR-0050), not accidents; containing them would retire ADR-0050 by way of a containment refactor. **Encoding:** a typed `Result`, not a threaded mode — the `catch_unwind` sits around exactly the window call sites, each already preceded by its report: `element.mount(..)` in `insert_with_provisional_order` (after `*inserted = Some(Minted(id))`), `activate_subtree` + `node.element_mut().update(view, owner)` at BOTH retake sites (after `Retaken` is reported — D13), and the dense reconcile's `ElementTree::update` window. Those return `Result<ElementId, ChildHookPanic { inserted: InsertedChild, hook: LifecycleHook, payload: Box<dyn Any + Send> }>` (`Result<(), _>` for `update`); the `inserted: &mut Option<InsertedChild>` out-parameter and `insert_reporting_child` disappear — the report travels in the error. `mount_or_substitute`/`update_or_substitute` undo by disposition and mount the `ErrorView` unbounded; the public infallible `insert`/`update` `resume_unwind` the payload (today's behaviour exactly). A `Boundary::{Propagate, Substitute}` mode is rejected (a second policy axis a caller can set wrong; `Result` is `#[must_use]`). Two details: `discard_unannounced` keeps its symmetric teardown (`did_unmount_render_object` runs on an object that WAS created and adopted — seam (c) catches it; record the Flutter contrast: Flutter never unmounts a child whose `mount` threw); `mount_sparse_child`'s `BUG:` doc paragraph is rewritten to say the sliver-index stamp is OUTSIDE the region.

Independent of each other (seam (a) runs in the failing CHILD's drain iteration after its parent's phase-2 already committed `child_ids`; seam (b) runs inside the PARENT's phase-2).

**D6 — `RecoveredPanic` carries `internal_invariant: bool`, computed at push time.** The spec's shape cannot satisfy AC7 once PR-3 redacts in release; `RecoveredPanic::from_payload` classifies the raw payload with `flui_foundation::panic::{payload_text, is_internal_invariant}`. **D7 — `RecoveredPanic.parent: Option<ElementId>`, `None` at the unmount-side seams.** `ElementCore` does not record its parent (`ElementCore::mount` ignores its `_parent`; only `ElementNode::parent()` knows), and `on_unmount`/`on_deactivate` see only `core`. AC13 requires `element`, `view_type_id`, `hook`. Seams (a)/(b) fill it; the dispose/deactivate/unmount-hook seams push `None`, documented. `api-design-lead` may instead store the parent in `ElementCore::mount` (a retake must then update it) — the cost is why `None` is the default.

**D8 — `LifecycleHook::{Build, InitState, DidChangeDependencies, Mount, Activate, Update, Deactivate, Dispose, UnmountRenderObject}`; seams that cannot see which hook ran learn it from a marker.** `ElementOwner::note_entering_hook(LifecycleHook)` (a `Cell` on `BuildOwner`, threaded like `dirty_reasons`) is set by `StatefulBehavior` before `init_state` / `did_change_dependencies` (read by seam (a)) and by the tree before `activate_subtree` / the retake `update` (read by seam (b)'s `Retaken` undo). `Mount` covers `create_element` + `create_render_object` + `did_mount_render_object` (the `FlutterError.details` breadcrumb carries the finer name); `Update` covers `did_update_view` + `update_render_object` + `on_view_updated`'s `listenable()` re-read.

**D9 — AC6's report half is PR-3's, and the flui-app headline test re-targets to the segment probe.** Until PR-3 forwards the drain, a contained removal-path panic is observable only as `BuildOwner::take_recovered_panics()` plus `tracing`. After v2 no user-overridable hook on the removal path escapes any more, so `a_dispose_panic_is_contained_…` cannot keep a "real escape path" inside the segment; it re-targets to `PresentationState::set_segment_probe` (five sibling tests already use it; its field doc names it "the controllable stand-in for real escape paths"), keeps every assertion (SegmentPanic naming A, sibling B frames in the same pump, retry armed, clean recovery pump), and its doc says the real removal-path hooks are now bounded in flui-view and pinned in `tests/lifecycle_panic_containment.rs`. The one real user-callback escape that survives v2 — a lazy list delegate's `find_index_by_key` (`sparse_children::ReconcileSource.find_index_by_key`, unbounded, Flutter parity) — is the alternative fixture if `qa-lead` wants a real path; it is named in 4.7's residual list either way.

**D10 — Drain first, then the seams that feed it.** 3.1 drain + `build_or_recover` feed → 3.2 extraction (primitives push `Mount`/`Activate`/`Update`) → 3.3–3.5 seam (c) hooks each pushing their own entry. A seam whose report has nowhere to go for a commit is the "shipped seam never wired" class this repo keeps finding.

**D11 — Hook (e) `listenable()` is closed by caching, not by a catch.** `ListenableView::listenable(&self) -> Arc<dyn Listenable>` is the only handle to the listenable; if that call panics at unmount there is nothing to remove the listener FROM, so "the listener is removed regardless" is unreachable with a catch. `AnimatedBehavior` stores the `Arc<dyn Listenable>` it subscribed to (`subscribed: Option<(Arc<dyn Listenable>, ListenerId)>`), `on_unmount` removes through the cached handle and never re-enters user code; `on_view_updated`'s two `listenable()` reads stay inside seam (b)'s update window. AC6(e)'s oracle: after unmount the listenable's listener count is 0 even when `listenable()` is armed to panic on any call after mount. `chief-architect` confirms the reading of v2 (it satisfies "cleanup unconditional" literally; the catch it names would be inert).

**D12 — Seam (c)'s `deactivate` catch needs `owner`, so `activate`/`deactivate` take it.** `ElementBehavior::{on_activate, on_deactivate}(&mut self, core)` and `ElementBase::{activate, deactivate}(&mut self)` carry no `ElementOwner`; a catch inside `StatefulBehavior::on_deactivate` (the only place where `core.deactivate()`'s lifecycle flip stays unconditional after a user panic — a catch at the tree level around `element_mut().deactivate()` would skip that flip and hand a retake a still-`Active` element) cannot push its report. Thread `owner: &mut ElementOwner<'_>` through both trait pairs — the same shape `mount(.., owner)` / `unmount(owner)` already have. Ripple: `view/view.rs` (trait), `element/{behavior,kind,unified,generic,root}.rs`, `view/root.rs`, `layout_builder.rs`, `sliver_adaptor.rs`, `sliver_persistent_header.rs`, `tree/element_tree.rs::{activate_subtree, deactivate_subtree}`, `owner/layout_builder.rs` (one caller), `key/registry.rs` + `element/root.rs` tests — all flui-view (`rg -ln "impl ElementBase for|impl.*ElementBehavior<" crates --type rust` → flui-view only). ★ `api-design-lead`.

**D13 — The `Retaken` report moves before `activate_subtree` in both retake functions.** v2's claim that an `activate` panic "unwinds into seam (b)'s `Retaken` disposal" is false at `29935c04`: `retake_inactive_global_key` and `retake_active_global_key` (`tree/element_tree.rs`) both call `tree.activate_subtree(candidate_id, owner)` BEFORE `*destination.inserted = Some(InsertedChild::Retaken(candidate_id))`, so the undo sees `None` and the reactivated element is stranded. The write moves to right after the relocation lands (parent/slot set, inactive dequeued or the donor's `child_ids` edited) and before `activate_subtree`; the sparse path's existing undo then already covers (f). Born-red on the sparse path in 3.2, re-asserted dense in 4.1. Folded into spec v4.

## Risks

- **Hot path (seam (b)).** Landing pads are free; the `InsertedChild` write is a 16-byte move; the per-update returned id is a copy. Oracle: `scoped_build_drain` + `global_key_reparent_latency` before/after at 3.2 and 4.1; a >5 % regression blocks 4.8 until explained.
- **D12's signature ripple** is mechanical but touches the public `ElementBase` trait; the only implementors are in-crate (verified) — a downstream implementor would be a compile break caught by `just gate`'s workspace clippy.
- **`Retaken` fixture (dense).** `tests/global_key_reparent.rs::active_retake_outside_reconcile_grafts_when_no_render_moves` is the closest driver for AC4/AC6(f) through two parents' `build_scope` rebuilds; expect one fixture iteration.
- **Observer pairing oracle.** `MountLedger` is private to the sparse test module; a second copy or a lift to `tree::test_utils` (4.1). `flui_foundation::observe::tests::Recorder` records mounts only.
- **ErrorView under a sliver parent.** A substitute box under a sliver-protocol parent is a protocol mismatch on adoption — Flutter-parity failure; named in 4.7; not fixed here.
- **Report storm.** A deterministic `did_update_view` panic under an animated parent = one `Contained` report per frame (spec-accepted; the handler throttles); 5.4 documents it on `FrameFailureHandler`.
- **Held-queue memory under a storm** (spec v2): per-pointer collapse + the complete-sequence cap bound it; the cap's latched warn is the observability; 6.1's unit tests pin both.
- **Velocity on replay** — see Notes; a fork, not a risk to absorb silently.
- **Held input and the deferred first frame.** Input is held until the first submit by construction (6.3); the existing first-frame tests in `ui_realm.rs` (`segment_still_runs_by_the_same_predicate_while_deferred` family) are the neutrality oracle — a pointer test that assumed dispatch before the first present would flip; enumerate them at the PR-4 fine cut (`rg -n "make_down_event" crates/flui-app/src/app/ui_realm.rs`).
