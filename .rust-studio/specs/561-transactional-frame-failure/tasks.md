## Decisions this decomposition fixes (read before dispatching any task)

**D1 — The per-child boundary is a code REGION, never a payload filter.** A fresh element has one literal catch from `view.create_element()` through the end of `mount` inside `ElementTree::try_insert_with_provisional_order`. A `GlobalKey` retake has exactly two literal catches at both retake sites: `Activate` wraps only `activate_subtree`, and `Update` wraps only the retake's own `update`. The committed `InsertedChild::Retaken` value precedes activation; ancestry repair, render relocation, parent-data reset, and every other framework tail remain outside and between the two catches. The debug-only eager duplicate-`GlobalKey` rejection, registry collision checks, and retake preflight therefore continue to propagate. A `BUG:` raised inside a window is contained and classified `internal_invariant: true`: the region decides, while the prefix labels.
  **Encoding:** each fallible window returns a typed `Result` carrying `ChildHookPanic { inserted, hook, recording, payload }`; `recording` is the unwind-local handoff consumed at the immediate activation catch. `mount_or_substitute` / `update_or_substitute` undo by disposition and mount the `ErrorView` unbounded, while public `insert` / `update` resume the payload. `discard_unannounced` keeps symmetric teardown for an object created and adopted before its mount failed, and the sparse sliver-index stamp remains outside the mount window.

**D2 — Inside PR-2b, seam (b) lands before seam (a).** Seam (b) flips no pin and needs only the PR-2a primitives; seam (a) flips pins in two crates (D3) and needs `ElementTree::replace_child_with`. Independent of each other (seam (a) runs in the failing CHILD's drain iteration after its parent's phase-2 already committed `child_ids`; seam (b) runs inside the PARENT's phase-2).

**D3 — The spec's "flipped pin" is the wrong test; the real flips.** `tests/inherited_dependency.rs::init_state_panic_leaves_the_slot_intact_not_a_hole` mounts `PanicOnInit` as the ROOT (`tree.mount_root`) and a root still propagates under seam (a) — kept, renamed to say root. Seam (a) flips: (1) `tests/inherited_dependency.rs::did_change_dependencies_panic_leaves_the_slot_intact_not_a_hole` (the dependent is `tree.insert`ed under the provider); (2) `src/owner/build_owner.rs::tests::scoped_drain_unwind_restores_foreign_work_reasons_dependency_and_flags` (`DependencyPanicView` is a child of the scope root) — split: the unwind half re-fixtured on the one deterministic panic left OUTSIDE every window inside a scoped drain, the debug-only eager duplicate-GlobalKey rejection (one key twice under the same parent, `#[cfg(debug_assertions)]`-gated like the pin it mirrors), plus a new contained-inside-a-scope test; (3)+(4) `crates/flui-widgets/src/localization/localizations.rs::tests::{locale_of_panics_with_no_localizations_ancestor, of_panic_message_names_the_requested_type}` — `#[should_panic]` driven by an `init_state` probe mounted as a CHILD of `flui_widgets::testing::mount`'s scope wrappers. Seam (c) (PR-2a) flips `crates/flui-app/src/app/ui_realm.rs::frame_failure_containment::a_dispose_panic_is_contained_to_its_own_presentation_and_the_sibling_still_frames` (a REAL `dispose` panic). Every flip is re-targeted in the task that causes it.

**D4 — PR-1 lives in `crates/flui-rendering/tests/layout_poison.rs` with one testing-gated accessor.** `PipelineOwner::layout_poison` is private and `LayoutPoison::is_poisoned` is `pub(super)`; a same-crate unit test cannot use `flui_objects::RenderPadding` (flui-objects links the non-test build of flui-rendering — a different `RenderBox` trait than the `cfg(test)` one). So: `#[cfg(any(test, feature = "testing"))] pub fn is_layout_poisoned(&self, id: RenderId) -> bool` on `PipelineOwner` (the gate `parent_data_seeds` already uses), fixture in the integration binary. The parent that continues on the substitute is `RenderPadding`: every box parent continues, because the child-layout callback in `subtree_arena.rs::layout_subtree_borrowed_impl` returns a `Size`, never an `Err` — `Size::ZERO` on the failing walk, the poisoned node's `geometry_box().unwrap_or(ZERO)` stand-in on every later walk.

**D5 — PR-0 is ONE commit; seven production copies plus one test copy, and the test helpers go too.** Production: `flui-platform/src/shared/panic_boundary.rs::panic_payload_message`; `flui-app/src/app/ui_realm.rs::UiRealm::draw_frame_entered` (`Err(payload)` arm); `flui-app/src/app/close_request.rs::panic_message`; `flui-rendering/src/storage/entry.rs::RenderEntry::layout_leaf_only`; `flui-rendering/src/pipeline/owner/subtree_arena.rs::layout_subtree_borrowed_impl` and `::layout_sliver_subtree_borrowed_impl`; `flui-view/src/view/error.rs::FlutterError::from_panic`. **D6 — `RecoveredPanic` carries `internal_invariant: bool`, computed at push time.** The spec's shape cannot satisfy AC7 once PR-3 redacts in release; `RecoveredPanic::from_payload` classifies the raw payload with `flui_foundation::panic::{payload_text, is_internal_invariant}`. PR-3's `FrameFailureKind::RecoveredPanic` carries the same field.

**D7 — `RecoveredPanic.at: RecoveredAt` separates attribution from recovery outcome.** `RecoveredAt::Element { element, parent }` names the exact panicking element (including an `Activate` panic whose retake is later removed); `Substituted { element, substitute, parent, slot }` names a window-level replacement; `LazyDelegate { host, index }` covers builder/index callbacks before an item element exists. `ElementCore` does not record its parent, so behavior-level removal/activate records use `parent: None`; `RecoveredAt::parent()` never reinterprets a lazy host as a tree edge.

**D8 — attribution is recorded at the innermost seam, with transient carried state.** `LifecycleHook` includes `Build`, `InitState`, `DidChangeDependencies`, `Mount`, `Activate`, `Update`, `Deactivate`, `Dispose`, `UnmountRenderObject`, and `LazyIndexLookup`. A bounded caller arms `HookPanicRecording` immediately before entering user activation; a behavior catch that knows the exact element records it, marks `Recorded` only while armed, and rethrows. The immediate catch consumes and disarms it, storing the result in `ChildHookPanic`; direct/unbounded activation cannot arm or leak the marker. The substituting caller reads the carried value, never owner-global pending state, so it skips a duplicate without allowing `Recorded` to suppress a later unrelated recovery. PR-2b seam (a) must use the same arm/immediate-consume rule for `init_state` / `did_change_dependencies`, including disarming before a root rethrow.

**D9 — AC6's report half belongs to PR-3; PR-2a exposes only the frame-scoped drain.** Until PR-3 consumes it, contained removal-path and lazy-delegate panics are observable through `BuildOwner::take_recovered_panics()` / `WidgetsBinding::take_recovered_panics()` plus tracing, and an undrained batch is discarded at the next frame entry. The flui-app headline fixture uses the still-unbounded dense-path `create_render_object` escape so it genuinely enters `draw_frame` and pins the RAII building flag; task 4.1 must re-target it after dense reconcile adopts the containment primitives. Lazy count probes remain caught but unreported; mounted builder calls and `find_index_by_key` are caught and recorded as `RecoveredAt::LazyDelegate`.

**D10 — Drain first, then the seams that feed it.** 3.1 drain + `build_or_recover` feed → 3.2 extraction (primitives push `Mount`/`Activate`/`Update`) → 3.3–3.5 seam (c) hooks each pushing their own entry. A seam whose report has nowhere to go for a commit is the "shipped seam never wired" class this repo keeps finding.

**D11 — Hook (e) `listenable()` is closed by caching, not by a catch.** `ListenableView::listenable(&self) -> Arc<dyn Listenable>` is the only handle to the listenable; if that call panics at unmount there is nothing from which to remove the listener. `AnimatedBehavior` stores the subscribed `Arc` and listener id. `on_unmount` removes through that cached handle without re-entering user code; `on_view_updated` reads the new view's `listenable()` exactly once, compares it with the cached `Arc` by `Arc::ptr_eq`, and replaces the subscription only when the identity changed. AC6(e)'s oracle is a zero listener count after unmount even when later `listenable()` calls are armed to panic.

**D12 — `activate` / `deactivate` carry the owner handle.** `ElementBase::{activate, deactivate}` and `ElementBehavior::{on_activate, on_deactivate}` already take `owner: &mut ElementOwner<'_>`, matching `mount` / `unmount`. That handle lets `StatefulBehavior::on_deactivate` record before the unconditional lifecycle flip, and lets `StatefulBehavior::on_activate` record the exact panicking element while a bounded retake's transient handoff is armed. The signature ripple is wholly inside flui-view. ★ `api-design-lead`.

**D13 — `Retaken` precedes activation in both retake functions.** Once the candidate's parent and slot relocation commits (and the inactive entry or donor slot is released), both retake paths construct `InsertedChild::Retaken(candidate_id)` before the `Activate` catch. An activation panic therefore carries a disposition that can remove the relocated element; the framework relocation tail runs only after activation succeeds and remains outside both literal catches.
