## Decisions this decomposition fixes (read before dispatching any task)

**D1 — The per-child boundary is a code REGION, never a payload filter.** A fresh element has one literal catch from `view.create_element()` through the end of `mount` inside `ElementTree::try_insert_with_provisional_order`. A `GlobalKey` retake has exactly two literal catches at both retake sites: `Activate` wraps only `activate_subtree`, and `Update` wraps only the retake's own `update`. The committed `InsertedChild::Retaken` value precedes activation; ancestry repair, render relocation, parent-data reset, and every other framework tail remain outside and between the two catches. The debug-only eager duplicate-`GlobalKey` rejection, registry collision checks, and retake preflight therefore continue to propagate. A `BUG:` raised inside a window is contained and classified `internal_invariant: true`: the region decides, while the prefix labels.
  **Encoding:** each fallible window returns a typed `Result` carrying `ChildHookPanic { inserted, hook, staged, payload }`; `staged` is an owned diagnostic taken from the owner-local handoff at the immediate activation catch. `mount_or_substitute` / `update_or_substitute` undo by disposition and mount the `ErrorView` unbounded, committing the token only after substitute success, while public `insert` / `update` resume the payload. Dropping the token handles every pre-commit recovery failure without mutating older queue entries. `discard_unannounced` keeps symmetric teardown for an object created and adopted before its mount failed, and the sparse sliver-index stamp remains outside the mount window.

**D2 — Inside PR-2b, seam (b) lands before seam (a).** Seam (b) flips no pin and needs only the PR-2a primitives; seam (a) flips pins in two crates (D3) and needs `ElementTree::replace_child_with`. Independent of each other (seam (a) runs in the failing CHILD's drain iteration after its parent's phase-2 already committed `child_ids`; seam (b) runs inside the PARENT's phase-2).

Seam (c) (PR-2a) flips `crates/flui-app/src/app/ui_realm.rs::frame_failure_containment::a_dispose_panic_is_contained_to_its_own_presentation_and_the_sibling_still_frames` (a REAL `dispose` panic). **D4 — PR-1 lives in `crates/flui-rendering/tests/layout_poison.rs` with one testing-gated accessor.** `PipelineOwner::layout_poison` is private and `LayoutPoison::is_poisoned` is `pub(super)`; a same-crate unit test cannot use `flui_objects::RenderPadding` (flui-objects links the non-test build of flui-rendering — a different `RenderBox` trait than the `cfg(test)` one). So: `#[cfg(any(test, feature = "testing"))] pub fn is_layout_poisoned(&self, id: RenderId) -> bool` on `PipelineOwner` (the gate `parent_data_seeds` already uses), fixture in the integration binary. The parent that continues on the substitute is `RenderPadding`: every box parent continues, because the child-layout callback in `subtree_arena.rs::layout_subtree_borrowed_impl` returns a `Size`, never an `Err` — `Size::ZERO` on the failing walk, the poisoned node's `geometry_box().unwrap_or(ZERO)` stand-in on every later walk.

**D6 — `RecoveredPanic` carries exact payload provenance and classification.** `payload_text: Option<Box<str>>` is `Some` only for an actual `&'static str`/`String` payload and `None` for a non-string payload; the separate `FlutterError` remains display-facing and may contain its synthesized fallback. `internal_invariant: bool` is computed from that same raw text when the record is constructed. The shape satisfies AC7 after PR-3 redaction without guessing from diagnostics; `RecoveredPanic::from_payload` uses `flui_foundation::panic::{payload_text, is_internal_invariant}` before the record is staged or published. PR-3 consumes the owned provenance and carries the same classification.

**D7 — `RecoveredPanic.at: RecoveredAt` separates attribution from recovery outcome.** `RecoveredAt::Element { element, parent }` names the exact panicking element (including an `Activate` panic whose retake is later removed); `Substituted { element, substitute, parent, slot }` names a window-level replacement; `LazyDelegate { host, index }` covers builder/index callbacks before an item element exists. `ElementCore` does not record its parent, so behavior-level removal/activate records use `parent: None`; `RecoveredAt::parent()` never reinterprets a lazy host as a tree edge.

**D8 — attribution is staged at the innermost seam and committed only with recovery.** `LifecycleHook` includes `Build`, `InitState`, `DidChangeDependencies`, `Mount`, `Activate`, `Update`, `Deactivate`, `Dispose`, `UnmountRenderObject`, and `LazyIndexLookup`. A bounded caller arms `LifecyclePanicHandoff` immediately before entering a user lifecycle window; a behavior catch that knows the exact element creates one owned `StagedRecoveredPanic`, emits one outcome-neutral trace, stores the token only while armed, and rethrows. The immediate catch takes and disarms it into `ChildHookPanic` or a local phase-one recovery value; direct/unbounded activation cannot arm or leak the handoff. The recovering caller commits the token to `recovered_panics` only after substitute/replacement success and emits no second trace. Factory/create/mount/replacement failure drops the token without modifying older committed records. Seam (a) uses the same arm/immediate-take rule separately for `init_state` and `did_change_dependencies`, including disarming before a root rethrow.

**D9 — AC6's report half belongs to PR-3; PR-2a exposes only the frame-scoped drain.** Until PR-3 consumes it, contained removal-path and lazy-delegate panics are observable through `BuildOwner::take_recovered_panics()` / `WidgetsBinding::take_recovered_panics()` plus tracing, and an undrained batch is discarded at the next frame entry. After dense reconcile adopted per-child containment, the flui-app headline fixture moved to a one-shot segment probe that fires before `draw_frame`: it proves that a presentation-local segment panic is reported and dropped (`frames_rendered` is unchanged), retry is armed and later succeeds (`frames_rendered` increments by one), and a sibling presentation continues in the same pump. Because the probe fires before `draw_frame`, this fixture deliberately makes no claim about the widgets binding's RAII building-flag restoration. Lazy count probes remain caught but unreported; mounted builder calls and `find_index_by_key` are caught and recorded as `RecoveredAt::LazyDelegate`.

**D10 — Drain first, then the seams that feed it.** 3.1 drain + `build_or_recover` feed → 3.2 extraction (primitives push `Mount`/`Activate`/`Update`) → 3.3–3.5 seam (c) hooks each pushing their own entry. A seam whose report has nowhere to go for a commit is the "shipped seam never wired" class this repo keeps finding.

**D11 — Hook (e) `listenable()` is closed by caching, not by a catch.** `ListenableView::listenable(&self) -> Arc<dyn Listenable>` is the only handle to the listenable; if that call panics at unmount there is nothing from which to remove the listener. `AnimatedBehavior` stores the subscribed `Arc` and listener id. `on_unmount` removes through that cached handle without re-entering user code; `on_view_updated` reads the new view's `listenable()` exactly once, compares it with the cached `Arc` by `Arc::ptr_eq`, and replaces the subscription only when the identity changed. AC6(e)'s oracle is a zero listener count after unmount even when later `listenable()` calls are armed to panic.

**D12 — `activate` / `deactivate` carry the owner handle.** `ElementBase::{activate, deactivate}` and `ElementBehavior::{on_activate, on_deactivate}` already take `owner: &mut ElementOwner<'_>`, matching `mount` / `unmount`. That handle lets `StatefulBehavior::on_deactivate` record before the unconditional lifecycle flip, and lets `StatefulBehavior::on_activate` stage an owned exact-element diagnostic while a bounded retake handoff is armed. The immediate catch takes the token; recovery publishes it only after the substitute commits, or drops it on failure. The signature ripple is wholly inside flui-view. ★ `api-design-lead`.

**D13 — `Retaken` precedes activation in both retake functions.** Once the candidate's parent and slot relocation commits (and the inactive entry or donor slot is released), both retake paths construct `InsertedChild::Retaken(candidate_id)` before the `Activate` catch. An activation panic therefore carries a disposition that can remove the relocated element; the framework relocation tail runs only after activation succeeds and remains outside both literal catches.
