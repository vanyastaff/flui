# Survey: winit physical-key mapping onto the canonical W3C `Code` (issue #1092)

Read from sources on 2026-09-15. Third-party text is reported, not adopted.

## The market already has the complete converter
- **`ui-events-winit` 0.3.0** (crates.io, repo endoli/ui-events, updated 2026-01-18; deps `ui-events ^0.3.0`, `winit ^0.30.10`, `web-time ^1.1.0` — all in FLUI's graph; FLUI locks `ui-events 0.3.0`, `winit 0.30.13`). `ui-events-winit/src/keyboard.rs`: `from_winit_code(PhysicalKey) -> Code` has **194 `KC::X => Code::Y` arms = every `winit::keyboard::KeyCode` variant of 0.30.13** (diffed: zero unmapped; the deprecated `Meta`/`Hyper`/`Turbo` are mapped under `#[expect(deprecated)]`); `from_winit_location(KeyLocation) -> Location` (4/4); `from_winit_key(Key) -> Key` (~290 `NamedKey` arms, `_ => Unidentified` fallback). Masonry/Xilem ship it. FLUI's hand tables map 71 `Code` arms (of 194) and 37 `NamedKey` arms (of 306), falling through to `Unidentified` for the rest — a re-derived seam, the class #1143/#1144 name.
- **keyboard-types 0.8.3** `Code` has 216 variants — a superset of winit's 194; `Code::Unidentified` is the only honest fallback for a `PhysicalKey::Unidentified(_)`.

## Flutter (reference, 3.44.0)
- Physical identity is complete **by generation**: `packages/flutter/lib/src/services/keyboard_key.g.dart` (*"DO NOT EDIT … generated by dev/tools/gen_keycodes"*) defines 269 `PhysicalKeyboardKey` constants keyed by USB HID usage (`numpadEnter = 0x00070058`, `contextMenu = 0x00070065`, `f24 = 0x00070073`, `audioVolumeUp = 0x00070080`, `intlYen = 0x00070089`, `lang1 = 0x00070090`); per-platform maps in `keyboard_maps.g.dart` are generated from the same data. A hand-picked subset is not a shape the reference ever had.
- Where the reference still breaks is the **logical** side of the numpad, repeatedly: flutter#144936 (open, 2026: desktop `TextFormField` ignores Numpad Home/End/arrows), #133954 (numpad Enter in Windows tests), #147138 (Android numpad Enter does not submit), #150724 (closed: Linux numpad shortcuts on web), #123565 (Chromebook numpad). Lesson for FLUI: completing `Code` is the floor; `convert_logical_key` (numpad Enter ≡ Enter for submission, numpad navigation with NumLock off) is where users actually feel gaps, and shortcuts should bind on physical `Code` where layout independence is wanted.

## Decision inputs
- A: production dependency on `ui-events-winit` (delete the three hand converters); B: keep/complete the table, use the crate as a dev-dependency oracle over all 194 variants; C: A plus a documented vendoring escape if winit bumps ahead of the bridge (`winit-0.31.0-beta.2` is already in the local registry). Evaluated by the dependency-manager lens (deny/MSRV/feature-gating/cohort bumps) before the builder proceeds.
