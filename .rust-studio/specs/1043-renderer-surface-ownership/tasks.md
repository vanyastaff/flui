## T2 — flui-platform: Unavailable after destroy; native backends release the renderer on close
Crate: flui-platform only.
- `traits/window.rs`: the MUST on `window_handle`/`display_handle` docs.
- `shared/handlers.rs`: `WindowCallbacks.cleared: AtomicBool`; `clear()` sets it (before taking the
  slots); `CallbackLease::drop` consults it and DROPS instead of restoring when set (a close issued
  from inside a leased callback no longer resurrects the frame closure). Unit test: take a lease,
  `clear()`, drop the lease → slot stays `None`.
- `platforms/windows/window.rs`: `HasWindowHandle::window_handle` → `Unavailable` when
  `teardown_route(self.hwnd, self.context)` is `AlreadyGone | StaleHandle`; rewrite the
  "gap this comment does not close" paragraph to state exactly what is closed (re-acquisition after
  destroy; the orphaned lane) and what remains open (a surface alive during `DestroyWindow` when the
  close is requested from a leased callback). `platforms/windows/platform.rs` `WM_DESTROY` arm:
  `ctx.callbacks.clear()` after `dispatch_close()` (HWND still valid inside `WM_DESTROY`), with the
  comment naming the cycle it breaks (see memory `pre-present-hook-pins-the-window-in-a-cycle`).
- `platforms/macos/window.rs`: `setReleasedWhenClosed: NO` in `new` (comment: AppKit default YES
  would release the alloc/init +1 that `Drop` releases again); `closed: AtomicBool` set in
  `handle_close` (`windowWillClose:`), then `callbacks.clear()`; `window_handle()` returns
  `Unavailable` when `closed`. Add the same to the `CloseRequested`-equivalent path if `close()`
  bypasses the delegate.
- `platforms/android/window.rs`: doc only — it conforms; cite `MainEvent::Paused`.
- Tests (AC6): pure-function tests where the OS is not needed (route → `Unavailable` mapping via a
  helper that takes a `TeardownRoute`; AppKit `closed` flag → `Unavailable` via a helper that takes
  the flag) so they compile under `cross-typecheck`; label them "compiled on every target, executed
  on none" in their doc.
- Gate: `just cross-typecheck` (all three targets), `cargo clippy -p flui-platform --all-features --all-targets -- -D warnings`,
  `FLUI_HEADLESS=1 cargo nextest run -p flui-platform --all-features` (Linux suite), `cargo fmt --check`.
