### Approach 1 — borrowed lifetime `Renderer<'w>`

Shape: `Renderer<'w>` holds `Surface<'w>` built by the safe `create_surface(&'w W)` plus `&'w dyn (HasWindowHandle + HasDisplayHandle + Sync)` for recovery.

(a) *Invariants.* Surface-outlives-target: encoded by `'w` — `drop(window)` is E0505. Recovery-from-live-owner: `recover()` re-calls `window_handle()` on the borrow; nothing stores bytes. `Send`: `&'w W: Send` iff `W: Sync`; auto-derived. Owner-thread affinity: not encoded (none of the three encode it; see §Residuals).
(b) *Failure modes.* The borrow forbids *dropping* the window but not `window.close()` (`&self`) — the Win32 synchronous `DestroyWindow` case is exactly as open as today. Structural killers: `RasterOwner<B>::spawn` and `dyn RasterBackend + Send + 'static` need `'static` (`crates/flui-engine/src/raster.rs` L43, L198) — a `Renderer<'w>` can never enter the threaded lane ADR-0045 exists to build; `thread_local! APP_RUNTIME` requires `'static`; `PresentationState` holds the window `Arc` *and* the renderer that would borrow it — self-referential, which needs ouroboros or unsafe, i.e. the bug moves crates; the web runner's `Arc<Mutex<Option<Renderer>>>` in `spawn_local` needs `'static`.
(c) *Forward.* Incompatible with per-owner-thread `GpuServices` + `ReplaceServices` (a `Surface<'w>` cannot be shipped to a raster thread). Effort: high (ripples through flui-app types). Risk: high. Semver: breaking (allowed). Perf: none. Testability: compile_fail trivial. **Reject** — the owner already holds the window in an `Arc`; a lifetime models something ownership already models better.

### Approach 2 — owned target retained through rendering and recovery (recommended)

Shape:

```rust
// crates/flui-engine/src/wgpu/window_target.rs (new)
/// What a windowed renderer needs from the thing it draws into: a handle
/// source it can OWN (`'static`), share with wgpu's `Surface` (`Send + Sync`
/// — wgpu's `WindowHandle` bound on native), and re-query on recovery.
pub trait WindowTarget: HasWindowHandle + HasDisplayHandle + Send + Sync + 'static {}
impl<T: ?Sized + HasWindowHandle + HasDisplayHandle + Send + Sync + 'static> WindowTarget for T {}

// renderer.rs
#[doc(hidden)] // supersession note stays verbatim (intent: "Not this")
pub async fn new(target: impl WindowTarget) -> EngineResult<Self>

enum GpuStackOrigin {
    OwnedWindowed { target: Arc<dyn WindowTarget> }, // the ONLY place the target lives
    OwnedOffscreen,
    SharedServices,
}
```

`new` does `let target: Arc<dyn WindowTarget> = Arc::new(target)`, probes `target.window_handle()` and `target.display_handle()` (mapping `HandleError` → the new variant, below), then `instance.create_surface(Arc::clone(&target))` — `Arc<dyn WindowTarget>` satisfies `DisplayAndWindowHandle + 'static` through rwh's `Arc<H: ?Sized>` blankets, so this is the safe path and yields `Surface<'static>`. `recover()` matches the origin: `OwnedWindowed { target }` → probe + `create_surface(Arc::clone(target))`; `OwnedOffscreen` → device-only rebuild; `SharedServices` → `SharedServicesNotRecoverable`. Today's two-fact split (`raw_handles.window.is_some()` *and* `gpu_stack_origin`) collapses into one enum — one fact, one place.

(a) *Invariants, structurally.* **Surface never outlives its target:** wgpu holds its own `Arc` clone in `_handle_source`, declared last, so the target is released only after the surface's inner is destroyed — this is the #713 ordering (surface before `wl_surface`) enforced *inside* the surface, not by runner discipline; declare `surface` above `gpu_stack_origin` in `Renderer` for the same reading. **Recovery never uses stale bytes:** there are no bytes — `RawHandles`, its `unsafe impl Send`, `raw_handles_field_pin`, and the `create_surface_unsafe` block are deleted; wgpu calls `window_handle()`/`display_handle()` live at every creation. Android's Pause→Resume case is fixed by construction: `AndroidWindow::window_handle()` already returns `Unavailable` while paused and the fresh `ANativeWindow` after resume. **`Renderer: Send`:** every field is `Send` (`Arc<dyn WindowTarget>: Send + Sync` by the bound; `Surface<'static>: Send + Sync` per wgpu's assertion, on wasm32 via the already-enabled fragile feature) — the existing `assert_impl_all!(Renderer: Send)` / `assert_not_impl_any!(Renderer: Sync)` stay as the pin, now with zero manual impls behind them. On wasm32 the `Send + Sync` bound is stricter than wgpu's `WasmNotSendSync`, but `PlatformWindow: Send + Sync` already holds there and the web runner's `spawn_local` needs neither — no site changes. **The escape no longer compiles:** `Renderer::new(window.as_ref())` passes `&dyn PlatformWindow`, which fails `'static` (E0597/E0310) — the issue's proof program is the `compile_fail` doctest. **Owner-thread affinity:** not encoded by any type; wgpu panics on macOS off-main at creation (cited above). Its structural home is ADR-0045 decision 1 (creation is owner-affine) and `GpuServices`' `created_on: ThreadId` debug assert; `Renderer::new`/`recover` inherit that check when the windowed `GpuServices` constructor lands — out of scope here, per intent "Not this".
(b) *Failure modes.* `PlatformWindow::close()` while the renderer holds the `Arc`: **winit** — `set_visible(false)` + owner-deferred map removal (#919); the native window lives until the last `Arc<winit::Window>` drops, and the surface holds one → protected by ownership, on X11 and Wayland alike. **Win32 native** — `DestroyWindow` runs synchronously; the HWND is an *ID*, so the live swapchain fails with `SurfaceError::Lost`/`Outdated` (a logic error, not memory unsafety under rwh's stated contract), the runner's recovery loop calls `recover()`, and `WindowsWindow::window_handle()` must now answer `Unavailable` instead of handing out the dead HWND: reuse the identity probe `teardown_route` already performs (`GWLP_USERDATA` compare → `AlreadyGone`/`StaleHandle`, `crates/flui-platform/src/shared/hwnd_affinity.rs` L132-153) — no new flag, same fact, same home. This also closes the "gap this comment does not close" paragraph at `windows/window.rs` L1108-1120 with a real argument. **AppKit native** — `[NSWindow close]`; `MacOSWindow` alloc-inits with a +1 it releases in `Drop` (`macos/window.rs` L629-632), so the object outlives `close()` only if `setReleasedWhenClosed:NO` was set — `rg releasedWhenClosed crates/flui-platform` finds nothing, so **the platform lead must verify that before relying on it**; then `handle_close` (`windowWillClose:`, L1216-1222) sets a `closed: AtomicBool` and `window_handle()` returns `Unavailable`. **Android** — the owned target keeps the *activity* (`AndroidApp`) alive, not the `ANativeWindow`; the existing surface across Pause is governed by the lifecycle events exactly as today (pre-existing, unchanged); re-acquisition is now correct. **What the platform impls owe, as a contract on `PlatformWindow::window_handle`/`display_handle` (doc in `traits/window.rs` L504-523):** `Err(HandleError::Unavailable)` once the native window is destroyed or suspended. This protects **re-acquisition only**. What protects the **existing surface**: on winit, the retained `Arc` (structural); on Win32/AppKit native backends, the runner's drop order (renderer before `close()`) plus ADR-0045 §7's quarantine — **accepted residual**, recorded as a named follow-up issue ("native backends: `close()` is synchronous destruction; an owner-deferred close like winit's #919 route would make the `Arc` own the native lifetime"), *not* done here: both backends are compile-only in CI (`cross-typecheck`), and #1043 is scoped to the constructor.
(c) *Forward.* `GpuServices::create_surface(&self, target: impl WindowTarget) -> EngineResult<Surface<'static>>` on the owner thread is the windowed constructor's seam; the earlier `resolve_for_surface` cut (instance and surface must share a wgpu-core `Global`) is satisfied because the surface comes from *that* instance. `ReplaceServices { services, surface, generation }` ships a `Surface<'static>` that is `Send`; the `Arc<dyn PlatformWindow>` inside it crosses too, **erased to `dyn WindowHandle`** — the raster thread physically cannot reach `request_redraw` or `close` through it, which is decision 5 by type rather than by convention. A lane-side `Renderer` then has origin `SharedServices` and no target at all (ADR-0045's "the lane retains no raw handles"). `WindowPolicy::SharedRealm`: the target is per-presentation (one `Arc` per window, one surface each from the owner thread's instance) — composes. Crate placement stays right: flui-engine owns the *bound* (rwh vocabulary), flui-platform's `Arc<dyn PlatformWindow>` satisfies it by impls that already exist, flui-app composes; no new edge in `workspace-layers.toml`. Effort: one bundled PR (~14 files). Risk: low-medium (platform impl obligations on backends CI cannot execute). Semver: breaking on a `#[doc(hidden)]` fn — allowed. Perf: one extra `Arc` allocation per construction/recovery. Testability: compile_fail doctest; GPU-free unit tests of the probe with a fake `WindowTarget` returning `Unavailable` (`new` fails before `Instance::new`); GPU-gated `recover()` test with a toggling fake over an offscreen-built stack.

### Approach 3 — `unsafe fn new_raw` + the safe owned constructor

Shape: approach 2 plus `pub unsafe fn from_raw_handles(window: RawWindowHandle, display: Option<RawDisplayHandle>)` with a `# Safety` section.

(a) The safe half is approach 2. The unsafe half re-introduces stored bytes, hence `RawHandles` and the `unsafe impl Send` (or a `!Send` renderer variant), and `recover()` on a raw-built renderer either rebuilds from bytes under the caller's extended promise or is refused. (b) Same as today for every raw-built renderer; the SAFETY story is again "what a consumer promises". (c) It has **zero consumers**: all eight sites own an rwh-typed value (`Arc<dyn PlatformWindow>`, `Arc<winit::Window>`, the demo's `AndroidWindowHandle { app }` — `AndroidApp` is `Send + Sync + 'static`). An FFI host that owns a bare native handle implements `HasWindowHandle`/`HasDisplayHandle` on its own owner type — where the validity knowledge lives, via rwh's `borrow_raw` — and passes it to the safe constructor; that is the softbuffer/glutin/wgpu convention. Effort: low on top of 2. Risk: it contradicts ADR-0045's "deleted rather than narrowed". **Reject** — a strict maintainer refuses a public `unsafe fn` no caller needs.

### Recommendation and pre-code maintainer verdict

**Approach 2.** Pre-code verdict: **ACCEPTABLE as the reshape below** — a minimal patch ("add `Arc`, keep `RawHandles`, narrow the SAFETY comment") would be **RESHAPE NEEDED**; do not ship it.

- **Concept owner:** flui-engine owns `WindowTarget` (an rwh-vocabulary blanket trait, effectively sealed by its blanket impl). Not wgpu's `DisplayAndWindowHandle` in a public signature (wgpu majors every few months; rwh 0.6 is the stable ecosystem contract — softbuffer's `Surface::new(&ctx, window: W)` and glutin take an *owned* `W: HasWindowHandle` the same way), not a flui-platform type (engine must not name platform). The name avoids `SurfaceTarget`, which collides with wgpu's enum.
- **Reused, not reinvented:** wgpu's safe `create_surface` + `_handle_source` drop ordering; rwh's `Arc<H>` blankets; the existing `dyn PlatformWindow` handle impls; `hwnd_affinity::route_teardown`'s identity probe for Win32's `Unavailable`; the existing `assert_impl_all!` pins; `GpuStackOrigin` extended rather than a parallel `Option` field.
- **Public-surface changes:** `Renderer::new` keeps its name and `#[doc(hidden)]` (renaming buys nothing; ADR-0045 deletes it later); signature `pub async fn new(target: impl WindowTarget) -> EngineResult<Self>`; new `pub trait WindowTarget` exported from `flui_engine::wgpu` (re-export at crate root alongside `Renderer`); new `EngineError::SurfaceTargetUnavailable(#[source] raw_window_handle::HandleError)` — recoverability `Recoverable` for `HandleError::Unavailable` (suspended/closing target; the owner's lifecycle decides, and the runners' backoff loop already never gives up), `Fatal` for `NotSupported`. **Why a new variant, not `SurfaceCreation`:** the two facts have different consumers — "the owner says the window is gone/suspended" vs "the driver refused" — and wgpu's `CreateSurfaceError` does not expose the `HandleError` (cited above), so flui-engine must probe the target itself before `create_surface`; a probe/create race on Android falls through to `SurfaceCreation` and is re-probed on the next backoff tick (benign). `recover()` returns that variant when the target reports `Unavailable`.
- **What a strict maintainer rejects:** `Renderer<'w>`; an `unsafe` constructor with no caller; keeping `RawHandles` "for the unsafe path"; classifying `Unavailable` under `SurfaceCreation`; a `destroyed` flag on Win32 when `teardown_route` already computes the fact; touching Win32/AppKit `close()` semantics inside this issue.
- **Breaking changes allowed:** the `new` signature; the error enum gains a variant (`EngineError` is already `#[non_exhaustive]` or must become so — `api-design-lead` confirms); the `PlatformWindow::window_handle` doc contract gains a MUST.
- **Governing record:** new ADR-0063 "Renderer owns its surface target" (context: the cross-crate SAFETY; decision: `WindowTarget`, origin enum, platform `Unavailable` obligation, accepted native-backend residual; consequences: net unsafe delta −2 blocks in renderer.rs) plus an **amendment note on ADR-0045** decision 1 and §7: the blanket impl is deleted *by #1043, before the lane*; §7's rationale changes from "the `create_surface_unsafe` precondition" to "the `Arc` does not own the native lifetime on Win32/AppKit" — the quarantine decision itself is unchanged.
