# Spec: a node's own paint effects as one value — update-only commits for every effect expressed through it

- **Status:** Draft v3 (three adversarial passes folded in: B2 → A′ → A″; ready for the terminal gate)
- **Slug:** `996-fragment-scope-layer-updates`   ·   **Date:** `2026-09-10`   ·   **Owner:** `chief-architect` (design), `systems-perf-lead` (walk + bench), `api-design-lead` (types, trait method, removals, impact bits)
- **Governing ADR:** none yet — the composited-layer-update contract lives in `crates/flui-rendering/ARCHITECTURE.md` `## Mapping decisions` and this spec rewrites its trade-off 1. If C-lite (Deferred) is ever built it changes the retention model and gets an ADR.

## Problem

*(carried from `intent.md`, not re-authored)*

A property tick on a clip, a physical model, or a backdrop filter — a reveal animation driving a `ClipPath`'s clipper, a blur-in driving a backdrop filter's sigma, an elevation animation on a Material surface — repaints the whole subtree under the nearest repaint boundary every frame, because the effect reaches the frame as a fragment scope the paint walk replays, and a `COMPOSITED_LAYER_UPDATE` mark on such a node is inert: `layer_patches_for` finds no effect slot for it and the enclosing boundary repaints in full. Opacity, transform, and rotated box already get the cheap path; the fragment-scope effects do not, and nothing tells a widget author which of the two classes they are animating.

**What "fixed" looks like (intent):** ticking the property of a fragment-scope effect under a retained boundary leaves the subtree's paint count flat and produces the same layer tree a full repaint would — for every producer that can be served without a structural change; for the ones that cannot (or are not worth it), the record says so and why, and their setters still report the repaint they need.

**The bar set by the maintainer for this design (2026-09-10):** architecturally right for future decisions, and better than Flutter — not the smallest green slice. A fourth hook beside `paint_alpha` / `paint_transform` / the dead `paint_layer_blend` would ossify a hook family; the shape below replaces the family.

## Goals / Non-goals

**Goals**
- One declarative value per node for its own paint effects, from which the paint walk and the update arm both build layers — so patchability is a property of the value, and adding an effect kind is a field, not a hook.
- Serve `RenderClip` (rect / rrect / oval / path) property changes as update-only layer commits.
- Record, per producer, which properties are patchable, which are structural (→ `PAINT`), and which producers are not layer-patchable and why.
- Delete `paint_alpha`, `paint_layer_blend`, `paint_transform` (the family the value replaces).

**Non-goals (explicitly out of scope)** *(from intent)*
- No node is promoted to a repaint boundary.
- No effect draws anything different; a patched frame equals a fully repainted one.
- Clip semantics and hit-testing are untouched in behaviour (they keep resolving the clip shape as today).
- `RenderBackdropFilter` / `RenderShaderMask` setters are not flipped: no widget exists for either in flui-widgets / flui-material / flui-cupertino, so a flip has zero callers (seam-never-wired). Their fields and flips land with their widgets, against this mechanism.
- `RenderPhysicalModel` / `RenderPhysicalShape` are not layer-patchable (elevation/color/shadow are display-list content — `draw_shadow` + fill — and a descriptor layer wraps a node's OWN draws too, so the shadow cannot sit outside a descriptor clip). Recorded with its trigger.
- `RenderFlow`'s per-child transforms and `RenderFittedBox` are unserved (Deferred, with the precise reasons).

## Approach — A″-staged: `PaintEffects`, one value, one constructor, two callers

**Facts this rests on (each read in source this session; `.flutter` at 3.44.0):**
- Today a node's own effect layers come from three hooks read back-to-back at `pipeline/owner/paint.rs` ~:559-561, BEFORE the walk's three return gates (`skip_paint` ~:600, `needs_layout` ~:608, sliver cull ~:620) and before the `catch_unwind` that wraps only `paint_raw` (~:628); `own_effect_layers(alpha, blend, transform, origin)` (~:978) is the one constructor with two callers (walk ~:652, patch arm inside `layer_patches_for` ~:468); `record_effect_layer` fills `effect_slots`; the structure guard compares layer discriminants per position (~:494); a slotless target is refused (~:426). Fragment scopes (`FragmentScope`, `context/paint_cx.rs` ~:116) are replayed at ~:664 via `scope_layer(scope, origin)` (~:1448; clip shapes `translate_offset(origin)`-conjugated) and never recorded.
- `paint_transform` has a THIRD consumer: the default `apply_paint_transform` on `RenderBox` (~:444) and `RenderObject` (~:567), which `transform_to` (`pipeline/owner/accessors.rs` ~:292) walks on every ancestor for hero, IME/pointer (`editable_text.rs`), and focus-rect queries — outside any paint walk and any `catch_unwind`. `RenderTransform` and `RenderFittedBox` override `apply_paint_transform`; `RenderRotatedBox` relies on the default (pinned by `harness_transform_to_*` and `tests/transform_to.rs`). `forward_single_child_box_queries!` (used by 18 proxies incl. `RenderClip`) does NOT supply `apply_paint_transform`.
- `FragmentScope` is `pub(crate)` by recorded decision (`context/mod.rs` ~:83-92) and is named in exactly three files; `with_clip_rect/rrect/path(shape, behavior, f)` are the public producer API; `FragmentOp::Push(_)` is matched cross-crate only with a wildcard. `Leader`/`Follower` scopes get their ADR-0015 correlation only on the replay arm and make `capture()` evict the subtree — never patchable.
- `RenderClip::paint` (`proxy/clip.rs` :788) is `resolve_clip(size).with_clip_scope(ctx, clip_behavior, paint_child)`, pushed unconditionally (at `Clip::None` the engine skips the push — `layer_render.rs` "Clip::None should not push"), so its layer chain is constant. `resolve_clip(size)` (:633) is the shape's single source for paint, semantics (:817), hit-test (:827); for a path clipper it invokes user code through the owner lane (`flui-interaction` `resolve_path_clip_target`; `Err(InactiveRealm)` → `default_for_size`). `RenderFlow::paint` (`layout/flow.rs` ~:302) opens its clip iff `clip_behavior != Clip::None`, outside its per-child `PushTransform`s; `RenderFlow` is itself a repaint boundary.
- Production effect producers are disjoint sets: alpha ×4 (`proxy/opacity.rs`, `proxy/animated_opacity.rs`, `sliver/sliver_opacity.rs`, `sliver/sliver_animated_opacity.rs` — two slivers, so a `RenderSliver` mirror is required), transform ×2 (`layout/transform.rs`, `layout/rotated_box.rs`), clip-scope ×9 in `paint`. No node returns two hooks today.
- Upstream nesting, every `push*` outside `object.dart`: `RenderFittedBox` clip > transform; `RenderFlow` clip > opacity > transform per child; `RenderListWheelViewport` clip > opacity > clip > transform. No upstream node pushes its own transform outside its own clip. Opacity commutes with an anti-aliased clip and with a transform, so the only observable nesting is the clip/transform pair.
- Upstream's update-only contract at 3.44.0: `updateCompositedLayer` is the single layer builder on both the repaint and the update-only path (`object.dart` `_repaintCompositedChild`, `updateLayerProperties` ~:200-212 asserts `child.isRepaintBoundary` and `identical(updatedLayer, childLayer)`); `RenderOpacity.paint` is `super.paint` (`proxy_box.dart` ~:948-952) and builds no layer; **`markNeedsCompositedLayerUpdate` degrades to `markNeedsPaint` for any non-boundary** (`object.dart` ~:3395-3404). So upstream serves a layer-property update only for a node that IS a repaint boundary, owns its layer through a `LayerHandle`, and overrides `updateCompositedLayer` per class.
- `Path`'s derived `PartialEq` includes its memoised `bounds` (`flui-types/src/painting/path.rs`), so two equal paths compare unequal once one has had `.bounds()` called.
- `flui-rendering` depends on `flui-interaction` (`Cargo.toml` :31), so the walk can resolve a path-clip target itself.

### The types (flui-rendering, `traits/paint_effects.rs`)

```text
#[non_exhaustive] pub struct PaintEffects { pub opacity: Option<PaintOpacity>, pub clip: Option<PaintClip>, pub transform: Option<Matrix4> }
    pub const NONE; by-value builders with_opacity / with_clip / with_transform; Debug + Clone (not Copy: Path is boxed; not PartialEq: see below)
    ≈128 bytes, returned by value through the vtable (sret); built once per node per read, consumed by move
#[non_exhaustive] pub struct PaintOpacity { pub alpha: u8 }      // const fn new(alpha); blend is ADDED here when a producer exists — no phantom field now
#[non_exhaustive] pub enum PaintClip { Rect { rect, behavior }, RRect { rrect, behavior }, Path { path: Box<Path>, behavior }, PathTarget { target: PathClipTarget, behavior } }
```

- **Nesting is fixed on the type, outermost first: `opacity`, `clip`, `transform`.** Transform innermost by necessity: every other field is stated in the node's own space and the transform maps the child's space into it — anything inside the transform would be read in the child's scaled coordinates (the failure `RenderFittedBox` documents). Opacity outermost: coordinate-free group opacity over everything the node contributes; it commutes with clip and transform, so this matches every upstream instance pixel-for-pixel. Node-local shapes sit between; when `backdrop_filter` / `shader_mask` fields are added their position is fixed AT THE FIELD, because alpha does not commute with them — and the rule on the type is: **a node that needs opacity inside a filter or mask expresses it as a child node, as upstream does, never by reordering.** A node that needs a different nesting keeps that scope in `paint` and forgoes patchability for it — expressible, unaccelerated, documented on each field.
- **`#[non_exhaustive]` + public readable fields + `NONE` + builders.** Cross-crate, literal construction and `..Default::default()` are E0639 and exhaustive destructuring needs `..`; no producer destructures; a later field is additive. Builders are not `const fn` (`with_clip` needs drop glue for the boxed path); `NONE` covers test constants.
- **No `PartialEq` on `PaintClip`/`PaintEffects`** (the `Path` memoised-bounds trap); nothing in production compares descriptors — the patch arm compares layer discriminants. Test oracles compare layer kinds plus rect/rrect values, and path clips through an explicit accessor that ignores memoised bounds.
- **`Clip::None` is a layer, not an absence, for `PaintClip`** (`behavior: None` still emits; the engine skips the push) — stated on the type. A producer whose clip is overflow-gated (`RenderFlow`) returns `None` instead; the entry says why the two conventions coexist (property vs layout-derived gate).
- **A `PaintClip::PathTarget` is data**: the WALK resolves it through `resolve_path_clip_target` inside the `catch_unwind` on both arms. The descriptor therefore contains no user code and allocates nothing beyond a static path — which is what makes the default `apply_paint_transform` safe to read it (see Q5 below). The resolver is one helper in flui-rendering (`paint::resolve_path_clip(target, size)`), called by the walk and by flui-objects' hit-test/semantics (`resolve_clip`), so the `InactiveRealm → default_for_size` degrade stays one fact in one place.

### The method and its readers

`fn paint_effects(&self, size: Size) -> PaintEffects` on `RenderBox`, `RenderSliver`, `RenderObject` (default `PaintEffects::NONE`), both blanket forwards, and `RenderNode::paint_effects()` keeping exactly today's size resolution (box `geometry().unwrap_or(ZERO)`, sliver `absolute_paint_size()`, `storage/node.rs` ~:696-707). Contract on the method: the node's OWN effects, pure in `(self, size)`, no user code, must not depend on `paint` having run (the patch arm never runs it), **also read by the default `apply_paint_transform` outside the walk** (so it must stay cheap — a `PathTarget` token, never a resolved user path). `skip_paint` stays a separate walk gate (it decides "paint nothing", not "wrap in a layer"; `RenderTransform` uses it independently).

Readers after the change — exactly three, all through the value: the paint walk (one read per node), `layer_patches_for` (one read per patched node), and the default `apply_paint_transform` (`.transform` only). No other place builds an effect layer from a node: hit-test and semantics transforms are matrices, not layers.

### The mechanism

- `own_effect_layers(effects, origin)` takes the one value (`SmallVec<[Layer; 3]>`); the walk and the patch arm remain its two callers. **No stored `shape()`**: under a fixed order the per-position layer-discriminant compare already IS the complete structure guard (`Opacity | ClipRect | ClipRRect | ClipPath | Transform` are distinct discriminants; a same-position property change keeps the discriminant; a `Some ↔ None` changes the count). A same-count kind swap (`Rect → RRect`) is reproduced positionally either way and is therefore unpinnable — and no production producer does it.
- `FragmentScope`'s three clip variants fold into `FragmentScope::Clip(PaintClip)`; `with_clip_rect/rrect/path` keep their signatures and build the same value; `scope_layer`'s clip arm and `own_effect_layers`' clip arm share one `clip_layer(PaintClip, origin)`. The 11 non-`RenderClip`/`RenderFlow` scope producers recompile untouched. `ClipGeometry::with_clip_scope` (sealed) is replaced by `to_paint_clip(&self, behavior) -> PaintClip`; `Oval` maps to `RRect` exactly as today, so `PaintClip` has no Oval variant.
- The `apply_paint_transform` defaults read `paint_effects(size).transform`. **Q5 resolution (ALT-1):** because `PathTarget` is resolved by the walk, `RenderClip<Path>::paint_effects` returns a 16-byte token and no closure runs on a coordinate query — pinned by AC11. Producers that override `apply_paint_transform` today (`RenderTransform`, `RenderFittedBox`, `RenderFlow`) keep doing so.
- **The guard move (PR2), two intended behaviour changes:** (a) the descriptor read moves from before the return gates to inside the `catch_unwind` beside `paint_raw`, so a gated-out node's descriptor is never built (today a `needs_layout` node's transform hook runs on `Size::ZERO`); (b) a panic in `paint_effects` — or in the walk's `PathTarget` resolution — on either arm becomes `RenderError::poisoned` instead of a raw unwind through `run_paint` with the phase never exited. The patch arm's build is wrapped with `AssertUnwindSafe` (the closure captures a `&RenderNode` holding `dyn RenderObject`); `layer_patches_for` returns `RenderResult<Option<LayerPatch>>` (one call site ~:782-787: `retained.and_then(..)` → `.map(..).transpose()?.flatten()`; no test callers); the poison carries phase `"layer-update"` so a frame that never ran `paint_raw` is diagnosable. Refuse-on-panic is rejected (it would re-run the closure and panic twice).

### Producers (PR3)

- `RenderClip`: `paint_effects` returns `PaintEffects::NONE.with_clip(self.resolve_clip_descriptor(size, self.clip_behavior))` — a static shape as `Rect`/`RRect`/`Path`, a token-driven one as `PathTarget` (dropping today's `self.clone()` at :485); `paint` becomes `ctx.paint_child()`; hit-test/semantics keep `resolve_clip` (now through the shared resolver). Five setters (`set_clip_shape`, `set_border_radius`, `set_path_clip_target`, `set_path_clip_source_token`, `set_clip_behavior`) report `COMPOSITED_LAYER_UPDATE` (`| SEMANTICS` where they report it today). No `RenderClip` setter is structural. Note for the record: `set_clip_behavior` stays without `SEMANTICS`, and the a11y clip gates on `Clip::None` outside `resolve_clip` (:814) — a pre-existing gap, not claimed fixed.
- `RenderFlow`: its gated clip moves to `clip:` (`None` at `Clip::None`), NO impact change (`set_clip_behavior` stays `PAINT | SEMANTICS` — structural). This gives the structural-refusal oracle a production type and exercises the clip arm on every Flow frame; Flow's per-child transforms stay in `paint`.
- Migrated in PR1 (behaviour-neutral): the four opacities (`opacity: Some(PaintOpacity::new(alpha))`, incl. the `alpha == 255` group-layer case `always_needs_compositing` forces today), `RenderTransform` (`transform:`; its `owns_effect_layer` predicate unchanged), `RenderRotatedBox` (`transform:`; the default mapping now derives from the value — pinned by the existing `transform_to` tests).

### Alternatives considered

- **A′ — a fourth hook `paint_scope`** returning a clip descriptor beside the existing three. Rejected on the maintainer's bar: it ossifies a hook family whose ordering lives as prose in `own_effect_layers`, leaves the dead blend hook a separate decision, and makes every future effect a hook + an arm + a prose update. Everything A′'s review established is retained here (FragmentScope stays `pub(crate)`, no link variants, guard move, `RenderResult`, Flow for the oracle, lane-entered bench).
- **B2 — stamp scope layers at capture, rebuild by re-recording the node's fragment** (`paint_raw` into a scratch recorder, typed `FragmentSkeleton`). Covers variable-fragment producers (Flow transforms, FittedBox) the value cannot; costs a scratch execution per patch and a skeleton that needs an explicit hook prefix. Not needed for any producer this spec serves; recorded as the second rebuild mode for the Deferred variable-fragment producers — and the descriptor IS the hook prefix that skeleton needed, so B2 gets cleaner after this.
- **B1** (stamp + query hook) — A′ with a duplicate descriptor; rejected. **C-full** (Masonry model: per-node retained scenes re-stitched every frame) — forfeits the inline O(1) graft the measured 163×/1.4× rests on; rejected on measurement. **D** (record only) — right for backdrop/shader/physical model/Flow transforms/FittedBox, wrong for `RenderClip`: `ClipPath::new(closure)` mints a fresh `ClipSourceToken` per rebuild (`flui-widgets/src/clip/clip_path.rs` ~:57) → `PAINT | SEMANTICS` → a per-frame subtree repaint inside any app `AnimatedBuilder`, the default way to write a reveal; a wired beneficiary today.
- **Two methods** (keep `paint_transform` for mapping, `paint_effects` walk-only) — two `size` conventions and the drift the value removes; rejected.
- **Per-producer `apply_paint_transform` overrides** for lane-resolved fields (Q5 option a) — caller discipline the second producer forgets; rejected in favour of walk-resolved targets.

## Acceptance criteria

Each traces to intent's "flat paint count + same layer tree as a repaint, or a recorded reason".

- **AC0 (PR1 is behaviour-neutral):** the full existing suite is green with ZERO test-assertion changes beyond mechanical renames (`paint_alpha()` → `paint_effects(size).opacity.map(|o| o.alpha)`, `paint_transform(size)` → `paint_effects(size).transform`); `fitted_box.rs`'s `paint_and_hit_test_share_one_transform` keeps its non-tautological `transform.is_none()` pin; `repaint_boundary.rs`'s `test_paint_effects_none` is deleted on the tautology argument; `transform_to.rs` and `harness_transform_to_*` stay green (the default mapping now reads the value); one double-backed case reaches the clip arm (`an_effect_layer_shape_change_falls_back_to_a_repaint`, clip `Some ↔ None`).
- **AC1 (setter algebra, unit):** each of the five `RenderClip` setters returns `NONE` unchanged and `COMPOSITED_LAYER_UPDATE` (+ `SEMANTICS` as today) on change; red before PR3 (`PAINT`).
- **AC2 (update without repaint):** root → boundary → `RenderPadding` (non-zero) → `RenderClip<RRect>` → a drawing leaf; after `set_border_radius` via `apply_render_update_impact`: the LEAF's paint count flat; the `ClipRRectLayer` equals a fresh owner's at the new radius and differs from the old. Mutation: setter reverted to `PAINT` → count increments.
- **AC3 (write-back, three frames):** as AC2, then dirty a sibling boundary's leaf; the outer graft replays the stored capture and shows the new radius.
- **AC4 (captured origin):** a preceding sibling grows in the tick frame; the clip rect equals a fresh repaint's (translated by the new origin) — the `LayerUpdate` was upgraded to `Repaint`.
- **AC5 (structural refusal, production type):** `RenderFlow` — itself a repaint boundary, so its own effect layers live in its OWN capture — `set_clip_behavior` `HardEdge → None` applied, then a direct `mark_needs_composited_layer_update`: the walk refuses, repaints, and clears the flag; oracle = `needs_composited_layer_update()` + layer-KIND fingerprint (the `ClipRectLayer` is gone). No kind-change case (unpinnable, and no producer does it).
- **AC6 (panic on either arm):** one double whose `paint_effects` panics: under a layer-update mark → `Err(poisoned)` with phase `"layer-update"`, once, no second panic; under a repaint → `Err(poisoned)` with phase `"paint"`; a gated-out node (`needs_layout`) whose descriptor would panic does not run it. Plus a `PathTarget` whose resolver panics → the same two outcomes.
- **AC7 (widget wiring):** rebuilding `ClipRRect` with a new radius yields the new layer (pins `update_render_object`; cannot see the arm, says so).
- **AC8 (pixels):** `/tests/composited_layer_update_readback.rs` (workspace root; `required-features = ["gpu-readback-tests"]`; CI `gpu-test`; locally `cargo nextest run -p flui --features gpu-readback-tests --no-default-features --test composited_layer_update_readback --locked --test-threads 1`): patched vs forced-repaint identical for a radius change, sampled at the CORNER; old vs new differ.
- **AC9 (measurement):** `paint/clip_rrect_radius_change` and `paint/clip_path_token_change` on both shapes, both arms dirtying the same node; the path bench runs `run_paint` inside an entered `InteractionLane` with a registered clipper and asserts the clipper counter is non-zero per iteration (without a lane the resolver returns the default rect and the bench measures nothing); N=1 and N=1000 quoted on both shapes. Expectation stated correctly: the resolver runs once on both arms, so its cost cancels in the ratio (compresses toward 1×, cannot cross it).
- **AC10 (accounting):** ARCHITECTURE.md — trade-off 1 rewritten to the rule + the `rg` enumeration command (no list a human maintains); the improvement over upstream stated as below; per-producer entries; the Deferred table; the ten existing mentions of the old hooks (`:238-239`, `:304-313` — now false, alpha rides the box/sliver size split — `:337`, `:343`, `:376-377`, `:401-403`) rewritten; the harness comment "`RenderTransform`/`RenderFittedBox` need no override" corrected (both override `apply_paint_transform`).
- **AC11 (no user code on coordinate queries):** `transform_to` through a `RenderClip<Path>` with a registered, counting clipper: the counter stays 0 and no allocation of a resolved path occurs (the descriptor holds the token).

### The improvement over upstream, as the entry will state it

> Upstream can serve a layer-property change without a repaint only for a node that IS a repaint boundary: `markNeedsCompositedLayerUpdate` degrades to `markNeedsPaint` for any other node (`object.dart`), `updateLayerProperties` asserts `isRepaintBoundary`, and the class must own its layer through a `LayerHandle` and override `updateCompositedLayer` — `RenderOpacity` therefore declares `isRepaintBoundary => alwaysNeedsCompositing` to qualify, at the cost of an `OffsetLayer` and a retained capture per node. FLUI reads one `PaintEffects` value from any node and builds its layers inside the ENCLOSING boundary's flat capture through one constructor with two callers, so every effect expressed through the value is patchable with no promotion, no layer ownership, and no per-class override; the value fixes the nesting (opacity outermost, transform innermost, node-local shapes between), which is what lets a single per-position layer-kind compare stand as the whole structure guard. Re-derive upstream's contract from `markNeedsCompositedLayerUpdate` and `updateLayerProperties` in `object.dart` and `RenderOpacity` in `proxy_box.dart`, not from a mark grep.

## Risks & open questions

- PR1's neutrality rests on: read site unchanged; `RenderNode::paint_effects` keeping the exact size resolution; `apply_paint_transform` defaults re-pointed and pinned; the `RenderSliver` mirror present; `skip_paint` untouched.
- The walk-resolved `PathTarget` moves the `InactiveRealm` degrade into flui-rendering's resolver; hit-test/semantics in flui-objects call the same helper so there is one behaviour — verified by AC11 + the existing clip hit-test/semantics tests.
