# Spec: update-only composited-layer commits for fragment-scope effects

- **Status:** Draft v2 (two adversarial passes folded in: B2 attack → A′; A′ attack → the ten edits below)
- **Slug:** `996-fragment-scope-layer-updates`   ·   **Date:** `2026-09-10`   ·   **Owner:** `chief-architect` (design), `systems-perf-lead` (walk + bench), `api-design-lead` (hook + impact-bit sign-off)
- **Governing ADR:** none — the composited-layer-update contract lives in `crates/flui-rendering/ARCHITECTURE.md` `## Mapping decisions`; this spec extends that entry. An ADR becomes warranted only if C-lite (below) is ever built, since it changes the retention model.

## Problem

*(carried from `intent.md`, not re-authored)*

A property tick on a clip, a physical model, or a backdrop filter — a reveal animation driving a `ClipPath`'s clipper, a blur-in driving a backdrop filter's sigma, an elevation animation on a Material surface — repaints the whole subtree under the nearest repaint boundary every frame, because the effect reaches the frame as a fragment scope the paint walk replays, and a `COMPOSITED_LAYER_UPDATE` mark on such a node is inert: `layer_patches_for` finds no effect slot for it and the enclosing boundary repaints in full. Opacity, transform, and rotated box already get the cheap path; the fragment-scope effects do not, and nothing tells a widget author which of the two classes they are animating.

**What "fixed" looks like (intent):** ticking the property of a fragment-scope effect under a retained boundary leaves the subtree's paint count flat and produces the same layer tree a full repaint would — for every producer that can be served without a structural change; for the ones that cannot (or are not worth it), the record says so and why, and their setters still report the repaint they need.

## Goals / Non-goals

**Goals**
- Serve `RenderClip` (rect / rrect / oval / path) property changes as update-only layer commits: `set_clip_shape`, `set_border_radius`, `set_path_clip_target`, `set_path_clip_source_token`, `set_clip_behavior`.
- Record, per producer, which properties are patchable, which are structural (→ `PAINT`), and which producers are not layer-patchable at all and why.
- Decide the dead `paint_layer_blend` hook.

**Non-goals (explicitly out of scope)** *(from intent)*
- No node is promoted to a repaint boundary.
- No effect draws anything different; a patched frame equals a fully repainted one.
- Clip semantics and hit-testing are untouched.
- `RenderBackdropFilter` and `RenderShaderMask` setters are NOT flipped in this spec: neither has a widget in flui-widgets / flui-material / flui-cupertino, so a flipped bit there has zero production callers — the seam-never-wired pattern by definition. Their flip is one line each in the PR that lands their widget, against the same mechanism.
- `RenderPhysicalModel` / `RenderPhysicalShape` are not layer-patchable (their elevation/color/shadow live in the display list as `draw_shadow` + fill, not on a layer); recorded, not built — see Deferred.
- `RenderFlow`'s per-child `PushTransform`s and `RenderFittedBox` (clip-outside-transform, translation fast path via `paint_child_at`) are not served by this slice — see Deferred. (Flow's CLIP does move to the hook, with no impact change, to give the structural-refusal oracle a production type.)

## Approach — A′: one `paint_scope` hook, the existing slot machinery

**Facts this rests on (each read in source this session):**
- `own_effect_layers(alpha, blend, transform, origin)` (`pipeline/owner/paint.rs` ~:978) is the one constructor for a node's own effect layers, with two callers (paint walk ~:652, patch arm inside `layer_patches_for` ~:468); `record_effect_layer` (~:1202) has one call site (that loop) and fills `effect_slots`; the structure guard compares layer discriminants per position; a slotless target is refused (~:426). Fragment scopes (`FragmentScope` in `context/paint_cx.rs` ~:116) are replayed at ~:664 through `scope_layer(scope, origin)` (~:1448, clip shapes `translate_offset(origin)`-conjugated) and never recorded.
- `RenderClip::paint` (`proxy/clip.rs` :788) is `resolve_clip(size).with_clip_scope(ctx, clip_behavior, paint_child)` — the scope is pushed unconditionally, even at `Clip::None` (the engine skips the push: `flui-engine` `layer_render.rs` test "Clip::None should not push"), so a FLUI clip's layer structure is a constant one-layer chain and `clip_behavior` is a pure layer property. `resolve_clip(size)` is already the single source of the clip's shape: paint (:793), semantics (:817), hit-test (:827) all call it. It may run user code (`resolve_path_clip_target` → the owner lane's path-clipper closure).
- The three hook reads (`paint_alpha`/`paint_layer_blend`/`paint_transform`, ~:559-561) run BEFORE the walk's three return gates (`skip_paint` ~:600, `needs_layout` ~:608, sliver cull ~:620) and before the `catch_unwind` (which wraps only `paint_raw`, ~:628); `own_effect_layers` (~:652) runs after both. So today a gated-out node's hooks still execute — a `needs_layout` node's `paint_transform` receives `Size::ZERO` from `geometry().unwrap_or` (`storage/node.rs` ~:699) — and a hook panic unwinds raw through `run_paint` without exiting the phase.
- `FragmentScope` is **`pub(crate)` by recorded decision** (`context/mod.rs` ~:83-92: "has ZERO cross-crate consumers … not re-exported as `pub`"; the type doc calls it pipeline-internal paint IR). It also carries `Leader`/`Follower`, whose bookkeeping (`record_follower_correlation`, ~:670) fires only on the replay arm, and whose presence makes `capture()` evict the subtree (~:1280) — a link scope can never be patched.
- `RenderFlow::paint` (`layout/flow.rs` ~:302) opens its clip scope iff `clip_behavior != Clip::None` — a real production `Some ↔ None` transition; its clip sits OUTSIDE its per-child `PushTransform`s, the order the hook produces.
- Six more clip-scope producers of the shape `has_visual_overflow && clip_behavior != None` with a layout-derived rect exist (enumerate with `rg -n "with_clip_rect\(|with_clip_rrect\(|with_clip_path\(|with_shader_mask\(|with_backdrop_filter\(" crates/flui-objects/src`); none has a patchable property.
- Origin: a child's paint origin is `parent origin + child_offset` (~:872), where `child_offset` is the committed layout offset or a `paint_child_at` override; transform layers do not shift it. Every `paint_child_at` producer reports `PAINT` on a translation change, so no property-only path changes a descendant's origin without a repaint (harsh-critic traced this; the existing pin `a_same_frame_layout_change_forces_the_repaint_a_transform_patch_relies_on` covers the layout half).

**The change:**

1. **flui-rendering, traits.** A new default method `fn paint_scope(&self, size: Size) -> Option<PaintClip>` on `RenderBox` and `RenderObject` (default `None`), the box blanket forward (pattern of `paint_transform`'s at `traits/render_box.rs` ~:839), and a `RenderNode::paint_scope` box arm. **No `RenderSliver` mirror**: no sliver overrides `paint_transform` and no sliver scope producer exists; the sliver blanket inherits the default and the method is added with its first sliver producer. `PaintClip` is a NEW public `#[non_exhaustive]` enum — `Rect { rect, behavior }`, `RRect { rrect, behavior }`, `Path { path: Box<Path>, behavior }` — converted crate-internally into `FragmentScope`, which stays `pub(crate)`. It deliberately has no link variants (a hook-returned `Follower` would lose its ADR-0015 correlation and could never be patched) and no filter/mask variants yet (additive when their widgets land). Hook contract, stated on the method: the node's OWN effect, fixed nesting, pure in `(self, size)`, must not depend on `paint` having run (the patch arm never runs it), and any node needing a different nesting keeps its scope in `paint` and forgoes patchability for it.
2. **flui-rendering, walk.** `own_effect_layers` grows a scope arm (`SmallVec<[Layer; 2]>` → `[Layer; 3]`): emitted order `[alpha, scope, transform]`, outermost first. Today no production object returns two of the three (alpha: 4 objects; transform: 2; scope: clip only — disjoint sets), so the order is a contract for future producers, not a behaviour change; it is what `RenderFittedBox` documents as right for a clip-and-transform fit, and a node that needs its transform OUTSIDE its clip (a rotated clip window) keeps the clip in `paint` — expressible today, unpatchable, documented on the hook. The scope layer is built by the existing `scope_layer(scope, origin)` and recorded by the existing `record_effect_layer`; the per-position guard covers it, and its load-bearing case is the COUNT (`Some ↔ None`): with a fixed order a same-count kind swap is reproduced positionally either way, so no test pins a kind change (it cannot). **The guard move, two behaviour changes, both intended:** (a) the three hook reads move from before the return gates to inside the `catch_unwind` beside `paint_raw`, so a gated-out node's hooks no longer run at all (today a `needs_layout` node's transform hook runs on `Size::ZERO`); (b) a panic in ANY hook — alpha, transform, scope — becomes `RenderError::poisoned` on both arms instead of a raw unwind through `run_paint`. The patch arm's `own_effect_layers` call is wrapped the same way (`AssertUnwindSafe` — the closure captures a `&RenderNode` whose entry holds `dyn RenderObject`); `layer_patches_for`'s return type becomes `RenderResult<Option<LayerPatch>>` (one call site at ~:782-787, the `retained.and_then(..)` chain becomes `.map(..).transpose()?.flatten()`; no test callers), and the poison carries a distinct phase label `"layer-update"` (`error.rs` `poisoned(debug_name, phase)`) so a frame that never ran `paint_raw` is diagnosable. A refuse-then-repaint on panic is rejected: it would re-run the same closure and panic twice per frame.
3. **flui-objects, producers.** `RenderClip`: `paint_scope` returns `resolve_clip(size)` as the matching `PaintClip` variant with `self.clip_behavior` (returning the owned shape drops today's `self.clone()` at `clip.rs` ~:485); `paint` becomes `ctx.paint_child()`. The five property setters report `COMPOSITED_LAYER_UPDATE` (`| SEMANTICS` where they report it today). No `RenderClip` setter is structural (constant one-layer chain — a childless clip is not a slotless trap either: `paint_child` is a no-op and the hook has no `has_child` gate). Note for the record: `set_clip_behavior` stays without `SEMANTICS` as today, and the a11y clip gates on `Clip::None` outside `resolve_clip` (`clip.rs` ~:814) — a pre-existing gap, not introduced here, so the entry must not claim `resolve_clip` is the single source for `clip_behavior`. **`RenderFlow`**: its gated clip moves from `paint` to `paint_scope` (returns `None` at `Clip::None`) with NO setter flip — `set_clip_behavior` stays `PAINT | SEMANTICS` because the transition is structural. This gives AC5 a production `Some ↔ None` on a catalog type and exercises the walk's scope arm on every Flow frame; Flow's per-child transforms stay in `paint` (that is the deferred B2 case, not its clip).
4. **Accounting.** `flui-rendering/ARCHITECTURE.md`: amend trade-off 1 of the composited-layer entry to state the RULE ("a scope with a layout-derived rect gated on overflow / `Clip::None` has no patchable property; a scope whose shape is a node property is served through `paint_scope`") plus the `rg` command that enumerates the producers — never a list a human must maintain; a new entry "`RenderClip` serves a shape change by updating its layer" with the upstream contract (`_RenderCustomClip.clipper` → `_markNeedsClip` + paint; `clipBehavior` → `markNeedsPaint`; none is a repaint boundary; re-derive by reading `_RenderCustomClip`'s setters in `proxy_box.dart`, not by grepping a mark), the measured numbers on both shapes, the oracles, and the Deferred table with triggers.
5. **Housekeeping, separate PR (first):** delete `paint_layer_blend` from `RenderBox`, `RenderSliver`, `RenderObject`, `RenderNode`, `own_effect_layers` (signature + both callers), and `layer_patches_for` (zero overriders — `rg "fn paint_layer_blend" crates/flui-objects/src` is empty — and a documented foot-gun: a blend without an alpha is dropped silently, `paint.rs` ~:646-651). Also in that PR: the prose naming it at `paint.rs` ~:646-651 / ~:987-992 and `traits/render_object.rs` ~:487-495; the `ARCHITECTURE.md` RotatedBox entry sentence that names the hook (~:376-377); a decision on `OpacityLayer::with_blend` (`flui-layer/src/layer/opacity.rs` ~:94), which loses its only rendering-side caller — keep it (the layer API is not this deletion's subject) and say so; a CHANGELOG line for a public trait-method removal. `runtime-contract.toml` does not list it. Note, not ruling: if an advanced-blend producer ever arrives, the shape to consider is a `PaintOpacity { alpha, blend }` descriptor on `paint_alpha` — decided then, with a consumer. `test_paint_effects_none` (`proxy/repaint_boundary.rs`) asserts alpha and transform on a type that overrides neither — deleted on #996's tautology argument, not on this deletion.

**(a) Invariants and how they are encoded**
- *Captured-origin validity:* unchanged mechanism and unchanged pin; scope layers are rebuilt at `slots.origin` through the same `scope_layer` the walk uses. The clip variant of the same-frame test is added (grow a preceding sibling in the tick frame).
- *Structure:* the existing per-position guard; its load-bearing case is the count (`Some ↔ None`). `RenderClip` has no such transition (constant chain); `RenderFlow` does (`Clip::None`), and its setter reports `PAINT` while the guard refuses by construction (the bit is the optimisation, the refusal is the guarantee); `RenderBackdropFilter::enabled` follows the same rule when its widget lands.
- *Order:* one fixed order `[alpha, scope, transform]` in one constructor with two callers — no ordering policy anywhere else.
- *Single source of truth:* `resolve_clip(size)` feeds paint, semantics, hit-test, and now the hook; `paint` no longer holds a second copy.
- *Panic safety:* one guard shape on both arms; `poisoned`, not refuse.

**(b) Failure modes / abuse**
- Stale origin → same-frame layout marks paint → the queued `LayerUpdate` is upgraded (existing rule, existing pin + clip variant).
- Clipper panics → `poisoned` frame on whichever arm ran it (one panic, one error); lane inactive → `resolve_path_clip_target` degrades exactly as it does in paint today.
- A producer that both draws and scopes (physical model) must NOT implement `paint_scope` — its runs stay in `paint` and its setters stay `PAINT`; documented on the hook. (A′ cannot express "scope + own runs" and does not try; that is B2/C-lite territory, Deferred.)
- A producer whose fragment order needs the clip INSIDE its transform cannot use the hook (must keep the scope in `paint`); `RenderFittedBox` is the documented example of the opposite need and is unchanged here.
- Layer-update mark on a slotless node stays inert-and-correct (existing refusal).

**(c) Forward view (three extensions)**
- `BackdropFilter` / `ShaderMask` widgets land → their render objects implement `paint_scope`, `filter`/`shader`/`blend_mode` setters flip to `COMPOSITED_LAYER_UPDATE`, `enabled` stays `PAINT` — upstream's `_ImageFilterRenderObject` split ported as-is; `ImageFiltered` lands as a `FragmentScope::ImageFilter` variant + the same hook. Responsibility stays: render object decides property-vs-structure, walk enforces, capture addresses.
- `Material` implicit elevation/shape animation lands → needs C-lite (a drawing scope-owner's runs sealed into their own picture so a re-record can replace the `Arc<DisplayList>`); B2's re-record helper becomes the second rebuild mode then. A′ does not preclude it: the slot record gains a mode.
- `Flow` with an animated delegate → B2 (re-record the node's fragment, skeleton with an explicit hook prefix) — the design pass and the critic's findings are recorded so it is not re-derived.

### Alternatives considered

- **B2 — stamp scope layers at capture, rebuild by re-recording the node's fragment** (`paint_raw` into a scratch `FragmentRecorder`, typed `FragmentSkeleton` guard). Covers variable-fragment producers (Flow, FittedBox) A′ cannot, with zero trait surface. Rejected for this slice after adversarial review: for `RenderClip` it buys nothing over A′ (the source of truth is `resolve_clip`, not `paint`), and it costs a scratch execution per patch (with the lane/guard/phase asymmetries the critic enumerated), a `catch_unwind` extraction, and a skeleton type that must carry an explicit hook/scope split because hook layers are not in the fragment and `Layer::Transform` is emitted by both routes. Kept as the named next step for Flow/FittedBox.
- **B1 — stamp + query hook.** A′ with a duplicate descriptor; rejected.
- **A (three hooks: clip / backdrop / shader).** More surface for the same coverage; one hook returning one `#[non_exhaustive]` descriptor enum is the same thing without the family. (Returning `FragmentScope` itself was considered and rejected: it is `pub(crate)` by record and carries link variants the hook path cannot serve.)
- **C-full (Masonry model: per-node retained scenes re-stitched every frame).** Forfeits the inline O(1) graft the measured win rests on (163× vs 1.4×). Rejected on measurement.
- **D (record + trigger, build nothing).** Right for physical model, backdrop, shader, Flow; wrong for `RenderClip`: `ClipPath::new(closure)` mints a fresh `ClipSourceToken` on every rebuild (`flui-widgets/src/clip/clip_path.rs` ~:57), so a `ClipPath` inside any app `AnimatedBuilder` is a per-frame subtree repaint today — the default way to write a reveal, and a wired beneficiary. It stays `| SEMANTICS` per tick; the record must not claim "flat" for semantics.

## Public surface & semver impact

Active-dev workspace (0.2.0). Additive: one default method `paint_scope` on `RenderBox` and `RenderObject` (+ `RenderNode` box dispatch; no sliver mirror) and one new public `#[non_exhaustive]` enum `PaintClip` in flui-rendering. Behavioural: five `RenderClip` setters change their reported `RenderUpdateImpact`; `RenderFlow` moves its clip to the hook with no impact change; `paint_layer_blend` is removed from four traits (zero overriders; `runtime-contract.toml` does not list it; CHANGELOG line). No widget API changes. `api-design-lead` signs the hook, the enum, and the impact-bit flips.

## Pre-code maintainer verdict

**ACCEPTABLE (as reshaped after harsh-critic).** Owning crate: flui-rendering owns capture/graft/slots/guard and the hook; flui-objects owns impact decisions; flui-layer untouched (layers stay values; the layer setters are irrelevant to the patch path, which rebuilds values); widgets untouched. Sibling reuse: `own_effect_layers`, `scope_layer`, `record_effect_layer`, the discriminant guard, `FragmentScope`, `resolve_clip`, the `catch_unwind` guard, `build_effect_tree` / `bench_effect_change`, the `retained_boundary_layers.rs` fixtures — all get a second caller; the only new item is the hook. What a strict maintainer rejects: a second slot map; a per-effect hook family; flipping a setter with no widget caller; a refuse-on-panic path; quoting the inline number alone; a paint-count oracle placed on the clip node instead of drawing leaves; inferring patchability from the emitted layer tree.

## Acceptance criteria

Each traces to intent's "flat paint count + same layer tree as a repaint, or a recorded reason".

- **AC1 (setter algebra, unit, `proxy/clip.rs`):** each of the five `RenderClip` setters returns `NONE` on an unchanged value and `COMPOSITED_LAYER_UPDATE` (with `SEMANTICS` where it reports it today) on a changed one; red today (they return `PAINT`).
- **AC2 (update without repaint, `tests/retained_boundary_layers.rs`):** root → boundary → `RenderPadding` (non-zero) → `RenderClip<RRect>` → drawing leaf (emits draw commands; not a count-only counter); after `set_border_radius` through `apply_render_update_impact`: the LEAF's paint count is flat, the emitted `ClipRRectLayer` equals a fresh owner's at the new radius and differs from the old one. Mutation: setter reverted to `PAINT` → paint count increments.
- **AC3 (write-back, three frames):** as AC2, then dirty a SIBLING boundary's leaf; the outer graft replays the stored capture and still shows the new radius.
- **AC4 (captured origin):** a preceding sibling grows in the same frame as the radius change; the frame's clip rect equals a fresh repaint's (translated by the new origin), i.e. the `LayerUpdate` was upgraded to a `Repaint`.
- **AC5 (structure refusal, production-backed):** `RenderFlow` under a retained boundary, `set_clip_behavior` `HardEdge → None` applied, then a DIRECT `mark_needs_composited_layer_update` on it: the walk refuses, repaints, and clears the node's flag — the oracle reads `needs_composited_layer_update()` and fingerprints layer KINDS (the `ClipRectLayer` is gone), since content stays visible either way and a picture/pixel oracle is blind. No kind-change case: with a fixed order a same-count kind swap is unpinnable (positional patching reproduces the repaint tree), and no production `RenderClip<S>` changes `S` at runtime.
- **AC6 (panic on either arm, all three hooks):** a double whose `paint_scope` / `paint_alpha` / `paint_transform` panics under a layer-update mark → `run_paint` returns `Err(poisoned)` with phase `"layer-update"` exactly once for the frame, no second panic from a fallback; the same double under a repaint → `Err(poisoned)` with phase `"paint"`. And a gated-out node (`needs_layout` set) whose hook would panic does NOT run it.
- **AC7 (widget wiring):** rebuilding `ClipRRect` with a new radius yields the new `ClipRRectLayer` (pins `update_render_object` forwarding; cannot see the arm, says so).
- **AC8 (pixels):** workspace-root `tests/composited_layer_update_readback.rs` (`[[test]] required-features = ["gpu-readback-tests"]`, run only by CI's `gpu-test` job; locally `cargo nextest run -p flui --features gpu-readback-tests --no-default-features --test composited_layer_update_readback --locked --test-threads 1`): patched vs forced-repaint frames identical for a radius change, sampling the CORNER (a clip layer isolates its content — sample where the two radii differ); old vs new radius differ.
- **AC9 (measurement):** `paint/clip_rrect_radius_change` AND `paint/clip_path_token_change` on both shapes, both arms dirtying the same node. The path bench must run `run_paint` inside an entered `InteractionLane` with a registered clipper and assert the clipper's call counter is non-zero per iteration — without a lane, `resolve_path_clip_target` returns `Err(InactiveRealm)` → `default_for_size`, zero closure invocations, and the bench measures nothing. The record quotes N=1 and N=1000 on both shapes. Expectation stated correctly: the hook runs once on BOTH arms (walk and patch), so a closure's cost cancels in the ratio — it compresses toward 1× and cannot cross it through the hook; no setter is held at `PAINT` pending measurement.
- **AC10 (accounting):** ARCHITECTURE.md entry + trade-off 1 amended + Deferred table (physical model / backdrop / shader / Flow / FittedBox / ImageFiltered) each with its trigger; `paint_layer_blend` gone with its note.
- **AC11 (housekeeping PR):** `paint_layer_blend` removed; `just ci` green; `test_paint_effects_none` deleted with its reason.

## Risks & open questions

- The hook reads user code (path clipper, later shader) on the patch arm — same lane, same phase guards as the walk (critic traced: `run_paint` runs inside `UiRealm::enter` → lane; `enqueue_paint` side-queues marks under `debug_doing_paint`); the guard move is the load-bearing change and is pinned by AC6.
- `SEMANTICS` per tick stays for shape changes; the semantics pass cost is unchanged from today's `PAINT | SEMANTICS` (same `mark_needs_semantics` call).
- The layered N=1 ratio compresses toward 1× (the hook's cost is paid on both arms); the record quotes it as measured rather than only the inline number.
- Seen in passing, not this spec: `crates/flui-widgets/src/scroll/viewport.rs` ~:193/:384 discard `set_clip_behavior`'s impact with `let _ =` — file as its own item.
- Open: whether `set_clip_behavior` should stay `PAINT` for parity with the engine's `Clip::None` skip — no: the layer is still emitted at `None` (engine skips the push), so the chain is constant and the discriminant guard is satisfied; verified by AC5's kind-change case being the ONLY structural transition.
