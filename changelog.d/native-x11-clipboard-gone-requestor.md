### Fixed

- The X11 clipboard no longer answers, or refuses, the window that takes a gone client's window id in place of the request that client left waiting for the primary selection's text: the server hands a gone client's ids to the next one, and the answer used to land on the new window. A request that waits, or text that goes `INCR`, now hears its requestor's window and is dropped as it goes, and the answers decided later are written after a round trip to the server and the events it read, including those decided as the clipboard stops. A requestor the server will not let the clipboard hear for a reason other than being gone is refused rather than left waiting. X itself cannot tell a window that goes, and whose id a new window takes, in the moment between the clipboard's last exchange with the server and its write.
