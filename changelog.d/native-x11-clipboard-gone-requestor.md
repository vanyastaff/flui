### Fixed

- The X11 clipboard no longer answers, or refuses, the window that takes a gone client's window id in place of the request that client left waiting for the primary selection's text: the server hands a gone client's ids to the next one, and the answer used to land on the new window. A request that waits, or text that goes `INCR`, now hears its requestor's window and is dropped as it goes, and an answer decided later is written once a mark sent behind it comes back, every event before the mark handled. A requestor the server will not let the clipboard hear for a reason other than being gone is refused rather than left waiting. X itself cannot tell a window that goes, and whose id a new window takes, in the moment between the clipboard's last exchange with the server and its write.
- As the X11 clipboard ends (dropped, its connection failing, or after a panic on its thread), the requests still waiting on the application are refused, no `INCR` transfer starts, and the answers owed are written; it waits for the server only a bounded time, so a server another client holds or a dead link no longer holds up the application's exit.
- A client flooding the X11 clipboard with requests no longer holds up the answers it decided: each step handles a bounded number of events.
