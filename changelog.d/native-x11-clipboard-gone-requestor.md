### Fixed

- The X11 clipboard no longer answers, or refuses, the window that takes a gone client's window id in place of the request that client left waiting for the primary selection's text: the server hands a gone client's ids to the next one, and the answer used to land on the new window. A request that waits, or text that goes `INCR`, now hears its requestor's window and is dropped as it goes, and an answer decided later is written once a mark sent behind it comes back, every event before the mark handled. A requestor the server will not let the clipboard hear for a reason other than being gone, or does not answer about in time, is refused rather than left waiting, and so is a request into the clipboard's own window. X itself cannot tell a window that goes, and whose id a new window takes, in the moment between the clipboard's last exchange with the server and its write.
- The X11 clipboard waits a bounded time for every reply from the server, so a server another client holds, or a dead link, no longer stalls it or holds up the application's exit; as it ends (dropped, its connection failing, or after a panic on its thread) the requests still waiting on the application are refused, no `INCR` transfer starts, no write takes a selection, and the answers owed are written, those it had to drop reported.
- A client flooding the X11 clipboard with requests no longer holds up the answers it decided: each step handles a bounded number of events. A diagnostic subscriber that panics no longer costs a requestor its answer or refusal.
